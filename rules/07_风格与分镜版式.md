# 07 · 风格与分镜版式（handraw-style 接入规则）

这篇文档说明**画风从哪来、版式怎么选、提示词怎么写、工作流怎么配**。
相关代码：`comicgen/stylelib.py`、`comicgen/pagelayout.py`；
机器可读数据：`rules/data/storyboard_layouts.json`、
`handraw-style/skills/handdraw-style-prompter/references/*.json`（只读）。

---

## 一、风格来源与选择（S1–S7）

### S1 风格库是"资产库"，不是"提示词模板"

| 资产 | 数量 | 文件 | 程序怎么用 |
| --- | --- | --- | --- |
| 视觉风格 | 365（`FA-001 … FI-034`） | `references/styles.json` | 取 `traits` / 参考图；`generation_name`/`reference` 只留界面，不写进提示词 |
| 主题色 | 36（`C-01–C-36`） | `references/colors.json` | 主色 + 点缀色两色搭配 |
| 影调 | 40（handraw `T-01–T-16` + 本地扩展 `T-17–T-40`） | `references/tones.json` + `rules/data/tones_extended.json` | 按故事气质自动选一个阶调，写进「漫画分级特征」 |
| 排版图型 | 167，其中漫画分镜 71 | `references/layouts.json` + `layouts/SB-*.md` | 版式目录、缩略图、版式说明 |

**只读**：程序不会修改 `handraw-style/` 下任何文件；风格参考图按需转成
PNG 缓存到 `data/cache/style_refs/`。

### S2 旧编号自动映射

用户可能记的是旧编号 `001–365`。`stylelib.normalize_style_id()` 会通过
`style_alias_map.json` 的 `legacy_to_new` 映射到 `FA-001` 这类新编号；
也接受 `FA1`、`fa-001`、风格名、参考作者名。

### S3 自动推荐 = 本地收敛 + 模型决策

1. `stylelib.shortlist_style_ids()` 用故事文本（标题/梗概/情节线/关键点/角色/场景）
   给 365 种风格打分，取前 20~30 个；
2. `prompts.style_recommend_prompt()` 把候选清单 + 36 种主题色交给文本模型，
   让它结合题材、时代、情绪、受众做最终选择；
3. 模型的 `style_id` 必须落在候选里（防止编造编号），颜色解析失败就用本地结果；
4. 模型不可用 / 演示模式：直接用本地打分第一名，流程不中断。

**禁止**在代码里写"悬疑→某个固定编号"这种映射：风格是审美判断，
候选收敛只是缩小搜索空间，最终选择要结合具体故事。

### S4 手动锁定优先

- 手动选过风格 → `style_auto=False`，重新分析 / 一键全流程不覆盖；
- 点「✨ 自动推荐」→ 强制重新推荐，并把 `style_auto` 设回 `True`；
- 点「用回内置画风」→ 清空 `style_id`，回落到 `config.STYLE_PRESETS`。

### S5 提示词块（唯一画风来源）

`stylelib.style_prompt_block()` 输出：

```
漫画分级特征：{风格家族媒介}；{traits 里真实出现的漫画特征词}；{阶调名}（{阶调说明}）。
视觉语言：{过滤后的正面 traits}。
主题色：{主色（英文名），点缀色（英文名）}。
第1张参考图只用于匹配色彩倾向与整体色调，不取其中的人物、场景、构图、文字或故事。
```

**为什么是"漫画分级特征"而不是风格名**：风格家族媒介（电影级写实摄影 / 二维赛璐璐动画 /
日式漫画…）来自 `styles.json` 的 `group`，特征词只在 traits 里真实出现时才取（线稿、网点、
平涂、赛璐璐、胶片噪点、低饱和、暗调…），阶调来自 `tones.json`。这三层都是 handraw-style
的原始资产，组合后既保留风格辨识度，又不会被 Z-Image 当成标题文字。

**为什么不写风格名 / 作者名**：Z-Image-Turbo 会把
`…Cinema`、`…Illustration` 这类标题式名字当成画面标题文字画上去
（实测 FI-030 会在画面底部排出片名）。名字只留在界面给人看，给模型的是可执行的
视觉特征。需要旧格式（给 GPT-Image/Midjourney 之类）时把
`HANDRAW_PROMPT_INCLUDE_NAME = True`（作者名另开 `HANDRAW_PROMPT_INCLUDE_AUTHOR`）即可。

**阶调**：`stylelib.tone_for()` 按"故事文本 + 该风格 traits"做确定性打分，
雨夜/压抑 → `T-15 暗沉调`，复古/胶片噪点 → `T-14 胶片调`，高对比/动作 → `T-06 高反差`。
`HANDRAW_TONE_DEFAULT` 可锁死；`HANDRAW_PROMPT_TRIGGER=False` 可整块关闭。

规则：

- **只取正面特征**：按 `；/。/换行` 切分，丢掉含「避免 / 不要 / 不准 / 禁止 / 严禁 /
  不得 / 不能」的分句；
- **去掉编号**：`#018`、`SC-021`、`C-01` 一律剔除，避免模型把编号当文字画进画面；
- **去掉《作品名》与 markdown 符号**：`**`、`` ` ``、`__`；
- **负向词不写进正向**：正向只保留正面特征；"不要文字/多格/多余人物/透明衣料"等
  走独立的 `CLIPTextEncode → KSampler.negative`（默认 cfg=1.4 生效，见 S9）；
- **风格块不参与 `_sanitize_prompt`**：提示词里的"写实/3D/照片"是风格本体，
  被替换成"插画/2D手绘"会直接毁掉风格（例如 3D 渲染风格）。实现上
  `prompts.shot_image_prompt()` 用 `raw_keys` 跳过风格块的清洗。

### S6 参考图策略

- **默认 `style_color` 工作流**：只接 1 张参考图（画风缩略图），在生成后用
  `ColorTransfer`（`reinhard_lab`，强度 `COMFY_COLOR_TRANSFER_STRENGTH`，默认 0.55）
  把参考图的色彩倾向迁到成图上。**只迁色，不迁内容**，不会把参考图的人物/构图抄进来。
- 参考图会先统一成 `COMFY_REFERENCE_SIZE²`（默认 768²）的 PNG：多张参考图尺寸不一致
  会让 Omni 条件报 `KSampler shape invalid`，留边填充比拉伸更安全。
- 工作流只接 N 路图像输入时，程序只送 N 张（`reference_slot_count`），
  提示词里的"第 N 张参考图"也同步截断。
- **实验性 `style_ref`（Z-Image Omni）**：3 路（1 画风 + 2 角色）。用基础 Turbo
  权重时它会把参考图内容/构图一起抄过去（实测姿态总图的三个小人会排进画面），
  只在装了 Z-Image Omni 权重时才值得用。`auto` 预设**不会**选它。
- 色彩迁移工作流会把气泡一起染色，所以此时**气泡全部交给程序画**
  （`model_bubbles=False`），避免空白气泡被染色后检测不到。

### S7 一致性

角色主视图、姿态总图、每一格、每一页共用**同一个风格块**；
风格块在提示词里只出现一次（`_unique_parts`），不重复放大。

### S8 操作步骤（触发词 / 阶调）

1. 阶段②分析完成，点「✨ 自动推荐」或「浏览全部风格」选一个编号；
2. 风格卡会显示当前 `触发词 · 媒介 / 漫画特征 / 阶调`；
3. 想换阶调：在「阶调」下拉里选 `T-01…T-40`（不选=按故事气质自动）；
   想改触发词：直接编辑输入框，点「保存阶调/触发词」；
4. 正常出图即可，系统会自动把这段放在每一格提示词最前面，不需要手工拼；
5. 想核对实际提示词：看 `01_分析/绘制风格.md` 与
   `04_提示词/逐格提示词.jsonl`；
6. 想整块关闭：`HANDRAW_PROMPT_TRIGGER=False`；想锁死阶调：
   `HANDRAW_TONE_DEFAULT="T-15"`；想试英文风格名：
   `HANDRAW_PROMPT_INCLUDE_NAME=True`（会被画成标题文字的风险自负）。
身份卡仍由 `rules/01` 管，风格块只管"怎么画"，不管"画谁"。

## 二、分镜版式（L1–L9）

### L1 三种形态

| `RENDER_MODE` | 行为 | 页面对象 |
| --- | --- | --- |
| `webtoon` | 一格一张图，竖屏无缝长条 | `project.pages = []` |
| `page` | 2~6 格拼一页，版式从 SB-* 选 | `PagePlan[]` |
| `hybrid` | 按内容分流（默认） | `PagePlan[]`，可含 WB-* 单格页 |

### L2 内容信号优先于"模板轮播"

| 字段 | 来源 | 用途 |
| --- | --- | --- |
| `beat` | 分镜拆解模型 + `pagelayout.infer_beat()` 兜底 | 版式匹配主信号 |
| `pacing` | 模型 + `infer_pacing()` | 页面节奏、避免连续同节奏 |
| `panel_emphasis` | 模型 + `infer_emphasis()` | main/splash 必须落在大格 |
| `caption` | 模型（仅说明型画面） | 上图下文版式的字幕栏 |

`infer_beat()` 的判定顺序（确定性兜底）：
`hook → 场景切换 → 建立（远景/全景 + 新场景）→ 物件/特写（揭示/细节）→
无台词（悬疑/情绪）→ 对白 → 动作 → 幽默 → 悬疑 → 情绪`。
有模型给的 `beat` 时不覆盖。

### L3 版式打分（`_layout_score`）

```
基础分 = Σ fit[k] × 信号[k] / Σ 信号[k]        # 7 维加权
+ beat/关键词命中（每个 +0.035，上限 1.35）
- 一页场景数 > PAGE_MAX_SCENES_PER_PAGE（默认 2）
- 重点格不在最大格（按格位差 × 0.10）
- 单格台词 > 2 且版式 dialogue fit < 0.6
- 物件格塞进对白版式
- 每页固定开销 0.45（避免全篇被拆成单格页）
+ 多格信息密度 min(p-1,3) × 0.40
+ 单格页只有在 need_splash 时才 +0.95
+ 同场景对白段在 hybrid 下偏向原生条漫 +0.10
- 连续同版式 PAGE_LAYOUT_REPEAT_PENALTY（默认 0.22）
+ 极小的确定性抖动（避免同分永远选字母序在前的版式）
```

### L4 全局覆盖：动态规划

`plan_local()` 在"每页格数 × 版式"上做 DP：

```
dp[i] = max over layout(l): score(l, shots[i:i+p]) + dp[i+p]
dp[n] = 0
```

保证每格恰好被编进一页、不重不漏；最后再做一次"同版式连续"替换，
换一个同格数、分差不多的版式，避免整话一个模子。

### L5 文本模型方案 + 严格校验

`plan_pages()` 优先让文本模型输出 `pages[]`，`plan_from_llm()` 校验：

1. `layout_id` 必须存在；
2. 每页 `shots` 数量必须等于版式 `panels`；
3. 序号必须从 1 开始、连续、不重、不漏、覆盖全部；
4. 任何一条不满足 → **整体放弃**，退回本地 DP（不拼接半份方案）。

### L6 一个格 = 一张独立画面

分格页不是"让模型一次画 4 格"，而是：

```
每格单独出图（含气泡计划/自检/自动返修）
        ↓
按版式几何等比裁切贴进页面画布
        ↓
墨线边框 + 纸色 gutter + 字幕栏 + 页码
```

原因：一次画多格时，模型经常把格子画歪、把气泡画到格子外，且单格返修会牵连整页。
代价是跨格连续背景不保证，靠"同一风格块 + 同一身份卡 + 场景描述"维持。

### L7 几何与格数

- 每个版式登记 `geometry`，几何模板在 `storyboard_layouts.json` 的
  `geometries` 里：`cells` 是归一化 `[x,y,w,h]` 或 `{"poly": [[x,y],…]}`，
  `captions` 是字幕栏矩形，`ratio` 是页宽/页高；
- 格子出图比例会夹在 `0.55~1.95`（模型画不了 1:5 的极窄条），
  合成时再等比裁切填满；
- 版式格数与实际分镜数不一致时：规划阶段不会选中；合成阶段直接报
  "分镜与版式格数不一致，请重新规划版式"，不会错位贴图。

### L8 页面失效与重排

`pages_valid()` 检查 `pages` 覆盖的分镜 id 序列是否与 `project.shots` 完全一致。
以下场景会失效并自动重排：

- 阶段④保存分镜、增删/移动/合并/拆分；
- 切换 `RENDER_MODE`；
- 导出前发现分镜已改（`compose_all_pages` 内自动重排）。

**绝不把旧页拼进新成品**：`strip_tiles()` 发现页面失效时退回单格图。

### L9 原生条漫版式

`WB-001` 单格 / `WB-002` 双格 / `WB-003` 三格，几何是**满幅、无页边、窄缝**，
用于保留"手机上一路下滑"的原始条漫手感；`hybrid` 下情绪/冲击/转场格
会优先考虑 WB-001，对白密集的同场景段优先 WB-002/003。

## 三、ComfyUI 工作流匹配（W1–W4）

### W1 三份工作流

| 预设 | 工作流 | 参考图 | 适用 |
| --- | --- | --- | --- |
| `base` | `image_z_image_turbo_int8` | 无 | 不选风格 / 老工程 / 显存紧张 |
| `style_color` | `..._style_color` | 1 画风（**只做 ColorTransfer 色彩迁移**） | 选了 handraw 风格的默认链路 |
| `style_ref` | `..._style_ref` | 1 画风 + 2 角色（`TextEncodeZImageOmni`） | 实验性，需 Z-Image Omni 权重 |
| `style_img2img` | `..._style_img2img` | 1 画风（VAEEncode，denoise 0.62） | 兜底，会带参考图构图 |

`COMFY_WORKFLOW_PRESET="auto"`：本次有画风参考图 → style_color，否则 base。

### W2 参考图注入

1. `ImageClient._prepare_upload_image()` 先处理参考图：style_color 只等比缩到
   `COMFY_REFERENCE_SIZE`（默认 768，**不填灰边**，否则污染 ColorTransfer 色彩统计）；
   Omni 才填成 768²（多图同尺寸），再上传；
2. `_upload_reference()` 上传到 ComfyUI `/upload/image`（`input/manhua_refs/`，同名覆盖）；
3. `WorkflowTemplate.build(reference_names=[...])` 按 `_meta.title` 的
   「参考图N」给 LoadImage 排序并写 `image`；
4. 用不到的槽位从节点图里摘掉，避免空 LoadImage 加载默认文件报错；
5. `ColorTransfer` 的强度由 `COMFY_COLOR_TRANSFER_STRENGTH` 注入；
6. 图生图工作流的画幅写在 `ImageScale` 上，`_apply_latent_size()` 会往上游找到它。

### W3 角色 LoRA（已停用）

LoRA 已归档到 `archive/lora/`，当前 `IMAGE_LORA_ENABLED=False`，不再接入工作流。

### W4 失败降级

- style_color 工作流不存在 / 节点不支持 → 自动回退 base（提示词里的参考图说明同时去掉）；
- 参考图上传失败 → 明确报错（不会静默丢参考图）；
- 显存不足 → 按 `_webtoon_degrade_plan` / `OOM_RETRY_PLAN` 降画幅重试。

### S9 负面条件（与风格配套）

- 工作流必须有一个 `CLIPTextEncode`（标题「负面提示词」）接到 `KSampler.negative`；
- 默认 `COMFY_CFG=1.4`；Z-Image-Turbo 官方推荐 1，cfg=1 时负向词被忽略；
- 负向词按镜头/角色/姿态总图/背面/风格分开，**风格层**要避免打架：
  - FI 写实电影：压"低幼卡通/简笔画/平涂网点"，**不要**压"照片/摄影"；
  - FA/FB/FD/FE/FG：压"写实照片/真人/3D/CG"；
  - FF 3D 材质：压"平面简笔/无材质"，**不要**压"3D"；
- 姿态总图负向词不能带"多格/分镜"，否则会把三角度压成一张；背面另加"双人/正面人物"。

### S10 角色图与分镜图的区别

| 项 | 角色主视图/姿态总图 | 分镜格 |
| --- | --- | --- |
| 负向词 | 多余人物/额外外套/透明衣物/眼镜（无眼镜时） | 多格/画框/文字/多余人/程序气泡 |
| 画幅 | 1024²（默认由正面单视图重排） / 512×832×3 | 按页面格子比例 |
| 构图 | 全身、中性背景、正/侧/背 | 镜头语言 + 场景 |
| 气泡 | 无 | 程序画（style_color） |
| seed | `character.seed` 共用 | `shot.seed` 可复现 |

姿态总图默认逐张生成（`CHARACTER_TRIPLE_SEPARATE`），并只保留一件外层服装
（`CHARACTER_SINGLE_OUTERWEAR`）；否则背面容易换成另一件大衣。

### S11 风格必须放在提示词最前面

- 第一段是 **`视觉语言（本图必须执行）：{traits}`**，把该风格的真实特征放在开头；
- 第二段才是 `画风执行`（线条/人体/材质的具体做法），再后面才是一般性
  `漫画分级特征`（家族媒介 + 漫画特征 + 阶调）；
- 不再用“快看式韩漫 / 彩色韩漫”作为所有风格的固定开头；
- 不同家族有不同执行词与负向：
  - FA：手工墨线、线宽不匀、头小颈长腿长、8~9 头身；负向压“干净矢量线/均匀线宽/正常头身比”；
  - FB/FE：纸纹、水彩、留白；负向压“硬边矢量/塑料 3D”；
  - FD：墨线+网点；负向压“照片/厚涂/3D”；
  - FI：电影摄影；负向压“卡通/平涂/简笔”；
  - FF：黏土/毛毡/纸雕；FG：赛璐璐+硬边阴影。

### S12 清空、重排与实时刷新

- 重新规划版式**不会**再自动拿旧分镜图合成：旧图属于上一版风格/版式，
  页面会先显示“待生成”，等新图出来再按新 `cells` 合成；
- 分镜画幅在分格页/混排页里**从当前 `page.cells` 计算**，不再沿用旧
  `shot.panel_size`；这样重排后出图的格子比例和页面版式一致；
- 每个阶段都有“清空图片”：
  - 角色：清空主视图/姿态总图/造型图，保留人设文本；
  - 分镜：清空成品/原图/气泡计划，保留分镜文本与版式；
  - 页面：只清页图；
  - 全部：清所有图，保留小说/人设/分镜/页版式。
- 风格卡新增“应用风格并清空旧图”：应用风格后一次性作废旧图，避免调试时
  一直看到上一版风格的缩略图；
- 批量/单格生成时，每完成一格前端就刷新当前页面的对应图片，不等全部结束。

### S13 换风格后角色要重新解读

- 人设生成提示里增加“画风优先”段：先按当前画风的五官/比例/服装材质重新解释角色，
  再写人设；不要沿用上一套光滑大眼模板；
- 换风格后建议点一次「生成人设」再生成参考图；已有文本不会被自动覆盖；
- 角色主视图/姿态总图/分镜统一使用当前 `style_prompt_block`，不混用旧风格。

### S14 内置画风 / 阶调 / 触发词

- **内置画风不再只有韩漫**：`STYLE_PRESETS` 扩到 47 个，按 8 个家族分组
  （电影与综合 3、日系漫画 10、国风与华语 7、欧美漫画 6、欧洲漫画 3、
  独立与实验 5、美术媒介 6、韩漫与条漫 7），每个都有独立 `STYLE_PROMPT_MAP` 正文；
  分析提示词不再默认推荐韩漫，改为按题材/时代/情绪映射（见 `STYLE_CHOICE_RULE`）；
- **阶调扩到 40**：handraw 原始 16 个不动，本地
  `rules/data/tones_extended.json` 追加 T-17–T-40；`tone_entries()` 合并读取，
  界面会自动多出 24 个选项；
- **触发词严格来自 traits**：`trigger_phrase()` 不再只写“家族 + 暗沉调”，
  而是 `家族 + 该风格 2~3 条 traits + 阶调`；365 条触发词必须互不重复
  （自检：`len(set(trigger_phrase(...))) == 365`）；
- 用户手改过的触发词存 `style_trigger_custom=True`，不会被自动覆盖；
  旧工程未手改的老格式触发词会自动升级。

## 四、扩展方式

### 加一个版式

1. 在 `handraw-style/.../layouts.json` + `layouts/SB-xxx.md` 增加版式（如果来自上游库）；
2. 在 `rules/data/storyboard_layouts.json` 的 `layouts` 里登记
   `geometry / panels / fit / beats`；
3. 需要新几何时在 `geometries` 里加 `cells`（矩形或多边形）与 `captions`；
4. 跑 `env\Scripts\python.exe -c "from comicgen import stylelib; print(stylelib.self_check())"`；
5. 用 `python -c "from comicgen import pagelayout; ..."` 或界面「重新规划版式」验证。

### 改风格提示词写法

只改 `comicgen/stylelib.py` 的 `style_prompt_block()` / `positive_traits()`；
不要把风格词写回 `config.STYLE_PROMPT_MAP`，那是旧兜底路径。

### 风格名的中英文显示

- 风格卡/风格库/下拉框统一显示：**中文名主显示，英文原名副显示**；
- 中文名缓存在 `data/cache/style_zh.json`，由根目录
  `translate_styles.py` 批量生成/刷新（`--force` 重译）；
- 某个风格没有缓存时，用「风格家族 + traits 第一条」自动生成中文名，
  不会退回纯英文；
- 参考作者同样显示中文译名 + 英文原名；找不到常用译名时用音译，
  不删英文原名。

### 换一份工作流

把新工作流 JSON 放进 `comfy_workflows/` 与 ComfyUI，然后改
`config.COMFY_WORKFLOW_STYLE_NAME`（默认风格链路）。只要节点图里有
`LoadImage` + 采样器 + 保存节点，程序会自动定位，不需要改代码。
