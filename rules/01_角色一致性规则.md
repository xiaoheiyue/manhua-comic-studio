# 角色一致性规则（Character Consistency Rules）

> 适用范围：本项目的「人设生成 → 角色预设（主视图/面部特写/单视图/三视/俯视）→ 分镜出图 → 导出」全链路。
> 目标：**同一个角色跨 90 格像同一个人；不同角色同框时一眼能分开。**
> 机器可读版本：[`data/identity_rules.json`](data/identity_rules.json)（程序运行时读取，改这里即可生效）。

---

## 0. 三个词先定义清楚

| 术语 | 含义 | 本项目落地字段 |
| --- | --- | --- |
| **身份锚（anchor）** | 一眼能认出"是他"的 1~3 个视觉特征：发色+发型轮廓、服装主色、标志配饰/疤痕 | `Character.identity_tag` + `keywords` |
| **身份卡（identity card）** | 一段 ≤90 字、跨格**逐字不变**的外貌描述，每张分镜原样复用它 | `Character.identity_card()` |
| **撞车（collision）** | 两个角色在"脸型 / 眼部 / 发型轮廓 / 服装主色"里 **≥3 项相同**，或「≥2 项相同 + 人设相似度 >0.62」，或记忆点重复 | `pipeline.character_collisions()` |

> 一致性 ≠ 每次都写一遍完整人设。**写得越长，模型越容易把 A 的特征混到 B 身上**
> ——2026 年的对照实验把这种现象叫 attribute leakage，提示词越细越明显
> （[ICML 2026, Can Your T2I Model Handle Long Prompts?](https://openreview.net/forum?id=AZ0VQouDmR)）。
> 正确做法是「短身份卡 + 稳定复用 + 位置绑定」，而不是「长篇小说式人设」。

## 1. 十条硬规则（H1–H10）

### H1　一个角色，一张身份卡，逐字复用

- 身份卡只写 **可视化、可复现** 的东西：发色/发型、脸型、眼型、服装主色与款式、1 个配饰、体型年龄。
- 身份卡一旦定稿，**所有分镜必须原样引用同一份字符串**（含标点），不允许每格换同义词
  （"及肩黑发" ↔ "齐肩黑色长发" 会让模型当成两种发型）。
- 长度：**≤90 个汉字**（默认 88）。超过会挤掉画面内容，见 `data/shot_prompt_rules.json`。

**反例（当前工程）**：
```
陆鸣：女、二十七岁上下、数据复原师…；二十七岁冷白皮女性、及肩黑发低马尾、斜分长刘海、
细长上挑杏眼…【基本形象】女性，二十七岁上下，身高约168cm，体型清瘦挺拔…【发型与发色】…
（共 260 字，且以"下配黑色直筒长裤与"截断）
```
**正例（身份卡）**：
```
陆鸣：27岁女，及肩黑发低马尾、斜分长刘海、细长上挑杏眼、炭黑短风衣+深灰高领、颈挂旧U盘
```

### H2　角色之间必须"剪影可区分"

剪影是观众最先读到的信息，先于颜色和细节（[角色设计：剪影与形状语言](https://morphic.com/zh/ai-glossary/character-design)）。
出图前对任意两个角色做"剪影三问"：

1. **发型轮廓**一样吗？（长直发 vs 低马尾 vs 短发 vs 卷发 vs 束发）
2. **服装主色/廓形**一样吗？（深灰长风衣 vs 米色短夹克 vs 黑西装）
3. **体型年龄**一样吗？（清瘦青年 vs 微胖老年 vs 高挑女性）

三问里有两问答案相同 → 必须改一个。**优先改发型轮廓和服装主色**，这两个对画面影响最大、最不容易被光影吃掉。

### H3　每个角色至少 1 个"独家记忆点"，且不得重复

记忆点 = 别人没有的配饰/疤痕/发型细节/惯用物件，例如：

- 叶哥：**左耳单只细银耳线**
- 陆鸣：**颈挂细银链旧U盘**
- 何建军：**左手虎口旧疤**
- 吴德胜：**细金属框方眼镜**

规则：
- 每个角色都要有一个可被指认的记忆点（`identity_tag`，或关键词里的配饰/疤痕/眼镜）；
- **`identity_tag` 必须是"一个短特征"**（≤18 字），不能写成自我描述句。
  模型常写成"颈挂磨白旧U盘的墨黑齐发女""左耳旧铜环的印刷店老板"，
  直接进身份卡会变成"及肩黑发、…女、窄长脸"。
  程序现在优先取 `hard_features.signature`，并砍掉"的…"身份后缀；
- 记忆点**全局不得重复**（含近似写法："右眉尾浅疤" vs "右眉尾一道浅淡旧疤"）——
  两个角色都戴"右眉尾浅疤"等于没有记忆点；
- 记忆点必须"画得出来"：颜色/形状可描述，不要写"气质冷"。

### H4　人设生成时就要"看着别人写"

`prompts.character_design_prompt` 必须把**已有角色清单及其身份锚**一起喂给模型，并要求：

- 新角色的发色、发型轮廓、服装主色、体型年龄，**至少 2 项与清单里任何人都不同**；
- 不得复用清单里已出现的记忆点；
- 输出 `hard_features`（face/hair/eyes/outfit/signature/palette/build）与 `identity_tag`，
  供程序做机器校验，而不是只给一段散文。

生成后立刻跑撞车检测（`pipeline.ensure_character_distinctness`）：
撞车 → 带着"撞了谁、撞了哪几项"重写一次 → 仍撞车 → 追加**唯一点缀**（见 H5），并记录 `design_patchs`。

### H5　修撞车只做"加法"，不改原文硬设定

小说已经写死的外貌（"她一头银发"）不能改。可加的是**不在原文里的点缀**：

- 发饰：细银发夹 / 黑色发带 / 木簪
- 眼镜：细金属框 / 无框方片 / 圆框
- 颈部/耳部：细银耳线 / 黑色choker / 红绳
- 服装配件：藏青围巾 / 旧皮质文件袋 / 反光条背心

每次只加 **1 件**，并写进 `keywords` 与 `【标志性特征】` 末尾。
**不要**为了区分去改脸型/年龄/性别——那会和原文冲突。

### H6　一格一人是默认值，双人同框是例外

默认 `style_color` 只有 1 张画风参考、角色图不进模型，也没有分区注意力，
**两个人的特征仍然会互相污染**（社区结论一致：多角色同框要靠 Regional Prompting /
Attention Couple 分区，只靠提示词必然串味，
见 [LitMemo：AI 漫畫角色每格都換臉](https://litmemo.com/zh-Hans/blog/manga-ai-character-consistency)）。
2026-10 增加的 `castguard` 用"一人一段 + 具体差异对照 + 左右分区 + 中间留空"
把纯提示词的双人可用率往上拉，但它仍是**降风险**，不是区域控制。

因此：

| 场景 | 允许人数 | 镜头要求 |
| --- | --- | --- |
| 对白 / 情绪 / 反应 | **1 人**（对手用画外音 + 反应格） | 近景、特写、中景；**不要用"过肩"**（前景肩背会被画成第二个人） |
| 对峙 / 建立镜头 / 大场面 | **2 人** | 远景、全景、中景；左右必须分开、中间留一臂空隙；也不用过肩 |
| 3~4 人 | **允许**（群像/对峙/建立镜头） | 远景、全景、中景；逐人写位置/动作/视线；最多 1 条台词 |
| 5 人及以上 | **0 人**（拆成多格） | 拆成群像 + 单人反应格 |

配套：
- 双人格**最多 1 条台词**，且必须写明说话人；超过 1 条就拆格；
- 双人格必须写清"左侧是谁、右侧是谁、谁在说话、另一个人闭嘴"；
- 单人格提示词用 **"画面里只有一位人物"**（正面排他），不要写"不要画第二个人"；
- 单人格的过肩机位在 `castguard` 里会自动降成斜侧。

### H6.5　每个角色必须有一处"破坏性"不对称特征

完美对称的脸最容易被模型平均化。人设阶段必须写一处不对称的小特征
（左眉尾小痣 / 右眼略小 / 发缝偏右 / 单侧耳饰 / 一侧眉峰更高），
存进 `hard_features.asymmetry`，并进入关键词与身份卡。

- 已有角色优先用**故事里本来就有的**疤/痣/耳饰；
- 不要为了区分去改脸型/年龄/性别；
- 双人同框时，`castguard.contrast_block` 会把两人的脸型/眼型/发型/外套轮廓
  写成一句具体对照，而不是笼统的"两人明显不同"。

### H7　图像提示词必须"先身份、后画面"

顺序固定为：**画风锚 → 人数 → 身份卡（含左右）→ 隔离声明（差异对照/空场景）→
镜头 → 动作/表情 → 画面内容 → 场景/时间 → 气泡 → 收尾**。
理由：文本编码器对靠前的实体绑定更强；把 700 字人设放在画面内容前面，等于用"角色百科"淹没"这一格在演什么"。

### H8　同一角色跨格保持"造型版本"稳定

- 一个角色可以有多个造型（`extra_looks`），但**同一场戏只能用同一套**；
- 换造型必须走"造型版本"而不是临时改提示词；
- 主视图/面部特写/单视图是造型的唯一定义源，**不要用某张分镜图反推人设**（那张图可能已经漂了）。

### H9　seed：角色图共用，分镜只用于复现

- **主视图/三视/面部/单视图共用 `character.seed`**（`CHARACTER_SAME_SEED=True`），
  用于降低同一角色在正面/侧面/背面之间的脸型漂移；
- 分镜仍默认随机 seed：构图、角度、光影一变，同一个 seed 也会抽出不同的脸，
  不能靠 seed 锁脸；
- 某张分镜满意了 → 记下 `shot.seed`，重绘时同 seed 微调提示词；
- 做 A/B 对比时固定 seed，排除随机性。

### H10　一致性要能验收：抽检 10 格

每个角色至少抽 10 格（含 1 个双人格、1 个特写、1 个夜景）做"三看"：

1. 看**发色+发型轮廓**是否一致；
2. 看**服装主色+记忆点**是否还在；
3. 看**同框的两个人**能否 1 秒内分清。

任一项失败 → 先查身份卡是否被截断/改写，再查是否混入了别人的关键词。

## 2. 身份卡的写法（可直接抄）

### 2.1 字段模板

```
{姓名}：{性别}{年龄}，{发型}{发色}、{脸型}、{眼型}、{服装主色}{款式}、{唯一记忆点}
```

示例：

```
叶哥：二十七八岁女，及背中长直发偏分、偏窄鹅蛋脸、细长上挑杏眼、深藏青修身长风衣+黑高领、左耳细银耳线
陆鸣：二十七岁女，及肩黑发低马尾、鹅蛋脸、细长上挑杏眼、炭黑短风衣+深灰高领、颈挂旧U盘
何建军：42岁男，黑短发鬓角微白、瘦长脸、单眼皮细长眼、深灰旧夹克+深蓝T恤、左手虎口旧疤
```

> 叶哥和陆鸣仍然共用"细长上挑杏眼"——按 H2 这算 1 项，允许；
> 但她们的发型轮廓（偏分长直 vs 低马尾）、服装主色（藏青长 vs 炭黑短）、记忆点（银耳线 vs U盘）三项全不同，**可以区分**。

### 2.2 写作禁忌

| 不要写 | 原因 | 改成 |
| --- | --- | --- |
| `气质冷峻、眼神有故事` | 不可视化 | `眼睑压低、薄唇紧抿` |
| `精致的五官` / `比例偏写实` | 会把画面拉向写实 | `二次元五官、插画概括` |
| `像某某明星` | 版权 + 模型乱发挥 | 拆成 3 个具体特征 |
| 超过 3 个颜色 | 主色被稀释 | 主色 1 + 辅助色 1 |
| 同一角色两种发型混写 | 模型会取平均 | 明确"日常造型/工作造型" |

### 2.3 关键词上限

`CHARACTER_KEYWORD_COUNT = 6`，但一条关键词应尽量是"特征组合"而不是单词：

- 好：`及肩黑发低马尾`、`炭黑短款风衣`、`颈挂细银链旧U盘`
- 差：`黑发`、`风衣`、`U盘`

## 3. 多人同框的写法（纯文生图版）

### 3.1 双人格提示词模板（2026-10 castguard 版）

```
画面里只有两位人物，就是叶哥和陆鸣；画面里出现的其他东西都是环境与道具。
画面左侧三分之一是叶哥：女，偏窄鹅蛋脸，及背中长直发偏分，细长上挑杏眼，
深藏青修身长风衣，左耳细银耳线；
画面右侧三分之一是陆鸣：女，鹅蛋脸，及肩黑发低马尾，细长上挑杏眼，
炭黑短风衣，颈挂旧U盘。
两张脸各自独立：叶哥是偏窄鹅蛋脸、长直发偏分；陆鸣是鹅蛋脸、及肩低马尾。
叶哥穿长款风衣，陆鸣穿短款风衣。
叶哥在画面左三分之一，陆鸣在画面右三分之一；两人之间留出一臂宽的空隙，
背景从空隙里透出来。
这一格里说话的是叶哥，只有叶哥张嘴；陆鸣闭着嘴，看向叶哥。
```

要点：
- **一人一段**：先写完叶哥的全部特征，再写陆鸣，绝不交叉；
- **具体差异**：不要写"两人明显不同"，要写脸型/眼型/发型/外套轮廓的实际差异；
- **左右分区 + 中间留空**：这是纯提示词下最有效的"物理隔离"；
- **只有说话人张嘴**——这句话能显著降低"听者也在说话"的错觉；
- 不要在双人格里放第三个角色的名字，哪怕只是提到。
- 身份卡超过 94 字时，用 `castguard.compact_card(brief=True)` 重写，
  **不要按字数从中间切卡**（会切出"眼睛（画面左侧…"这种病句）。

### 3.2 什么时候必须拆格

- 双人 + ≥2 条台词 → 拆成「说话人单人」+「听者反应单人」；
- 双人 + 近景/特写 → 拆成两个单人反应格（对手用画外音）；过肩算 2 人构图，
  需要对手入镜就保留 2 人，不要用"单人过肩"骗自己；
- 三人及以上 → 一律拆。

## 4. 与分镜层的接口（谁负责什么）

| 责任 | 模块 | 说明 |
| --- | --- | --- |
| 生成互不撞车的角色 | `prompts.character_design_prompt` + `pipeline.ensure_character_distinctness` | 文本层 |
| 保存身份卡 | `Character.keywords / identity_tag / hard_features` | 数据层 |
| 拼进每格提示词 | `pipeline.build_shot_prompt` → `prompts.shot_image_prompt` | 出图层 |
| 校验撞车/人数/归属 | `director.validate` | 质检层 |
| 出现漂移后修 | `FaceDetailer` / 单格重做（见第 6 节） | 后期层 |

## 5. 一致性的四个层级（选型表）

| 层级 | 手段 | 一致性 | 成本 | 本项目状态 |
| --- | --- | --- | --- | --- |
| L0 | 身份卡 + 人数控制 + 位置绑定 | 60~75% | 0 | **已启用** |
| L1 | 参考图注入（Qwen Edit / ReferenceLatent） | 80~90% | +10~40% 时间 | **Qwen 分镜已启用**；按景别/视角/人数路由；Z-Image style_color 仍只迁色 |
| L2 | 角色 LoRA（20~60 张多角度图训练） | 90~95% | 训练 30~60 分钟/角色 | 未启用 |
| L3 | 区域控制（Regional Prompting / Attention Couple）+ L1/L2 | 90%+（多人） | 节点复杂 | 未启用 |

参考：
- IP-Adapter / InstantID / PuLID / LoRA 的分工与取舍：
  [ComfyUI Consistent Characters Guide](https://www.media.io/image-tips/comfyui-consistent-characters.html)、
  [11 种 ComfyUI 一致性方案全解析](https://blog.csdn.net/weixin_43951955/article/details/160287011)
- 多角色分区：见上 LitMemo 一文"多角色同框时特征互相污染"一节
- 多角色身份组合的学术方案：[CharCom: Composable Identity Control for Multi-Character](https://dl.acm.org/doi/full/10.1145/3743093.3770985)

## 6. 升级路线（等模型启动后按顺序做）

### 6.1 方案 C-1：Qwen-Image-Edit-2511（历史备选，8GB 不首选）

> 当前 8GB 环境不训练 LoRA；LoRA 资料已归档 [archive/lora/README.md](../archive/lora/README.md)。
> Qwen-Image-Edit 20B 在 8GB 上只能 Q3，画质/速度都不划算，保留为 12GB+ 环境的备选。

- 2509 起支持**多图输入**（人+人、人+物、人+景）与原生 ControlNet；
  2511 进一步强化"多人一致性"和"单参考图换角度"
  （[Qwen-Image-Edit 2509/2511 更新说明](https://www.thundercompute.com/blog/qwen-image-edit-comfyui)）。
- 显存：FP8 约 20GB；GGUF Q4 约 12~13GB 可跑，8GB 只能 Q3（画质明显下降）
  （[本地部署与量化对照](https://localaimaster.com/blog/qwen-image-edit-local-guide)）。
- 接入方式：把工作流存成 ComfyUI 里的 `image_qwen_edit_2511_manhua`，
  让 `COMFY_WORKFLOW_NAME` 指向它；本项目已能自动识别 `LoadImage` 节点并送参考图
  （`comfyworkflow.supports_reference_images`），无需改代码。
- 用法建议：
  - 先用「主视图」单独 T2I 生成正面全身参考，再派生面部特写/单视图；
  - 每格按景别路由参考图（特写 face+main、中景 main、侧背 main+side/back），
    身份靠参考图 + 身份卡，不再靠 700 字人设；
  - 双人格每人一张 face，并在提示词里写清左右、年龄/身高关系；
  - 全景/远景默认 0 张；3 人 0 张；4 人拆 3+1/2+2。

### 6.2 方案 C-2：给 Z-Image 训练角色 LoRA（已归档，不启用）

- 数据集：同一角色 20~60 张，多角度、多表情、干净背景；
- 参数参考：学习率 1e-4~2e-4，1500~2500 step，唯一触发词；
- 推理：`Load LoRA` 节点 + 权重 0.7~0.9；
- 优点：不换底模，速度不变；缺点：每个角色都要训，改设定要重训。

### 6.3 方案 C-3：IP-Adapter / PuLID

- 需要与底模匹配的 IP-Adapter 权重（Z-Image 生态目前不如 SDXL/Flux 成熟）；
- 若换到 SDXL/Flux 底模，IP-Adapter FaceID 权重 0.7~0.9、PuLID 2~3GB 显存，
  锁脸但不锁姿势，适合"同一角色不同分镜"。

### 6.4 方案 D：区域控制（双人格专用）

- 节点：Regional Prompting / Attention Couple / Latent Couple；
- 做法：左半区套叶哥的身份卡（+参考图），右半区套陆鸣的，中间留接缝；
- 前提：底模/节点支持；当前 Z-Image 工作流不支持，**不要在没有验证前接入**。

### 6.5 方案 E：出图后修脸（兜底）

- ComfyUI `FaceDetailer`：自动检测脸部 → 局部重绘 → 挂参考图/LoRA；
- 只修脸，不动构图；建议作为"导出前最后一道"；
- 注意：修脸也会改表情，修完要重看这一格的情绪是否还在。

## 8. handraw-style 与分页下的一致性补充（H11–H18）

### H11　一套造型只保留一件外层

人设里常同时写"工装夹克 + 羊毛大衣"。提示词层会只保留**第一件外层**
（`CHARACTER_SINGLE_OUTERWEAR=True`），并删掉"薄纱/透明/透视"描述；
完整人设仍保留在工程和导出文档里供人工查看。目的：主视图与姿态总图不会
一件夹克、一件大衣各画一次。

### H12　角色预设：主视图 + 面部特写 + 单视图 + 俯视

当前角色预设资产（阶段 3 自动生成）：

1. **主视图**：1024×1536，单人正面 T2I，身份主参考；
2. **面部特写**：512×512，从主视图裁头肩，特写/近景的身份参考；
3. **三视图**：1536×768，正面=主视图，侧面/背面从主视图生成，只做人工查看；
4. **单视图**：`views/front|side|back`，从三视图切分；侧身/背身镜头按需送；
5. **俯视图**：有真实参考时生成，按人脸检测标 `top_down/high_angle`；只用于真顶视镜头。

姿态总图只用于人工查看/姿态库，**不进分镜参考**；三视图整张也不进分镜。
旧字段 `triple_view` / `view_paths` 只做旧工程兼容。

### H13　发型与眼睛必须写死

- 发型：`全部头发向后收进低马尾/发髻，额前与鬓角干净，不散发、不半扎、不双马尾`；
- 眼睛：`双眼大小一致、瞳孔居中、看向同一方向`；
- 负向词：`散发、披发、半扎发、一半扎一半披、双马尾、大小眼、异色瞳、瞳孔偏移、斜视`。

只写"低马尾"会留下"一半扎一半披"的解释空间；只写"杏眼"会出现大小眼。

### H14　风格块是"画风"，不是"人设"

handraw 的触发词/阶调只负责线条、笔触、媒介、色彩与明暗，
不能替代身份卡；不要让风格词改掉发色、服装、记忆点。
风格块在角色主视图、姿态总图、每一格分镜里都出现，且只用同一段。

### H15　参考图能锁脸，但要按景别/视角路由

Qwen 分镜的参考图通道已修复（Autogrow 扁平键 `images.image_N`），
参考图会真正进入模型；但“送得对”比“送得多”重要：

- 特写/近景：面部特写 + 主视图（脸 + 服装）；
- 中景：主视图；
- 侧面/背面：主视图 + 对应单视图；
- 正顶视：主视图 + 俯视图，且俯视必须是 `top_down`；
- 全景/远景：默认 0 张（实测 `main+back` 会把背影复制成两个人）；
- 双人：每人一张面部特写；3 人 0 张；4 人拆 3+1/2+2。

Z-Image 的 `style_color` 仍只做色彩迁移；不要把“画风参考”当成“角色参考”。
LoRA 仍不在 8GB 主路径；需要严格锁脸时优先加参考图路由/后期，而不是堆提示词。

### H16　负向条件按角色类型分开

- 主视图：多余人物、第二个人、额外外套、透明衣物、薄纱、眼镜（角色无眼镜时）；
- 姿态总图：不同脸/不同发型/不同服装、散发、大小眼、透明衣物；
- 分镜：按镜头/人数/服装颜色组合，不把"多格/分镜"加到角色图上。

### H17　年龄/身高关系必须进“画面内容”

多人同框时，年龄/身高不能只写在角色卡里：

- `castguard.compact_card()` 必须保留年龄字段；
- 少年/儿童与成人同框时，画面内容写“X 是十二岁，Y 是成年人，X 比 Y 小得多；X 只到 Y 胸口”；
- 预设本身也要按年龄带生成（主视图、面部特写、三视图同一套），否则会“一致地错”。

### H18　四人同框上限按 3 人用

Qwen 2.1 Turbo 实测 4 人输出 5 人（尤其有儿童/少年时多画一个）。
分镜设计按 **3 人上限**；4 人拆 `3+1` 或 `2+2`，不要靠负向词/多脸重试硬压。
