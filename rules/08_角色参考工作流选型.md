## 结论

当前 **8GB 显存 / 16GB 内存** 下，角色一致性主路径是：

```text
姿态总图（Pose ControlNet，1536²）
  → 裁左上正面 → 主视图（1024×1536）
  → 分镜只把主视图当身份参考
```

不接 LoRA，不接 Qwen Image Edit，不接 Flux Redux/ICEdit。

> **2026-11-03 更新：** 本结论针对 2026-10 的旧环境。Qwen-Image-2.1 Turbo 已在本地可用，参考图通道（Autogrow 扁平键）已修复；分镜参考不再“只送主视图”，而是按景别/视角/人数路由 1–2 张（面部特写/主视图/侧面/背面/俯视）。详见 `角色分镜一致性资料/03_分镜参考路由与提示词规范.md` 与 `06_落地实现与测试记录.md`。

## 为什么不是 LoRA

- ComfyUI `TrainLoraNode`：8GB 实测 12.36GiB OOM；
- AI Toolkit：int8 反量化 14.21GiB OOM；fp8 仍需同时驻留 Qwen3-4B，训练阶段 OOM；
- 结论与归档：[archive/lora/README.md](../archive/lora/README.md)。

12GB+ 或云 24GB 才能稳定训练；需要时再用 musubi-tuner 的 De-Turbo/block swap 路线。

## 为什么不是 Qwen Image Edit / Flux

| 方案 | 问题 |
|---|---|
| Qwen Image Edit Plus（参考资料 2026.03.21） | 需要另一套 Qwen 编辑底模和 16 路参考链；本机没有权重 |
| Flux Kontext / Redux / ICEdit | 与 Z-Image 的 UNET/CLIP/VAE 不兼容；8GB 也不够 |
| Krea2 + Z-Image 4K | 需要 Krea2 底模 + SeedVR2 节点/VAE；当前未安装 |

这些方案的思想可以借鉴（多角度、先总图再裁参考、姿态骨架），但不直接接模型。

## 当前工作流

| 用途 | 工作流 | 说明 |
|---|---|---|
| 角色姿态总图 | `image_z_image_turbo_int8_character_pose` | 2.1 lite ControlNet，1536²，8 步，strength 0.85 |
| 普通分镜 | `image_z_image_turbo_int8` / `..._style_color` | 现有风格链 |
| 本格指定姿态 | `image_z_image_turbo_int8_character_pose` | 上传骨架/真人照，same workflow，不送角色参考 |

## 注意事项

1. **ControlNet + Omni/ReferenceLatent 不兼容**：batch 维度会在 KSampler 报错；
   姿态图只用文本身份锁，不送角色参考图。
2. **姿态总图不进分镜**：多身体参考会被抄成多人构图。
3. **主视图只从姿态总图裁**：不再单独文生图，也不再用旧三视图重排。
4. **自定义姿态**：真人照片先经 MediaPipe 转骨架；骨架图直接用。
5. **分镜一致性**：提示词身份锁 + 固定 seed + 服装/发型/眼睛负向词；
   本格动作复杂时再加 Pose ControlNet。
