# 分镜与镜头规则（Storyboard Directing Rules）

> 平台层面的条漫规范（画布、转场配比、gutter、悬念位置）见
> [条漫叙事与分镜规则.md](../docs/条漫叙事与分镜规则.md)。
> 本文只管一件事：**一条分镜在出图前是否"可拍"**——能不能被一个只会看文字的画师照着画出来。
> 机器可读版本：[`data/storyboard_rules.json`](data/storyboard_rules.json)。

---

## 0. 一句话原则

**一格 = 一个 beat = 一个瞬间 = 一个视觉焦点 = 一个可画的动作。**

判据（来自条漫规则文档）：**删掉这一格，读者对因果的理解如果毫无变化 → 这格无效。**
无效格只能是氛围格，且每场景占比 ≤30%。

---

## 1. 可拍性描述公式（P1）

每条 `description` 必须按下面 6 个槽位写，缺一不可：

| 槽位 | 写什么 | 反例 | 正例 |
| --- | --- | --- | --- |
| ① 谁 | 角色姓名（+身份卡锚点词） | "一个女人" | "陆鸣（低马尾、炭黑短风衣）" |
| ② 在哪 | 画面位置：左/右/中，前景/中景/后景 | "在房间里" | "在画面右侧中景，背对门" |
| ③ 做什么 | **一个**动作瞬间（到哪一帧） | "她起身走到窗边推开窗" | "右手已经推到窗框，窗开了一半" |
| ④ 视线/表情 | 看哪、什么表情 | "她心情复杂" | "眼睛盯着门缝，嘴唇抿紧" |
| ⑤ 前/后景 | 各有什么，谁挡谁 | "背景有些东西" | "前景是门框，后景是街灯和雨" |
| ⑥ 光 | 光从哪来、什么方向 | "冷色调" | "街灯从左后方打来，脸侧留一道边缘光" |

字数：**28~110 字**（生成目标）；低于 18 字或高于 120 字会被自检判为硬失败。
低于 28 字信息不足，高于 110 字模型开始丢槽位。

**反例（当前工程，第 1 格）**：
```
俯视全景，狭小工作室堆满机柜，唯一光源是桌面台灯，陆鸣在右，老太太在左，
中间桌上放着碎屏手机，冷色调
```
问题：开头复述景别（`俯视全景`）；③ 没有动作瞬间；④ 没有视线；⑥ 只写"冷色调"没写方向。

**改写后**：
```
狭小工作室，四台机器贴墙摆到天花板。陆鸣在右侧台灯下，右手已经把手机按在读盘器上；
老太太坐在左侧，双手放在膝上，眼睛盯着那部手机。前景是堆叠的硬盘盒，台灯从左前方打亮桌面。
```

## 2. 描述里禁止出现的五类内容（P2）

| 类别 | 例子 | 为什么禁止 |
| --- | --- | --- |
| **镜头词** | "俯视全景""特写""过肩镜头" | 景别/机位是独立字段，重复会让提示词自相矛盾（当前 59/92 格犯） |
| **台词/引号** | "「你来了」" | 会被画进画面（模型会尝试画字） |
| **心理描写** | "她想：他一定在骗我""心里一沉" | 画不出来，只会变成表情乱猜 |
| **比喻堆砌** | "像被抽走了骨头一样塌下去" | 抽象，模型会自由发挥 |
| **原文整段** | 把小说段落原样贴进来 | 一格塞多个 beat，画面必崩 |

校验：`director.validate` 的 `desc_camera_words` / `bad_description` 两个检查项。

## 3. 人数政策（P3）

| 人数 | 允许的镜头 | 台词 | 备注 |
| --- | --- | --- | --- |
| 0（物件/空镜） | 特写、近景、远景 | 旁白 / 音效 | **不要**强行补主角；屏幕类镜头不写"人物" |
| 1 | 任意 | ≤3 条 | 默认形态 |
| 2 | 远景、全景、中景 | ≤1 条 | 必须写左右、必须写明谁说话 |
| 3 | 远景、全景、中景 | ≤1 条 | 群像/对峙/建立镜头；逐人写位置/动作/视线；Qwen 群像甜点 |
| 4 | 拆成 3+1 或 2+2 | — | Qwen 实测 4 人会多画一个（尤其有儿童/少年） |
| 5+ | 禁止 | — | 拆成群像 + 单人反应格 |

补充：
- **对白优先单人**：A 说话 → A 的单人/近景；B 的反应 → B 的单人反应格。
  这是"正反打"（shot / reverse-shot），也是条漫最稳的对白拍法。
- **过肩镜头在本项目里默认不用**：纯文生图会把前景肩背画成一个独立的
  第三个人，即使 `characters` 只列了两个人也一样（2026-10 实测）。
  单/双人都改用斜侧/平视；需要前景纵深就用门框、桌沿、枝叶做遮挡，
  不要用"人的肩背"当前景。
- 物件镜头只有在该物件**就是**叙事主体时才用；不要为了"空镜好看"牺牲信息。
- 物件格必须带 `object_mode`：
  - `物证照`（手机+血迹/遗物）：俯拍平放 + 比例尺，画面只有物件/台面/反光；
  - `屏幕界面`（时间/记录/号码）：屏幕亮着，抽象色块与数字，不出现人像；
  - `环境细节`（桌面/墙面/门缝）：环境局部，没有人物。
- 需要"手"的镜头写成**斜侧+手**（人物格），不要写"物件特写"再指望模型不画人；
  也不要用单人过肩，前景肩背会被画成第二个人。

## 4. 台词归属（P4）

一张图里"谁在说话"必须同时满足三条，缺一条就会出现"说别人的话"：

1. **数据层**：`dialogue.speaker` 必须是 `shot.characters` 里的人，或者 `offscreen=true`；
2. **画面层**：提示词写明"这一格说话的是 X，只有 X 张嘴"；
3. **排版层**：气泡槽位在 X 的那一侧，尾巴指向 X 的脸（见第 5 节）。

规则：
- 说话人不在画面里（电话、回忆、画外音）→ `offscreen=true` + 气泡放顶部居中 + **尾巴 none**；
- 同一格两个人都说话 → 拆格（除非是"同时喊"的冲击格，需人工确认）；
- 台词为空/说话人为空 → 不允许进 `dialogues`，或者按"旁白"处理；
- **空说话人自动归位**（`director._fix_empty_speakers`）：
  ≤12 字的（时间、状态、屏幕文字）转 **旁白条**，不占气泡；
  更长的标 **画外音**，顶部居中、无尾巴；
- **长台词自动拆泡**（`director._split_long_speech`）：
  单条 >20 字时按标点拆成同格 2~3 个气泡，最多 3 个，保证手机可读；
- 不允许"旁白"承担对话功能（旁白只做时空定位、内心、因果桥接）。

## 5. 气泡规则（P5）

> 气泡是**画面构图的一部分**：出图时由图像模型画出来，程序只负责定位与填字。
> 因此气泡的位置、尺寸、数量必须在分镜阶段就确定，并写进图像提示词。
> 例外：`style_color`（色彩迁移）工作流会把气泡一起染色，此时气泡改由程序绘制，
> 提示词只留干净背景（见 `rules/07_风格与分镜版式.md` 与 `pipeline.generate_one_shot`）。

### 5.1 位置与坐标

| 说话人站位 | 槽位顺序（按台词先后） | 尾巴方向 |
| --- | --- | --- |
| 左 | top-left → mid-left → bottom-left | 朝左（指向说话人的脸） |
| 右 | top-right → mid-right → bottom-right | 朝右 |
| 画外音 | top-center | none |
| 旁白 | 画面顶部通栏 | none |

- 每个气泡必须有 `x/y/w/h`（画面百分比），由 `bubble.plan_layout()` 计算；
- 气泡之间不重叠、不贴画面边缘（离边至少 2%）；
- 有旁白时，顶部 8% 让给旁白条，气泡从下方开始；
- **近景/特写强制放顶部**：脸占掉大半画面，mid/bottom 会把气泡挤到反侧；
  双人格放 top-center，单人格按站位放 top-left/top-right；
- **阅读顺序**：第 1 条台词的气泡在最上，第 2 条在中，第 3 条在下。

### 5.2 数量与字数

- 单格 ≤3 条台词；单条 ≤20 字；旁白 ≤24 字；拟声词 ≤6 字；
- 长台词拆到相邻格，不要缩字号硬塞；
- **气泡数量 = 台词条数**，提示词里写"只有这 N 个"；
- 模型多画的气泡 → `bubble_count_mismatch`，补成背景并返修；
- 模型少画/没画 → `bubble_fallback` / `bubble_detect_fail`，返修时重申"只有 N 个"。

### 5.3 尾巴

- 尾巴必须指向说话人的**嘴部附近**，不能指向另一个人；
- 尾巴不要穿过眼睛；
- 画外音、旁白、拟声词**没有尾巴**；
- 提示词必须写清"尾巴指向画面左侧/右侧的某人"，不能只写"带尾巴"。

### 5.4 出图后的定位与回填（关键）

出图后不能"按计划框硬填"，必须**在画面里找回气泡**：

1. **候选检测**（`bubble._balloon_candidates`）：
   - 以 **320px 宽**检测（180 会让描边丢像素，气泡和背景漏成一块）；
   - 近白（≥226）、低饱和（max-min≤26）、实心（fill≥0.5）；
   - 宽高比 0.25~7，外接框面积占画面 0.6%~28%，白色主体 ≥0.6%；
   - 深色（lum<150）膨胀 2px 封住描边缺口，再取白色连通域；
   - 每条边取 2px 窄带的 20 分位判断暗描边，**至少 3 条边**成立；
   - 最多贴 1 条边（允许贴顶/贴左，分镜裁切常见）。
2. **一对一匹配**（`bubble.detect_blank_bubbles`）：
   - 计划框 vs 候选框：中心距离 + 面积比 + 左右侧别 + IoU 综合打分；
   - 全局贪心，一个候选只能配一条台词；
   - 侧别不符直接跳过（`BUBBLE_MATCH_REQUIRE_SIDE`）。
3. **回填**（`layouts_from_plan`）：
   - 匹配到 → 用气泡**白色主体的内接框**填字（不含描边/尾巴），`drawn_in_art=True`；
   - 没匹配到 → 在不与已检测气泡重叠的位置程序补画，`drawn_in_art=False`，
     记 `bubble_fallback`，触发返修；
   - 一个都没匹配到 → 整格程序兜底，记 `bubble_detect_fail`；
4. **多画的气泡**：用调和填充按气泡形状补成背景，记 `bubble_count_mismatch`；
5. **QA**：`bubble_debug = {expected, detected, extra, fallback}` 写进工程，
   并落盘到 `data/projects/<id>/prompts/07_bubble/` 便于回溯。

### 5.5 返修措辞

```
画面里只有 1 个空白气泡，严格按上面每个气泡的坐标与尺寸画，
气泡纯白、黑色描边、内部没有文字，彼此不重叠。
```

正面、具体、带数量；不要写"不要多画"。

## 5.6 分镜配额（程序会自动重排）

| 配额 | 默认值 | 超了怎么办 |
| --- | --- | --- |
| 总格数 | 16 格/千字，夹在 30~120 | 合并相邻同场景格（保留台词，最多 3 条） |
| 双人同框 | ≤25% | 中/近/特写拆成"说话人单人 + 听者反应单人"；双人 >1 条台词无条件改；不要用"单人过肩" |
| 3~4 人群像 | ≤10% | 保留 3 人群像/对峙/建立镜头；4 人拆 3+1/2+2；>1 条台词只留 1 条，其余转画外音；5 人以上拆 |
| 近景+特写 | ≤30% | 近景降中景；特写保留给情绪峰值 |
| 画外音 | 改旁白条 | 不画气泡，避免"尾巴指向别人" |

实测：`xiaoshuo.txt` 5.1k 字，模型初拆 116 格 → 自动合并到 **82 格**；
双人 49→20（24.4%），近景+特写 56→24（29.3%）。

## 6. 镜头节奏（P6）

沿用条漫规则文档的量化基线，这里只列**程序会强制检查**的：

| 检查 | 阈值 | 代码 |
| --- | --- | --- |
| 同景别连续 | ≤2 格 | `_enforce_shot_run` |
| 同机位连续 | ≤2 格 | `_enforce_camera_run` |
| 新场景首格 | 远景/全景（物件特写除外） | `_enforce_scene_establishing` |
| 近景+特写占比 | ≥24% | `_enforce_closeup_ratio` |
| 画幅档位 | ≥3 种，单档 ≤60% | `_enforce_panel_scale_mix` |
| 连续有台词格 | ≤3 格，第 4 格前插反应格 | `validate` |
| 纯画面格 | 15%~30% | `validate` |
| 章末钩子 | 最后 1 格 `hook=true` | `_mark_flags` |
| 180° 轴线 | 同场景左右不互换 | `_assign_sides` |

## 7. 转场与场景（P7）

| 转场 | 用法 | 配比 |
| --- | --- | --- |
| 动作衔接 | 同一动作的下一拍 | 40~50% |
| 主体切换 | 对话切人、切反应 | 20~25% |
| 时刻分解 | 关键动作的细分（≤4 格） | 5~10% |
| 场景切换 | 必须配建立镜头 | 5~10% |
| 氛围铺陈 | 环境、手、道具（≤3 格连用） | 10~15% |

场景切换必须有一格"桥接"（旁白/道具/视线/建立镜头），否则读者不知道"这是哪"。

## 8. 分镜字段规范（P8）

一条分镜的完整 JSON（新增字段已接入 `models.Shot`）：

```json
{
  "shot_type": "近景",
  "camera": "过肩",
  "composition": "前景遮挡",
  "lighting": "侧光",
  "panel_scale": "M",
  "transition": "主体切换",
  "characters": ["陆鸣"],
  "char_sides": {"陆鸣": "右"},
  "char_positions": {"陆鸣": "右侧中景，背对门"},
  "gaze": "看向画面左侧的画外人",
  "props": ["碎屏手机", "读盘器"],
  "scene": "陆鸣工作室",
  "time_of_day": "凌晨",
  "focus": "她按在读盘器上的手指",
  "action": "右手把手机按进读盘器，屏幕刚亮",
  "expression": "眼睛盯着接口，嘴唇抿紧",
  "description": "（按 P1 六槽位写，28~110 字）",
  "mood": "压抑",
  "silent": false,
  "hook": false,
  "dialogues": [
    {"speaker": "陆鸣", "text": "四天前，最后一次亮屏。", "tone": "平静",
     "kind": "speech", "slot": "mid-right", "offscreen": false}
  ]
}
```

字段约束：
- `characters` 只放**画面里看得见**的人；
- `char_sides` 与 `description` 的左右必须一致（`_assign_sides` 会以描述为准纠正）；
- `gaze` 写"看向画面左/右/画外/对方"，供出图时写视线方向；
- `props` 写这一格必须出现的道具（连续性：上一格出现的手机，这一格不能消失）；
- `silent` = 台词/旁白/音效**全都没有**。

---

## 9. 拆解粒度（P9）

- 一般 **70~110 字原文 = 1 格**；
- 一个连续动作（起身→走→推窗）拆 3 格；一段静止描写合并 1 格；
- 一章 45~80 格（快看单话量）；
- 每 6~8 格至少 1 格纯画面；每 4~6 格换一次转场类型；
- 不要按句子逐句拆，要按 beat 拆。

---

## 10. 自检清单（P10）

出图前必须清零：

- [ ] 每格 `description` 没有镜头词、引号、心理描写
- [ ] 每格描述里有：人（或明确"只有物件"）、位置、一个动作、视线、光
- [ ] 每格人数 ≤2 默认；3 人例外；4 人已拆；双人格 ≤1 条台词
- [ ] 每条台词的 speaker 在 `characters` 里，或 `offscreen=true`
- [ ] 每格台词 ≤3 条、单条 ≤20 字
- [ ] 同场景没有连续 3 格同景别/同机位
- [ ] 新场景有建立镜头；章末有 hook
- [ ] `props` 在相邻格里没有无故消失
- [ ] 气泡槽位与说话人站位一致
- [ ] 每格有 `beat` / `pacing` / `panel_emphasis` / `caption`（分页选版式要用）
- [ ] 分页计划覆盖全部格子，顺序不乱、格数匹配

## 11. handraw 叙事信号与分页（P11–P15）

### P11　每格必须带叙事信号

分镜拆解时除镜头/动作/台词外，必须写：

| 字段 | 取值 | 用途 |
| --- | --- | --- |
| `beat` | 建立/对白/反应/动作/情绪/转场/揭示/蒙太奇/日常/幽默/悬疑/细节 | 决定版式适配度 |
| `pacing` | 慢/中/快 | 决定格子面积与切分 |
| `panel_emphasis` | normal/main/splash | 决定是否给大格/满版 |
| `caption` | 短句（≤30 字） | 上图下文版式的字幕栏 |

缺 `beat` 时 `pagelayout.annotate_shots()` 会按镜头/台词/动作自动推断，
但推断不如人工/模型显式写好；这四项是"内容驱动版式"的输入，不是可选装饰。

### P12　分页是分镜的一部分

- 一页 2~6 格；页首格负责进入，页尾格负责转折/钩子；
- 同一场景内尽量同页；场景切换/时间跳转是换页/换形态的最佳切点；
- 单格页只给章首、章末、大反转、满版冲击；一话单格页不超过 35%；
- 不要把连续对白拆成 3 页单格，AI 方案出现这种情况会被 `pagelayout` 退回本地。

### P13　版式不是模板轮播

版式由 `beat` + 对白密度 + 动作 + 情绪 + 场景连续性打分选出，
7 维适配度：对话/动作/情绪/建立/蒙太奇/悬疑/喜剧。
同一版式连续出现时会换同格数的近似版式；不要为了"每页不一样"牺牲叙事。

### P14　正向/负向分开写

- 正向：画面里有什么、谁、在哪、什么动作、什么光；带 handraw「漫画分级特征」块；
- 负向：低质量、多格/画框、文字、多余人物、透明衣物、程序气泡等；
- 正向里不要写"不要X"；负向词只在 `COMFY_CFG>1` 时生效。

### P15　分格页的提示词差异

同一格在条漫和分页里的提示词不同：分页要带该格的 `panel_orientation`
（wide/tall/square）与 `panel_role`，并按格子比例生成；否则模型按整幅条漫构图，
拼页时会被裁切或留大片空白。
