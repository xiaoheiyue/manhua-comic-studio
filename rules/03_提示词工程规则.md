# 提示词工程规则（Prompt Engineering Rules）

> 目标：让 Z-Image-Turbo（8 步蒸馏 / Qwen3-4B 文本编码器）在一张竖幅/分格画幅里，
> 画出**一个镜头、一个瞬间、一群能分清的人**，同时保持 handraw-style 的画风。
> 机器可读版本：[`data/shot_prompt_rules.json`](data/shot_prompt_rules.json)。

---

## 1. 先说模型方言：六条不可违反的约束

| # | 约束 | 原因 |
| --- | --- | --- |
| D1 | **正向只写"要什么"；"不要 X"放到独立的 negative 节点** | 工作流 `KSampler.negative` 已接 `CLIPTextEncode`；`COMFY_CFG=1.4` 时负向词生效。不要把负向词写回正向 |
| D2 | **不需要气泡的格子，一个字都不提"气泡"** | 实测只要正向出现"气泡"，没有台词的格子也会多画一个空白气泡；程序画气泡时不写气泡 |
| D3 | **不写"分镜 / 一格 / 漫画格 / 拼贴"** | 模型会理解成"画一张带边框的漫画页"，于是加白边、切格；分格页改用"格子画幅比例"描述 |
| D4 | **不写与当前画风冲突的词** | 选了 FI 写实电影风就不要写"二次元/赛璐璐"；选了 FG 赛璐璐就不要写"写实照片/3D"。handraw 风格块本身就是风格本体，不能被 `_sanitize_prompt` 洗掉 |
| D5 | **不在提示词里出现画面中不存在的人名** | 哪怕只是"另一个人在门外"，模型也会把那个人画进来 |
| D6 | **风格触发块只出现一次** | `漫画分级特征` + `视觉语言` + `主题色` 已经够；重复会挤占预算、放大某个词 |

> D1~D3 是项目既有结论；D4/D6 是 handraw-style 接入后的新约束。
> 详见 [07_风格与分镜版式.md](07_风格与分镜版式.md) 与 `config.HANDRAW_PROMPT_*`。

## 2. 拼装顺序（固定，不要随意调）

```
1. handraw 风格块：视觉语言（本图必须执行，traits 开头）→ 画风执行（线条/人体/材质）
   → 漫画分级特征（媒介+漫画特征+阶调）→ 主题色
2. 人数声明：画面里只有一位/两位人物（正向排他，不写"没有第二个人"）
3. 角色绑定：左侧三分之一是 A：<短身份卡>；右侧三分之一是 B：<短身份卡>
4. 隔离声明：双人 → 具体差异对照 + 中间留空；单人 → 唯一人物 + 空场景构图锁
5. 说话人绑定：这一格说话的是 A，只有 A 张嘴；B 闭着嘴看向 A
6. 镜头语言：景别；机位；构图；光线（各 1 短句）
7. 画幅/分格声明：竖幅 / 横向宽幅 / 近乎方形 + 分格页的格子比例
8. 动作瞬间 / 表情 / 视觉焦点
9. 画面内容（description，已净化）
10. 场景 / 时间 / 情绪
11. 质量收尾（1 句）
```

> 气泡不在正向里：色彩迁移链路会染色空白气泡，改为程序画，提示词不提气泡。
> 负向条件单独走 `prompts.negative_prompt()` → `KSampler.negative`。

为什么把"人数 + 角色 + 隔离"提到镜头前面：

- 文本编码器对靠前的实体绑定更强；把 700 字人设放在画面内容前面，等于让"角色百科"淹没"这一格在演什么"；
- 人数与隔离声明放在前面，是**唯一能阻止模型"补人/平均脸"的正面写法**；
- 镜头词放在身份之后，避免"特写=脸占满画面"把双人格压成一张大脸。

## 3. 长度预算（硬上限）

| 段落 | 上限 |
| --- | --- |
| handraw 风格块（分级特征 + 视觉语言 + 主题色） | 300 字 |
| 人数 + 隔离声明 | 120 字 |
| 角色绑定（每人短身份卡） | 单人 ≤130 字 / 双人每人 ≤94 字，总 ≤200 字 |
| 镜头语言 + 画幅/分格 | 120 字 |
| 动作/表情/焦点 | 90 字 |
| 画面内容 | 110 字 |
| 场景/时间/情绪 | 60 字 |
| 收尾 | 40 字 |
| **正向总计** | **双人 ≤900 字；三人 ≤980；四人 ≤1060** |
| **负向词（独立）** | **≤ 900 字** |

超预算时的裁剪顺序（从后往前丢，绝不切半句）：

```
风格补充 → 视觉焦点 → 场景 → 表情 → 画幅/分格 → 情绪 → 时间 → 画面内容缩到 90/70/55 字
```

**不要裁角色卡**：旧版按 64/52/42 字切卡片，结果把"眼睛：…"切成
"眼睛（画面右侧中景）"，模型读到的是一张病句卡，反而更容易画错人。
现在双人卡按 94 字整卡生成，超预算只丢可选段，不切卡。

原因：长提示词会显著降低属性绑定准确率
（[ICML 2026](https://openreview.net/forum?id=AZ0VQouDmR)；社区实践同样建议"身份块短而稳"，
[ComfyUI 一致性指南](https://www.media.io/image-tips/comfyui-consistent-characters.html)）。

当前工程实测 **830~900 字/张**，双人卡各 90 字左右；旧版 1193~1268 字里约 700 字
是两个角色的完整人设散文——这就是"越写越像同一个人"的直接原因。

## 4. 人数与角色的写法（核心模板）

### 4.1 单人（默认）

```
画面里只有一位人物，就是陆鸣；画面里出现的其他东西都是环境与道具。
画面里只有陆鸣一个人物，只画头顶到胸口，腰部以下在画面之外；
背景是虚化的空无一人的夜晚街巷，画面里唯一的人影就是陆鸣。
```

要点：
- **"只有一位人物"** 比"一个人"强得多；配"画面里唯一的人影"形成双重排他；
- 身份卡逐字复用，不改同义词；
- 不要写"她看向画外的人"——改成"她看向画面右侧"；
- 单人场景先替换成空场景（见 4.4），不要保留"街头/酒馆/人群"。

### 4.2 双人（仅对峙/建立镜头）

```
画面里只有两位人物，就是叶哥和陆鸣；画面里出现的其他东西都是环境与道具。
画面左侧三分之一是叶哥：女，偏窄鹅蛋脸，及背中长直发偏分，细长上挑杏眼，
深藏青修身长风衣，左耳细银耳线；
画面右侧三分之一是陆鸣：女，鹅蛋脸，及肩黑发低马尾，细长上挑杏眼，
炭黑短风衣，颈挂旧U盘。
两张脸各自独立：叶哥是偏窄鹅蛋脸、长直发偏分；陆鸣是鹅蛋脸、及肩低马尾。
叶哥穿长款风衣，陆鸣穿短款风衣。
叶哥在画面左三分之一，陆鸣在画面右三分之一；两人之间留出一臂宽的空隙，
背景从空隙里透出来。
这一格里说话的是叶哥，只有叶哥张嘴；陆鸣闭着嘴，看向叶哥。
```

要点：
- 一人一段，**不要交叉写**（先写完 A 的全部特征，再写 B）；
- 必须写两人的**具体差异**（脸型/眼型/发型/外套轮廓/记忆点），不要写"明显不同"；
- 必须写**左右分区 + 中间留一臂空隙**；
- 不要用"她们""两人都"开头；
- 不要写第三个人的名字；
- 说话人绑定句必须紧跟在角色绑定之后。

### 4.3 物件/空镜

```
画面里只有物件与它所在的空间：手机屏幕占满画面，裂纹从左上角扩散，
边缘有一圈暗红指印，台灯光从左上方斜打下来。
```

要点：
- 用"画面里只有物件与它所在的空间"，**不要**写"不要出现人物"（D1）；
- 不要在物件格里放任何角色身份卡；
- 镜头词用 `SHOT_TYPE_PROMPT_MAP_OBJECT`（避免"特写=人脸占满"）。

### 4.4 人数锁与角色隔离（castguard，2026-10 新增）

`comicgen/castguard.py` 负责把上面三条模板落到代码里，原则是
**只写正面、一人一段、差异对照、物理留空**。它不修改工程里的分镜数据，
只生成一份"出图视图"。

#### 双人：一人一段 + 差异对照 + 左右分区

```
画面里只有两位人物，就是林晚和沈砚；画面里出现的其他东西都是环境与道具。
画面左侧三分之一是林晚：女，瘦长脸，佩恩灰及肩低马尾，细长上挑杏眼，
普鲁士蓝长款旧风衣，左手腕内侧月牙形浅白烫伤疤；
画面右侧三分之一是沈砚：男，棱角分明的长方脸，佩恩灰黑短发，
细长平直眼，普鲁士蓝立领旧工装外套，右眉尾短浅旧疤。
两张脸各自独立：林晚是瘦长脸、细长上挑杏眼、及肩低马尾；沈砚是长方脸、
细长平直眼、短发。林晚穿长款风衣，沈砚穿短款工装。
林晚在画面左三分之一，沈砚在画面右三分之一；两人之间留出一臂宽的空隙，
背景从空隙里透出来。
```

硬规则：
- **一人一段**：A 的发型/发色/瞳色/服装/记忆点一次写完，再写 B，绝不穿插；
- **差异必须具体**：不要写"两人明显不同"，要写出脸型、眼型、发型、外套轮廓的
  实际差异（`contrast_block` 从 `hard_features` 自动生成）；
- **左右分区**：`char_sides` 必须一左一右；没有就按角色顺序补；
- **中间留空**：两人之间留一臂宽背景，既是构图，也是防止两张脸黏在一起；
- **记忆点**：优先用角色已有的疤/痣/耳饰/发夹；没有就由人设阶段补一处
  不对称特征（`hard_features.asymmetry`）。

#### 3~4 人：逐人分块 + 横列留空

```
画面里只有三位人物，就是林晚、沈砚、林雨；画面里出现的其他东西都是环境与道具。
左侧前景是林晚：女，瘦长脸，佩恩灰及肩低马尾，细长上挑杏眼，
普鲁士蓝长款旧风衣，左手腕内侧月牙形浅白烫伤疤；
中央中景是沈砚：男，棱角分明的长方脸，佩恩灰黑短发，细长平直眼，
普鲁士蓝立领旧工装外套，右眉尾短浅旧疤；
右侧中景是林雨：女，略方短圆脸，普鲁士蓝黑齐耳短发，圆大黑豆眼，
佩恩灰宽大圆领针织衫，左耳旧铜色小发夹。
每张脸各自独立：林晚是瘦长脸、细长上挑杏眼、及肩低马尾；
沈砚是长方脸、细长平直眼、短发；林雨是短圆脸、圆大黑豆眼、齐耳短发。
外套轮廓不同：林晚长款，沈砚短款，林雨针织衫。
林晚在画面左三分之一，沈砚在画面中央，林雨在画面右三分之一；
相邻两人之间留出半臂宽的空隙，背景从空隙里透出来。
```

4 人时最后一句改成：

```
画面从左到右依次是 A、B、C、D，排成一条错落的横列；
相邻两人之间留出半臂宽的空隙，背景从空隙里透出来。
```

硬规则：
- **上限 4 人**：5 人以上由导演层拆成群像 + 单人反应格；
- 3~4 人只用于群像、对峙、建立镜头；每格最多 1 条台词；
- 每人的 `char_positions` 与 `character_actions` 必须单独写，不能共用一句；
- 逐人卡压到 82 字，给差异对照和空间声明留预算；
- 3 人预算 980 字、4 人 1060 字（双人仍 900）。

#### 单人：正向排他 + 空场景 + 构图锁

```
画面里只有一位人物，就是林晚；画面里出现的其他东西都是环境与道具。
画面中央近景是林晚：女，瘦长脸，佩恩灰及肩低马尾，……。
画面里只有林晚一个人物，只画她的头顶到胸口，腰部以下在画面之外；
背景是虚化的空无一人的夜晚街巷，画面里唯一的人影就是林晚。
```

硬规则：
- 场景先"去人群"：`街头 → 空无一人的街头`、`走廊 → 空无一人的走廊`、
  `酒馆 → 吧台空置的安静酒馆`、`广场 → 空旷的广场`；
- 描述先"去召唤词"：`两人/对方/路人/人群/观众/同伴/肩背/半张脸/人影`
  全部替换或删除，画面外角色名替换成"画面外的方向"；
- **过肩一律降成斜侧**：纯文生图会把前景肩背画成独立的第三个人，
  单人、双人都实测过；需要前景纵深用门框/桌沿/枝叶遮挡；
- 远景/全景补"人物占画面高度约三分之二 / 画面里唯一的人影"，
  别让画面边缘留出大片空地；
- 近景/特写不要写"完整人物"——"完整"会诱导模型画全身；写
  "只画头顶到胸口，腰部以下在画面之外"。

#### 负向清单按人数切换

`prompts.negative_prompt()` 现在把人数负向放在最前面（避免被风格词挤出 900 字上限）：

| 人数 | 负向核心词 |
| --- | --- |
| 0 | 人物、人脸、人像、手、手指、身体、腿、人群、人影 |
| 1 | 第二个人、多余人物、背景路人、人群、围观者、观众、半截人影、克隆人、双胞胎、分身、镜像人、倒影人、画面分割、分屏 |
| 2 | 第三个人、多余人物、人群、围观者、克隆脸、融合脸、两张一样的脸、换脸、脸型互换、服装互换、发型互换、镜像、倒影、画面分割 |
| 3 | 第四个人、多余人物、人群、围观者、克隆脸、融合脸、换脸、服装互换、发型互换、镜像、倒影、画面分割 |
| 4 | 第五个人、多余人物、人群、围观者、克隆脸、融合脸、换脸、服装互换、发型互换、镜像、倒影、画面分割 |

> 正向与负向必须成对：只做正向"只有一个人"，模型偶尔会把主角拆出一个
> 半截影子；只做负向"第二个人"，模型又会把主角放大到顶出画框。
> 两边同时写，才是"两头堵"。

#### Z-Image 不吃 A1111 权重

`(独自一人:1.3)` 这类权重语法是 SD/MJ 的方言，Z-Image 的 Qwen3-4B 文本编码器
会当成普通文字。这里用**句首人数锁 + 重复"唯一的人影" + 构图锁**代替权重，
不写 `(...:1.3)`。

## 5. 镜头语言的写法

| 维度 | 规则 | 例子 |
| --- | --- | --- |
| 景别 | 只用 `SHOT_TYPES` 五档 + 对应短句 | `近景镜头，取人物胸部以上，突出表情与手部动作` |
| 机位 | 只用 `SHOT_ANGLES` 七档 | `斜侧机位，与人物呈 30~45 度角，增加空间纵深`；过肩默认不用（会被画成多一个人） |
| 构图 | 只用 `SHOT_COMPOSITIONS` 六档 | `前景遮挡构图，用门框/器物做前景，形成纵深` |
| 光线 | 只用 `SHOT_LIGHTINGS` 八档，**必须带方向** | `侧光，从画面左侧打来，明暗分界清晰` |
| 竖幅 | 1 句，不写"分镜/格" | `单幅竖向构图，满版出血，一个镜头一层景` |

禁止：同一维度写两句；描述里再写一遍景别；"电影感构图"这种空词单独出现。

## 6. 角色一致性的提示词写法（与 01 文档配套）

1. **身份卡**：≤90 字，跨格逐字复用；
2. **位置绑定**：`左侧是 A` / `右侧是 B`，与 `char_sides` 一致；
3. **人数声明**：`有且只有 N 个人`；
4. **互不重叠**：双人格明确写"左右分开站立，彼此不重叠"；
5. **差异声明**（双人格可选）：`两个人物的发型、服装颜色、身形明显不同`；
6. **不要写**：`与参考图一致`（纯文生图没有参考图）、`第 N 张参考图`（没送图时是噪音）。

> 只有工作流真的支持参考图（`comfyworkflow.supports_reference_images == True`）时，
> 才允许写"第 1 张参考图是叶哥…"。

## 7. 台词与气泡的写法

> **气泡必须在出图时就画进画面**（`IMAGE_DRAW_BUBBLES=True`），
> 程序只负责"找回气泡 + 填字"。所以提示词要把气泡写到**可被检测**的程度：
> 数量、每个气泡的槽位、外接框百分比、宽高、形状、尾巴朝向、内部纯白。

### 7.1 气泡提示词模板（程序拼装，逐条列出）

```
画面中画出 N 个空白对话气泡，只有这 N 个，气泡之间互不重叠、不贴画面边缘；
气泡是纯白底、3 像素黑色描边、内部完整留白不出现任何文字或图案；
每个气泡带一个细小的尾巴，尾巴指向说话人；
气泡落在干净的浅色背景上，位置避开人物脸部与眼睛。
气泡 1：位于左上角，外接框左边缘约 2%、上边缘约 6%、宽约 48%、高约 13%，
        圆角矩形，内部纯白无字，尾巴指向画面左侧的陆鸣；
气泡 2：位于右上角，……
本格气泡总数 N 个，画面里只有这 N 个气泡。
```

规则：
- **数量必须写死**：`N = 台词条数`，并重复一次"只有这 N 个"；
- **坐标必须写**：左/上/宽/高都用画面百分比，和 `bubble_plan` 完全一致；
- **形状必须写**：对白用"圆角矩形/椭圆"，旁白用"方框无尾"；
- **尾巴必须写朝向**：说话人在左 → "尾巴指向画面左侧"；画外音 → "没有尾巴"；
- **内部纯白无字**：避免模型自己写字；同时不要写"不要文字"（D1）；
- **互不重叠 / 不贴边**：这两句能显著减少"多画一个"和"气泡被裁一半"；
- 有旁白的格子：顶部 8% 留给旁白条，气泡从它下方开始；
- 提示词里不写台词内容，只写"这里有一个空白气泡"。

### 7.2 坐标从哪来

1. `bubble.plan_layout()` 按台词长度、说话人站位、旁白高度算出每个气泡的
   `x/y/w/h`（归一化 0~1）与 `slot`；
2. `prompts._bubble_block()` 把这些值格式化成上面的自然语言；
3. 出图后 `bubble.detect_blank_bubbles()` 按同一组坐标做匹配，**不靠猜**。

### 7.3 什么时候用"只预留背景"模式

只有显式设置 `IMAGE_DRAW_BUBBLES=False` 时才走备用模式：提示词不提气泡，
只要求"画面上方 5%~28% 保持干净浅色背景"，气泡由程序画。
这是应急方案，不是默认。

> 为什么不靠"模型自由发挥"：实测模型会多画 1~3 个、画偏、画大。
> 但只要坐标写得足够细、检测按坐标匹配，多画的可以被识别并补成背景，
> 漏画的会被 `bubble_fallback` 捕获并返修（见 04 文档）。

## 8. 质量收尾（只用正面词）

```
画面满版出血到四边，构图完整占满画布，人物比例与透视正确，
背景与人物是同一套画风，整张图是一幅干净的完成稿插画。
```

无角色格换：

```
画面主体是环境、屏幕或桌面上的物件本身，画面里只有物件与它所在的空间；
构图干净，透视正确，背景与整体画风统一。
```

## 9. 反面清单（看到就删）

| 写法 | 问题 |
| --- | --- |
| `不要出现人物` | 把"人物"喂进模型（D1） |
| `不要文字` | 把"文字"喂进模型（D1） |
| `不要分格` | 把"分格"喂进模型（D3） |
| `写实风格 / 照片级 / 3D` | 拉向写实（D4） |
| `【基本形象】【发型与发色】` | 给人看的小标题，模型不解析，白占字数 |
| `与上一格保持一致` | 模型看不到上一格；要写具体特征 |
| `她看起来很悲伤` | 不可画；写"眼眶发红、嘴角向下" |
| `两个人站在一起` | 会被画成重叠/同一张脸；写"左右分开站立，彼此不重叠" |
| `她看向画外的人` | 会把画外的人画进来（D5）；写"看向画面右侧" |
| 同一个风格词出现两遍 | 挤占预算、放大该风格 |

## 10. 提示词组装的自检（出图前）

- [ ] 正向总长度 ≤900 字（handraw 风格块不裁）
- [ ] 正向没有"不要 / 非"（负向词应在 negative 节点）
- [ ] 正向没有"分镜 / 一格 / 漫画格"（分格页用"横向宽幅/竖向长构图/近乎方形"）
- [ ] 风格词/触发块只出现一次，且与当前 handraw 风格一致
- [ ] 单人格里没有"两人/对方/人群/路人/观众/同伴/肩背/半张脸"等召唤词
- [ ] 单人场景已写成"空无一人的…/空置的…/空旷的…"
- [ ] 过肩机位已降成斜侧（单/双人都可能多画一个前景人）
- [ ] 双人 `char_sides` 一左一右，且有两人的具体差异对照
- [ ] 3~4 人写清左/中/右或从左到右顺序，且每人一张独立短卡
- [ ] 3~4 人负向含"第四个人/第五个人"，没有沿用"第三个人"
- [ ] 双人之间写了"留出一臂宽的空隙"；3~4 人写了"半臂宽空隙"
- [ ] 每个出场角色的短身份卡都完整（没有从"眼睛"中间切断）
- [ ] 人数声明与实际 `characters` 数量一致
- [ ] 每个出场角色的身份卡与 `Character.identity_card()` 逐字一致
- [ ] 左右位置与 `char_sides` 一致
- [ ] 没有出现画面外的角色名
- [ ] 程序画气泡时，正向没有"气泡"字样
- [ ] 负向词已按镜头/角色/风格组合，且 `COMFY_CFG>1`

## 11. 负向提示词怎么写

负向词由 `prompts.negative_prompt(project, shot, kind=...)` 生成，分四层：

| 层 | 例子 | 说明 |
| --- | --- | --- |
| 通用低质 | 低质量、模糊、变形、多余手指、水印、签名、乱码文字 | 所有图都加 |
| 眼部/妆容 | 眼影、绿色眼影、眼下绿色、眼周绿色、彩妆、浓妆 | 角色有"青影/眼袋"描述时必加；正向改写为"眼周自然肤色" |
| 镜头/分页 | 多格漫画、分格线、拼图、并排画面、画框、边框 | 只加在分镜格；**姿态总图不加**，否则会把"三角度"压掉 |
| 角色/姿态总图 | 多余人物、额外外套、透明衣物、薄纱、半透明、多余肢体 | 角色图专用 |
| 背面 | 双人、正面人物、镜像、背面换大衣 | 仅背面视图 |
| 风格 | 写实风格压卡通；二次元压照片；3D 压平面简笔 | 按 handraw 风格家族选 |

规则：

- 负向词**不写进正向**；正向只写"要什么"。
- Z-Image-Turbo 官方推荐 cfg=1，此时负向词无效；本项目默认 `COMFY_CFG=1.4`。
- 如果画面过曝/线条变硬，优先把 `COMFY_CFG` 降到 1.2；还不行就回 1.0（负向失效）。
- 工作流必须有 `CLIPTextEncode`（标题「负面提示词」）接到 `KSampler.negative`；
  没有这个节点时，负向词不会进入图。
- 姿态总图/角色主视图的负向词不要用"多格/分镜"；否则模型会把并排三角度当成多格漫画。
