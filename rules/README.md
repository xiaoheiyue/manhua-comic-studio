改规则只改这里，不需要改代码；代码里只保留"怎么执行"，不保留"规则内容"。

## 一、给程序用（运行时会读）

`comicgen/rules.py` 在启动时加载 `data/*.json`，并把内容提供给：

| 规则文件 | 读取方 | 作用 |
| --- | --- | --- |
| `identity_rules.json` | `models.Character.identity_card()`、`pipeline.ensure_character_distinctness()`、`director.validate()` | 生成/校验身份卡，检测角色撞车，追加唯一点缀 |
| `shot_prompt_rules.json` | `prompts.shot_image_prompt()`、`comicgen.castguard` | 决定提示词段落顺序、长度预算、人数/角色/说话人措辞、镜头词表、禁用词替换；人数锁与角色隔离由 `castguard` 执行 |
| `storyboard_rules.json` | `director.normalize()`、`director.validate()`、`bubble.plan_layout()` | 清洗描述、人数政策、气泡锚点与尾巴方向、各类阈值 |
| `storyboard_layouts.json` | `stylelib`、`pagelayout` | 漫画版式目录：每个版式的格数、几何模板、适配度、强项标签 |
| `tones_extended.json` | `stylelib.tone_entries()` | 扩展阶调 T-17–T-40：明暗/反差/氛围/光线/色彩五类，界面可手选 |

- **缺文件不会崩**：`rules.py` 内置同结构缺省值，删掉 JSON 也能跑，只是规则回到默认。
- **改完立即生效**：加载器按文件 mtime 缓存，不需要重启（同一进程内下次读取即生效）。
- **运行期只读**：程序本身不会改写 `rules/`；界面里的「规则与工具」工作台在用户
  主动点击保存时会写回 `rules/`（保存前会自动留一份上次版本备份）。

### 校验规则文件

```powershell
env\Scripts\python.exe -c "from comicgen import rules; print(rules.self_check())"
```

会检查：JSON 能否解析、必需键是否存在、词表是否为空、模板占位符是否完整。

### 把规则应用到已有工程

新流程（一键全流程 / 重新拆解）会自动使用这些规则；**旧工程**需要手动跑一次：

```powershell
env\Scripts\python.exe apply_rules.py <工程id>            # 预览，不写盘
env\Scripts\python.exe apply_rules.py <工程id> --apply    # 写回（自动备份）
```

它会做：导演层整理（描述/站位/气泡/物件格）→ 角色撞车检测与点缀 →
打印自检结果与提示词长度。加 `--rewrite` 才会调用文本模型重写人设，
`--invalidate-images` 会把改过角色的成品图标为待生成。

## 三、维护约定

- **一条规则必须可执行**：要么能写成提示词，要么能写成检查项；写不了的一律删掉。
- **规则要带"反例"**：只说"要具体"没用，要给「反例 → 正例」。
- **阈值只放 JSON**：文档里出现的数字必须和 `data/*.json` 一致，改一处要同步另一处。
- **新增角色特征词**：加到 `identity_rules.json` 的 `trait_patterns`，否则撞车检测认不出来。
- **新增禁用词**：加到 `shot_prompt_rules.json` 的 `forbidden.words` 与 `forbidden.replace`。
- **版本**：每个 JSON 都有 `version`；结构性改动（改键名/删键）请升版本并在本文件记录。

## 四点五、与 prompts/ 的分工

- `rules/` **管"怎么写"**：角色一致性、分镜、气泡、提示词的硬规则；
- `prompts/` **存"实际发了什么"**：
  - 模板/样例：`export_prompts.py` 从代码渲染到 `prompts/<阶段>/`；
  - 运行期：`comicgen/prompt_trace.py` 把每次调用的 system/user、气泡计划与
    检测结果写到 `data/projects/<工程id>/prompts/<阶段>/`。
- 排查顺序：先看 `prompts/07_bubble` 的 plan/debug，再看 `06_image` 的坐标，
  最后回到 `rules/` 判断是规则没写细还是模型没执行。

## 四、和旧配置的关系

- 提示词里的**画风词表、镜头词表、气泡字号/颜色**仍在 `config.py`（它们是"配置"，不是"规则"）。
- 本文档管的是**怎么用这些配置**：顺序、预算、人数、绑定、校验。
- 如果两者冲突，以 `rules/` 为准；`config.py` 里的旧注释会逐步改为指向本目录。
