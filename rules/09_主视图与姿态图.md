## 1. 为什么改成两张图

旧方案的问题：

1. 三视图逐张生成，正面/侧面/背面各画一次，脸、发型、外套容易各变一次；
2. 主视觉又从三视图正面切割重排，跨图漂移被放大；
3. 三视图的三个小人进入分镜参考后，模型会抄成多人构图；
4. 角色 LoRA 在 8GB / 16GB 机器上训不出来，不能作为主路径。

新方案：

| 图 | 用途 | 是否进分镜参考 |
|---|---|---|
| **主视图** | 唯一身份参考：脸、发型、眼睛、服装、身高比例 | ✅ 只用这一张 |
| **姿态总图** | 人工查看多姿态/三视图、姿态库、给用户确认服装 | ❌ 不进分镜（避免抄多人） |

关键点：**姿态总图先生成，主视图从姿态总图中自动找左侧最高人物（正面）裁出**。
两张图必然同一张脸、同一套衣服，不再靠两次生成“碰运气”。

## 2. 生成流程

```text
人设文本
  ↓ 角色特征锁（脸/发/眼/服装/记忆点）
姿态总图（1536×1536，Pose ControlNet，文生图）
  ↓ 自动找正面全身、白底、等比放大
主视图（1024×1536）
  ↓
分镜提示词：character_feature_lock + 场景/镜头
```

- 姿态总图：`image_z_image_turbo_int8_character_pose.json`
- 主视图：从 `姿态图.png` 裁出，不再单独跑一次文生图
- 分镜：默认基础工作流；不再把姿态总图当参考图送进去

## 3. 工作流与参数

文件：

```text
comfy_workflows/image_z_image_turbo_int8_character_pose.json
```

节点：

```text
UNETLoader(z_image_turbo_int8_convrot)
  → ModelSamplingAuraFlow(shift=3)
  → QwenImageDiffsynthControlnet(model_patch=Z-Image ControlNet 2.1 lite)
  → KSampler(8 steps, cfg=1.4, res_multistep, simple)
  ← TextEncodeZImageOmni（无参考图时等价于文本编码）
  ← LoadImage(pose_sheet.png) + ImageScale(1536×1536)
```

参数：

| 项 | 值 | 说明 |
|---|---|---|
| 尺寸 | 1536×1536 | 8GB 实测可跑；再大速度明显变慢 |
| steps | 8 | Z-Image-Turbo 蒸馏步数 |
| cfg | 1.4 | 让负面词生效，又不至于过曝 |
| ControlNet | 2.1 lite 2601 8steps | 1.88GB，8GB 友好 |
| strength | 0.85 | 低于 0.8 容易只画站姿；0.95 在横格会放大骨架线条 |
| 采样器 | res_multistep / simple | 与现有风格链一致 |

> **不要**把主视图或角色参考图接进这个工作流的 Omni/ReferenceLatent：
> ControlNet 的 model patch 与 reference latent 的 batch 维度不一致，
> 会报 `output with shape [1, ...] does not match broadcast shape [2, ...]`。
> 身份靠 `character_feature_lock` 提示词锁，姿态靠 ControlNet。

## 4. 提示词锁

主视图和姿态总图共用一个身份锁：

```text
【身份锁定】角色：林晚；脸型：瘦长脸；
发型：及肩黑发低马尾，全部头发向后收进发髻，额前与鬓角干净，不散发；
眼睛：细长上挑杏眼；双眼大小一致、瞳孔居中、看向同一方向；
服装：炭黑高领针织衫、冷灰蓝长款风衣、深灰直筒长裤、旧皮短靴；
记忆点：左耳枯叶形旧银耳夹。
```

- 发型必须写“全部收进/额前干净”，不能只写“低马尾”；
- 眼睛必须写“双眼对称/瞳孔居中”；
- 服装只保留一件外层，负向词压掉第二件外套、透明衣料；
- 主视图、姿态图、分镜三处逐字复用，不允许每格重写。

## 5. 自定义姿态

支持两种输入：

1. **黑底彩色骨架图**：直接作为 ControlNet 输入；
2. **真人全身/半身照片**：`comicgen/poseutil.py` 用 MediaPipe 提取 33 个关键点，
   画成 OpenPose 风格骨架后再送 ControlNet。

界面入口：

- 阶段 3 角色卡：`上传自定义姿态` → 角色姿态总图使用该骨架；
- 阶段 5 分镜预览：`上传本格姿态` → 这一格用 Pose ControlNet 出图。

接口：

```text
POST /api/character/pose-upload   (id, convert, file)
POST /api/character/pose-clear
POST /api/shot/pose-upload        (shot_id, convert, file)
POST /api/shot/pose-clear
```

数据字段：

```text
Character.pose_source   自定义角色骨架
Character.pose_sheet    生成出的姿态总图
Shot.pose_image         本格骨架
```

## 6. 参考骨架库

`data/pose_library/`：

- `multi_actions.png`：原多姿态动作骨架；
- `front_side_back_actions.png`：正面/侧面/背面 + 动作；
- `views/`：从参考资料整理的全身正面/侧面/背面、半身、过肩、特写骨架。
  **注意：多数是从参考图裁出来的"无头骨架"，`validate_pose()` 会拒绝；
  当前只作为人工参考，不自动挂进分镜。**

参考来源：`参考资料/03.17-自定义人物姿势动作`、
`参考资料/2026.03.21人物一致性/骨架图`。

## 7. 与参考资料的关系

详见 [参考工作流分析](参考工作流分析.md)。采纳的核心只有三条：

1. 姿态控制用 ControlNet + 骨架，不靠文字描述动作；
2. 先用一张总图统一角色，再裁参考，不做多次独立生成；
3. 不把 LoRA 作为 8GB 主路径。

未采纳：Qwen Image Edit 多图参考（需要另一套编辑模型/权重）、
Flux Redux/ICEdit（与 Z-Image 不兼容）、Krea2 4K（需要另一套底模）。



## 8. 俯视图（真实顶视）说明

“正面/侧面/背面”之外还需要一个 **正上方俯视头顶** 的参考，否则看不到发旋、发缝、发髻/马尾在头顶的形状。

但当前 **Z-Image-Turbo + 8GB** 实测：

- 文生图写“正上方俯视”会退化成正面或后脑勺；
- Pose ControlNet 的顶视骨架也会被模型解释成正面；
- img2img 从主视图改机位会把头裁掉。

所以当前 **不自动伪造俯视图**（`CHARACTER_TOP_AUTO=False`），只接受：

1. 真实俯视照片（相机在头顶正上方）；
2. 3D 渲染的顶视；
3. 画师画的顶视参考。

界面入口：阶段 3 角色卡「上传俯视参考」。字段 `Character.top_view`，只做查看/参考，不进分镜参考。

要自动生成真正的顶视，需要 3D/多视角编辑模型（Qwen Image Edit、Trellis 等），不是 8GB Z-Image 能稳定做到的。


## 9. 分镜动作 → 姿态

分镜 schema 新增 `character_actions`（每个可见角色一个动作短语）；`Shot.character_actions` 保存后，出图前由 `comicgen/poseplan.py` 映射骨架：

- 跑/冲 → `actions/action_01.png`
- 跳/踢 → `actions/action_02.png`
- 坐/蹲 → `actions/action_03.png`
- 挥手/推/伸/抓 → `actions/action_04.png`（**已停用**，见下）
- 走/转身 → `actions/action_06.png`
- 过肩 → `views/12/13...`（**默认不用**：单/双人都可能多画一个前景人；castguard 一律降斜侧，且这些骨架缺头部关键点，`validate_pose` 会拒绝）
- 特写/近景 → `views/10/5...`
- 俯视 → **不自动挂骨架**（Z-Image 顶视不稳定，需上传真实俯视参考）

> **2026-10 修正：姿态库先自检，再出图。**
>
> 旧版 `actions/action_04.png` 里叠着**两个头**，而 `choose_pose` 只要文本里
> 出现单字"打"就会挂它（"货梯门**打**开"也中招）。结果单人全景被 ControlNet
> 强行画出"前后两张脸"——这是单人乱入最隐蔽的根因。
>
> 现在 `poseplan.validate_pose()` 做两道检查：
> 1. 已知坏图名单（`action_04.png`）直接拒绝；
> 2. 画面上方 32% 必须有一簇近白色头部关键点；`views/` 里大量从参考图裁出来的
>    "无头骨架"会被拒绝，避免把脸画到画布顶上。
>
> 动作词也改成上下文匹配：`打开/走廊/冲突` 不再误触发
> `打/走/冲` 骨架。选不到有效骨架时**宁可不挂**，让提示词接管，
> 也不要用一张坏骨架去"控制"构图。
>
> 新增骨架前先跑：
>
> ```python
> from comicgen.poseplan import validate_pose
> print(validate_pose("data/pose_library/actions/action_05.png"))
> ```

开关：`AUTO_POSE_SHOTS = off / key / all`。**默认 `off`（2026-11-04）**：
内置骨架缺少肩→髋躯干段，挂到 Qwen ControlNet 会出“无头长衫 / 头在胸口”；
需要锁动作时在第 7 步上传自定义姿态，上传图会等比补边后送 ControlNet。
