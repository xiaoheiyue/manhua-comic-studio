## 2. 发现的问题与修复

### 2.1 表情包无参考图：每格两个角色、九格同一姿势

**现象**：3×3 橘猫表情包，每格出现“一个高个狐狸人 + 一只小橘猫”，
九格的站姿几乎完全一样，表情变化很小。

**根因**：

1. `emoji` 的负向词里写了 `单个人物, 只有一张脸`。这是在告诉模型
   “不要只画一个人”，等于鼓励每格补第二个角色；
2. 无参考图时让 Qwen 一次直出 3×3，模型倾向复制同一张站姿，而不是真的画九种动作；
3. 无参考图路径完全没有走 `_generate_emoji_reference_grid`，所以程序叠字也没生效。

**修复**（`comicgen/studio.py`）：

- 负向改为 `每格两个角色, 每格多个人物, 九宫格重复, 同一姿势重复, 角色复制`；
- 新增 `_generate_emoji_topic_base()`：先按主题生成一张单人 chibi 母本；
- 无参考图时自动把母本当作参考，逐格 Qwen Edit 生成 9 个表情/动作，再拼网格、叠短句；
- 缓存版本升到 `20261104-emoji-base-v4`，避免命中旧结果。

结果：9 格是同一只橘猫，每格一个角色，表情/动作/文字不同。

### 2.2 IP/头像：模型写出一堆伪汉字

**现象**：IP 设定卡上出现“慰息之麓枫”“Phty……”等伪中文/伪英文，
版式里的名称、标签、受众说明全被模型写成乱码。

**根因**：IP 模式没有加入 `overlay`（程序叠字）名单，`IP-001` 版式提示词
又把“IP名称/定位/标签/受众”直接送进 T2I；模型不会写这些字，只能编。

**修复**：

- `overlay` 加入 `ip`，提示词明确“画面不要写任何文字”；
- IP 不再套用 `IP-001` 的文字版式，改用固定角色设定版式：
  中间全身主形象 + 侧面/背面小图 + 底部 3–4 个表情；
- 标题由程序叠加（有 title 时）。

结果：正/侧/背 + 3 表情，画面干净，无伪汉字。

### 2.3 电商图：商品被画风替换成早茶点心

**现象**：主题“手工柴烧陶杯”，FE-053 是广式早茶风格，输出变成
“陶杯 + 蒸笼 + 虾饺”的早茶场景，商品不再是唯一主体。

**根因**：风格块先写、主题后写，且没有“商品主体优先”约束；
FE-053 的“点心/蒸笼/早茶”先验覆盖了商品。

**修复**：

- 新增 `_SUBJECT_LOCK`：主题中的主体、地点、时代、关键道具必须出现，
  画风只作用于线条/笔触/材质/配色；
- 非编译模式改为**主题/媒介先写、画风后写**；
- 电商图明确“商品不能替换成风格里的其他食物/道具”。

结果：单只柴烧陶杯 + 木托 + 干净背景，标题程序叠加。

### 2.4 插画/封面：雨夜旧书店被画成古装仕女

**现象**：主题“雨夜旧书店的窗边，暖黄台灯下摊开的书”，
FE-034 输出古装女子在绿色室内读书，没有雨、没有旧书店。

**根因**：同 2.3，画风块在前，FE-034 的“古典服饰/古建筑”先验过强；
`_SUBJECT_LOCK` 不够具体。

**修复**：

- 主题先写、画风后写；
- 增加 `_ILLUSTRATION_LOCK`：主题写雨夜就画雨夜，写旧书店就画旧书店，
  写现代就画现代，不要替换成古装/古代室内/风格库常见题材。

结果：雨夜、窗、暖黄台灯、摊开的旧书都出现；人物仍保留 FE-034 的古风笔触，
这是画风与主题的折中，不再完全跑题。

### 2.5 信息图：rewrite off 只剩标题；底图出现淡色人物/动物

**现象 A**：关闭“LLM 改写”后，信息图只有标题，节点卡片全空。
**根因**：`build_prompt()` 只在 `compiled` 存在时生成排版计划；
rewrite off 时 `compiled` 为空，`infographic_plan` 也是空。

**修复**：rewrite off 时用 `prompt_rewriter._fallback()` 生成
本地节点/要点计划，保证程序仍能排版。

**现象 B**：底图上铺了一层淡色人物、动物、走路循环涂鸦，叠卡片后成脏底。
**根因**：完整 `style_prompt_block` 带有“圆头人物/简单动物/社论角色”等正向词；
只写“只保留纸张质感”压不住。

**修复**：

- 信息图改用 `_info_style_block()`：只取纸/墨/配色，不取风格里的人物动物；
- 追加 `_INFO_BG_LOCK`：画面里没有任何人物、动物、脸、手、图标、图案；
- 信息图不再套用 `IG-*` 的“金字塔/图标/标签”版式提示词，结构全部由程序画；
- 负向增加人物/动物/图标/图案。

**现象 C**：`主题：步骤1、步骤2` 的冒号没被切开，第一个节点变成整句主题。
**修复**：`_split_topic()` 支持全角/半角冒号；信息图兜底时冒号前作为主题名，
冒号后的步骤才作为节点。

**现象 D**：3 个节点时卡片拉满整页，中间大片空白。
**修复**：卡片高度上限 0.18h，从标题下方开始排；卡片右侧加很淡的
`01/02/03` 步骤大字，空卡片不再像空模板。

结果：干净纸底 + 3 个正确节点 + 关系行 + 步骤大字。

### 2.6 参考图生成：输出不按目标画幅

**现象**：非表情包的参考图路径把 `size=max(meta["size"])` 传给 Qwen Edit，
只是一个 int，不是 `(w,h)`；Qwen 会把参考图比例当成输出比例，
海报/电商图可能被拉成方图或竖图。

**修复**：改为 `size=tuple(meta["size"])`，先 pad 参考图到目标画幅再 Edit。

### 2.7 无参考图时提示词仍写“第1张参考图”

**现象**：没有参考图，提示词却写“第1张参考图只用于参考画风”，
Qwen 会以为真有一张图可看，表情包里甚至补出第二个角色。

**修复**：`include_reference_note=has_ref`，只有实际传入参考图时才写这段。

### 2.8 社媒/信息图/电商的“画文字”和“不要文字”互相打架

**现象**：rewrite off 时，模式指令写“文字可读、排版整齐”，
后面程序叠字又写“画面不要任何文字”。

**修复**：模式指令统一改成“留出文字面板/留白，画面本身不要写字”；
信息图明确只画底图。

## 5. 边界与未覆盖

- 表情包 4×4 未单独跑（代码与 3×3 共用逐格路径，耗时约 2 倍）；
- 参考图 + 信息图按设计会忽略参考图（只取配色），未做视觉对比；
- 社媒/电商/IP 的参考图模式未逐一跑，只跑了海报参考图；
- Qwen 仍可能写错画面内的精确文字（如石碣、招牌）；这类文字应像气泡一样
  由程序叠加，或让模型只画无字道具；
- 8GB 下 Qwen Edit 参考图约 2–3 分钟/张，逐格表情包约 5 分钟/9 格。
