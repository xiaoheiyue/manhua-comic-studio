## 二、已确认的根因与修复

### 1. 页面选了 Qwen，漫画实际还在用 Z-Image

根因：`server.py` 的 `STATE.pipeline()` 写死：

```python
image_client=ImageClient()
```

修复：

```python
qwen → QwenComicClient
zimage → ImageClient
```

影响：这是男女漂移、角色脸不对的最大原因之一。

### 2. 无参考图分镜 12/18 失败

报错：

```text
name 'names' is not defined
```

根因：Qwen T2I / ControlNet 里残留了参考图节点的变量。

修复：删除 T2I / ControlNet 图里的 `names` 残留；最终 18/18 成功。

### 3. 25 格分镜出现空白气泡

根因：`build_shot_prompt(include_bubbles=False)` 内部没有真正关掉气泡，仍按 `IMAGE_DRAW_BUBBLES=True` 画空白气泡。

修复：

```python
build_shot_prompt(..., draw_bubbles=False)
```

并且 25 格优先复用镜头的无气泡原图。

规则：

```text
25 格是分镜附图，不是成品页
不画对话框、气泡、文字、字幕、漫画框
```

### 4. 短篇不足 25 格

18 格项目只拼出 18 格。

修复：

```python
key_shots 不足 25 时循环补足
```

### 5. 单人格被画成两个人

根因分镜文字前后矛盾：

```text
单人反应镜头：陆鸣
两人站门外不动
```

模型会按“两人”画出第二个人。

修复：单人格提示词清洗。

```text
其他角色名 → 画外
两人/二人/他们/她们/对方/双人 → 她/他
```

同时追加：

```text
本格只能有一个人：不要第二个人、镜像、倒影、分屏、复制人物。
```

## 三、仍然存在的问题

### 1. 单人格仍可能复制脸/头

第 8 格清洗后仍然出现“两个人脸叠在一起”。  
原因不是文字，而是 Qwen 在低照度、半身构图下的 latent 复制。

处理建议：

- 单人镜头尽量用中景/近景，避免大面积暗部+半身；
- 出图后做人物检测/人脸数量自检；
- 不合格就重绘，不要靠提示词硬压。

### 2. 页面留白

第 3、4 页有较大留白，原因是分格画幅和版式不一致。

处理建议：

- 页面版式按实际画幅重新选；
- 不要让竖图硬塞进横格；
- 重绘后重拼页。

### 3. 25 格本次仍只有 18 个

测试项目只有 18 格，旧图没有重新生成。  
补 25 格的代码已加，下次重新生成即可满 5×5。

## 四、下次写分镜提示词的硬规则

### 1. 单人格

禁止出现：

```text
两人、二人、他们、她们、对方、双人
```

禁止出现其他角色名。

正确写法：

```text
本格只有陆鸣一个人。
陆鸣站在门外，高星在画外。
```

不要写：

```text
两人站门外不动，高星抬手示意。
```

### 2. 多人物

必须拆成单人格，或在 `char_sides` / `characters` 里明确两个人。

不要让“单人反应镜头”里出现“两人”。

### 3. 25 格

```text
不画气泡
不画文字
不画字幕
不画漫画框
```

提示词尾部固定加：

```text
这是 25 格分镜附图，不是成品页：画面中不得出现任何对话框、气泡、文字、字幕、漫画框、分格线。
```

### 4. 最终分镜

```text
画面不要写字
气泡和文字最后程序叠加
```

不要指望模型写对中文对白。

### 5. 画幅

- 竖格用竖图；
- 横格用横图；
- 页面版式按格子比例选；
- 不要用同一张竖图硬塞所有版式。

## 五、出图前检查清单

```text
[ ] 服务端是否真的在用 Qwen（不是 ImageClient 默认）
[ ] 单人格描述里有没有“两人/他们/对方/其他角色名”
[ ] 25 格是否 draw_bubbles=False
[ ] 25 格是否不足 25，是否需要循环补足
[ ] 最终页是否由程序叠加文字
[ ] 画幅与版式是否匹配
[ ] 出图后是否检查人数/人脸数量
```

## 七、针对“多人撞脸 / 单人乱入”的已落地改动

### 单人

1. 分镜文本清洗：

```text
其他角色名 → 画外
两人/二人/他们/她们/对方/双人 → 她/他
```

2. 描述首句强制：

```text
画面里只有{角色}一个人，场景空无一人，没有路人、第二个人、镜像倒影。
```

3. 提示词尾部：

```text
single subject only, no duplicates, no background crowd, no mirror reflection
```

4. 单人全景/远景强制挂单骨架，走 Qwen ControlNet，不送角色参考图。

5. 负向词增加：

```text
人群、围观者、路人、背景人物、克隆脸、双胞胎、重复人物、
镜像、倒影、画面分割、两张脸、融合脸、服装互换
```

### 多人

1. 首句锁定人数：

```text
画面里恰好有 N 个人物，各自独立，不融合、不互换、不克隆。
```

2. 每个角色的完整外观块分开写，再写位置和视线。

3. 负向词同样禁止融合/互换/克隆。

### 实测结果

- 第 11 格：从“两个陆鸣”变成“单个陆鸣”，修复成功；
- 第 8 格：仍然是两张脸叠在一起，没有完全解决；
- 原因：Qwen 在暗部、半身、低对比构图下会复制面部 latent，单纯提示词压不住；
- 追加的 OpenCV Haar 人脸检测对二次元脸不稳定，不能可靠触发裁切。

### 结论

提示词能解决“文字里写了两人”的单人乱入，不能完全解决模型 latent 复制。  
要彻底解决，需要：

```text
区域条件（Regional / Conditioning SetArea）
或角色分区 + 合成
或换更擅长多人分离的底模
```

本项目当前 Qwen 工作流没有原生的区域条件节点，所以单靠提示词只能做到“明显减少”，不能保证 100%。

## 八、2026-11-04：最终分镜结构崩坏的根因与修复

最终分镜出现“无头长衫 / 头在胸口 / 背后巨人”，不是提示词问题，是
**自动姿态骨架**问题。25 格一直是纯 T2I，不挂骨架，所以同一提示词正常。

- 内置 `data/pose_library/views/1全身正面.png` 等骨架没有肩→髋躯干段；
- 9 个镜头复用的是同一个骨架（SHA-256 相同）；
- 竖骨架送进 1280×1024 横格时被 `ImageScale(crop="center")` 裁掉头脚；
- Qwen `cfg=1.0`，负面提示词不参与计算，压不住结构错误。

修复：

```text
Qwen T2I 最终分镜：不挂任何自动骨架（与 25 格同路径）
用户上传姿态：保留，且改为等比补黑边，不裁头脚
AUTO_POSE_SHOTS 默认 off
```

详见 [最终分镜人体结构修复](最终分镜人体结构修复.md)。
