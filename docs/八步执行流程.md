# 八步执行流程

## 1. 输入文本
- 小说原文

## 2. 小说精修与连续故事板
- 一句话核心戏剧任务 + 结构化摘要（主角/目标/阻碍/转折/落点/基调/母题）
- 8–12 个视觉锚点（人物+动作+环境+情绪+原文依据）
- 扩展为 25 格连续故事板（每格：景别/主体动作/环境/光线/情绪/叙事功能/人物/道具/原文依据）
- 只产出文本，不画图；落盘到 `Project.core_task / refine_digest / visual_anchors / continuous_cells`
- 提示词回溯：`data/projects/<id>/prompts/02_refine/`
- **界面可直接编辑**：核心任务、结构化摘要、每个锚点、每个镜头格都可改；
  锚点/镜头格可单独删除，也可一键删除全部精修；保存后自动重建
  `continuous_storyboard`，状态变为「已修改」。

### 长文本策略

| 原文长度 | 做法 |
|---|---|
| ≤ `NOVEL_REFINE_WHOLE_CHARS`（默认 14000 字） | 整章一次送入，保证 25 格节奏与人物连续 |
| > 阈值 | 按场景边界切成 `NOVEL_REFINE_CHUNK_SIZE`（默认 7000 字）的段，逐段提取候选锚点/候选格，再用 `novel_refine_merge_prompt` 压成 8–12 锚点 + 恰好 25 格 |

分段时会把上一段的 `core_task + 转折 + 锚点事件`作为“前文摘要”传给下一段，
只用于保持人名/地点/时间连续，不重复提取。合并失败时走本地兜底
`Pipeline._local_refine_merge()`，不会让整步失败。

## 3. 内容分析
- 角色、场景、剧情、画风

## 4. 角色主视图 + 三视图 + 俯视图
- 主视图：唯一身份参考
- 三视图：正面 / 侧面 / 背面（单独文件；正面=主视图）
- 俯视图：上传参考 → 自动提取骨架 → ControlNet 生成；不再是“直接套一张默认图”
- **这一步不再生成姿态图**

## 5. 分镜拆解（文字镜头表）
- 每个关键镜头写清：
  - 景别 / 机位
  - 角色动作 `character_actions`
  - 场景 / 光线 / 道具
- 这一步还没有图

## 6. 25 格分镜图（纯 T2I）
- 用 25 个关键镜头生成 5×5 分镜结果
- 每格出图 = 角色主视图参考 + 本格分镜提示词（Qwen T2I）
- **不挂自动姿态骨架**（`AUTO_POSE_SHOTS=off`）；
  内置骨架没有肩→髋躯干段，挂上会出“无头长衫 / 头在胸口”
- 每格是**场景镜头**，不是姿态图
- 用于看节奏、机位、角色站位
- 低分辨率，不作最终页

## 7. 姿态图（只给关键动作镜头）
- 自动姿态默认关闭；需要锁动作时，在第 7 步**上传姿态图**
- 上传图会先转 OpenPose 骨架，再按骨架生成；送进 ControlNet 前等比补黑边，不裁头脚
- 静态对白、反应、纯道具、特写镜头不挂全身骨架
- 只对上传姿态的那一格生效，不会批量套到所有镜头

## 8. 最终漫画出图
- 逐格：身份锁 + 场景 + 画风（Qwen T2I，与 25 格同一条路径）
- 只有用户上传姿态的格子才走 ControlNet
- 拼页 / 气泡 / 自检 / 导出
