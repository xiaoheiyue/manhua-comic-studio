## 3. 项目结构与运行方式

### 3.1 启动

```powershell
# 项目自带虚拟环境
env\Scripts\python.exe server.py
# 浏览器访问 http://127.0.0.1:7870/
```

本次检测开始时 7870 端口已有实例在运行（PID 30888），为避免重复起服务，直接复用该实例；ComfyUI 在 13:46 左右自动启动，8188 端口恢复在线。

### 3.2 关键模块

| 路径 | 作用 |
| --- | --- |
| `server.py` | FastAPI 后端，81 个路由，负责工程、分析、角色、分镜、出图、气泡、导出、工坊 |
| `web/index.html` + `app.js` + `style.css` | 原生前端，无构建步骤；11 个一级导航 |
| `comicgen/pipeline.py` | 主流水线：分析、角色、分镜、分页、出图、导出 |
| `comicgen/textclient.py` | DeepSeek 客户端 + 演示模式 `DemoTextClient` |
| `comicgen/imageclient.py` | ComfyUI 客户端 + `DemoImageGenerator` |
| `comicgen/pagelayout.py` | 分页、版式打分/动态规划、页面合成 |
| `comicgen/bubble.py` | 气泡计划、空白气泡检测、旁白条、填字 |
| `comicgen/director.py` | 镜头字段兜底、节奏/轴线/气泡槽位、自检 |
| `comicgen/studio.py` | 创作工坊（海报/社媒/信息图/表情包/插画/IP/电商） |

| `data/` | 工程、角色图、分镜图、页图、缓存、日志 |
| `outputs/` | 最终产物与自检输出 |

### 3.3 运行模式

- **真实模式**：DeepSeek 做分析/人设/分镜/导演，本地 ComfyUI 出图。
- **演示模式**：`DemoTextClient` + `DemoImageGenerator`，不联网、用规则和程序化绘图跑通主链路。
- 两个模式可在请求里用 `demo` 参数切换；服务端 `STATE.pipeline(demo)` 会切换整套客户端。

## 5. 实测过程与结果

### 5.1 文本输入与编码

| 测试 | 输入 | 结果 |
| --- | --- | --- |
| UTF-8 带 BOM | 46 字测试文本 | 200，识别 `utf-8-sig`，3 行，0 个替换字符 |
| GBK | 同文本 GBK 编码 | 200，识别 `gb18030`，46 字，0 个替换字符 |
| 非法扩展名 | `.pdf` | 400，“仅支持文本格式文件” |
| 空文本分析 | `text=""` | 400，“请先输入或上传小说文本” |
| 过短文本 | `text="太短"` | 400，同上 |

结论：编码识别、空值/类型校验正常；上传接口会保留原始文件到 `data/uploads/`。

### 5.2 小说精修（第 2 步）

**真实模式（全文 2631 字）**

- 耗时：**16.1 秒**
- 结果：11 个视觉锚点 / 25 格连续故事板
- 核心戏剧任务示例：孔乙己想维持读书人的体面，却因偷窃被打断腿，最后在笑声中用手走来喝完酒、欠账消失。
- 落盘：`Project.core_task / visual_anchors / continuous_cells`
- 副作用：按设计清空旧分镜、旧页、旧 25 格，`refine_status=已完成`。

**演示模式**

- 同一操作返回 `refine_status=失败`，`anchors=0`，`cells=0`，job 消息为“精修完成：0 锚点 / 0 格”。
- 原因定位：`DemoTextClient.chat_json()` 没有“精修/连续故事板”分支，落到 `_analyze()`，返回的是分析 JSON，没有 `core_task/anchors/cells`。
- 影响：README 说的“演示模式跑通全部阶段”在 8 步流程的第 2 步断了；演示用户必须先跳过精修才能继续。

> 这是一个确定的**功能缺口**，不是环境问题。

### 5.3 内容分析（第 3 步）

**全文真实分析**（12.1 秒）：

- 9 个角色：丁举人、孔乙己、小伙计、掌柜、邻舍孩子、酒客乙、酒客甲、短衣帮顾客、长衫主顾。
- 3 个场景：咸亨酒店柜台、酒店隔壁房间、鲁镇街道。
- 推荐画风：`FE-061 当代人文水墨漫画风`，主题色 `佩恩灰 + 赭石`，阶调“中间调”。
- 梗概/情节线/关键点都能准确概括原文，质量明显高于演示模式。

发现的两个数据问题：

1. 角色顺序把“丁举人”排在第一位（未出场人物），但 `director` 会按 `role` 里的“主角”找孔乙己，所以没有把丁举人误当主角；不过角色表默认顺序对用户不友好。
2. 角色“我/酒客甲/酒客乙/短衣帮/长衫主顾”没有生成人设，后续提示词里没有身份卡；自检会报 `character_no_card`。

**演示模式分析**（同一全文）：只识别出 1 个角色“孔乙己”，场景抽成“演绎国内/柜里/靠柜外/的房子里/亨酒店里”等噪声。演示模式只适合跑通链路，不适合看质量。

### 5.4 角色人设与参考图（第 4 步）

对节选工程保留 2 个主要角色（孔乙己、掌柜）生成参考图，每个角色 3 张：

- 姿态总图（1536×1536，Pose ControlNet）
- 主视图（1024×1536）
- 三视图（正面/侧面/背面）

实测：

- 2 个角色 × 3 张图约 **5 分钟**（Qwen，含模型加载）。
- 主视图质量可用：孔乙己的破长衫、补丁、草绳腰带、旧布鞋都出来了；掌柜的短打、围裙、粉板也符合时代。
- 但**身份卡约束不稳定**：孔乙己人设写“花白稀疏短发”，主视图仍是黑发；年龄看起来像 20 多岁，不是 40 岁上下。
- 三视图与主视图的脸/发型有轻微漂移；掌柜在三视图、主视图、分镜里的体型/脸型差异明显。
- 俯视图上传/清除、本格姿态上传/清除、道具上传/清除都验证通过（道具上传会走 BiRefNet 去背景）。

### 5.5 分镜拆解与版式（第 5 步）

**全文真实分镜**：

- 耗时 **54.3 秒**
- 输出 **37 格 / 10 页**，26 条台词
- 景别分布：中景 16、近景 10、全景 8、远景 2、特写 1
- beat 分布：对白 12、动作 6、反应 5、日常 4、情绪 3、转场 3…
- 页面：SB-001 / SB-003 / SB-009 等，4 格一页为主。

**质量观察**：

- 结构成立：开场建立柜台 → 孔乙己出场 → 窃书争辩 → 教写茴字 → 分豆 → 中秋转折 → 断腿后最后一次喝酒 → 留白结尾。
- 但描述里大量出现“画面外的方向”这种占位式表达，例如“酒客甲指着画面外的方向脸上的伤疤叫嚷”，语义不通，出图时容易生成奇怪构图。
- 第 37 格是“空荡荡的咸亨酒店柜台”，却被自动补主角逻辑改成“空荡荡的……孔乙己是画面主体”，文本自相矛盾。
- 第 9 格（节选工程）出现两条完全相同的“孔乙己还欠十九个钱呢！”，生成后叠了两个同样的气泡；本次已通过 `/api/storyboard/save` 手动删掉一条并重生成修复。
- 第 8 格（节选工程）3 人同框、3 条台词；自检已提示“三人以上同框且有 2 条以上台词”，但没有自动拆格。

**版式规划**：

- AI 版式方案多次被程序判为不合法（“SB-003 需要 4 格，给了 3 格”“SB-005 需要 3 格，给了 2 格”），自动退回本地动态规划；这是设计好的兜底，不是崩溃。
- 本地规划选中 SB-009 作为第 2 页，合成后页面下半部出现大面积空白（详见 P2-3）；手动换成 SB-001 后页面利用率明显提升。

### 5.6 25 格分镜与姿态图（第 6/7 步）

**25 格分镜**：

- 节选工程 9 格全部有关键镜头，最终生成 **9/25 格**，其余 16 格为“无更多关键镜头”占位格，符合“不重复伪造”的设计。
- 真实出图耗时 **102.5 秒**；演示模式同一操作 **2.0 秒**。
- 结果图 `25宫格_分镜结果.png` 为 2560×2560，9 格真实画面 + 16 格占位，能用于节奏检查。

**姿态图**：

- 为 9 格关键镜头生成/跳过：4 格生成骨架，5 格按规则跳过（多人物镜头、特写/近景、无人物）。
- 但 4 张骨架全部是同一张“全身正面”兜底图，原因字段都写“正面兜底”；说明 `poseplan.choose_pose` 没有匹配到动态姿势库，姿态引导的差异化不足。

### 5.7 出图、气泡与自检（第 8 步）

**节选工程一键全流程**：

- 总耗时 **587 秒（9 分 47 秒）**
- 9/9 格完成，自检分 100、100、100、100、100、92、100、100、100
- 第 6 格 92 分，问题 `no_reference`（该格角色“我”没有参考图）
- 第 4 格尝试 2 次（本次检测中手动单格重做 1 次），最终 100 分
- 第 9 格尝试 3 次（修重复台词后重生成 2 次），最终 100 分
- 本次 9 格没有观察到 `IMAGE_AUTO_REPAIR` 真正触发重画；日志里没有“返修/自动重画”记录，自检主要起到评分和拦截作用
- 每格耗时约 20–26 秒；单格重做首次 24.1 秒，模型热缓存后 6.0 秒

**画面质量**：

- 整体水墨风格统一，纸面留白、墨线、暖色火光都成立。
- 第 2 格（孔乙己坐在门槛下）质量最好：老人、破衣、草绳、蒲包、仰头要酒，和原文高度贴合。
- 第 3 格（掌柜探身要账）构图、气泡、表情都不错。
- 第 1 格（我 + 掌柜）两个人物脸型过于相似，且都把“我”画成了成年男性；原文“我”是十二岁的小伙计。
- 第 5 格故事板只写“酒客们 + 掌柜”，模型自行补成了 4 个人（3 酒客 + 掌柜），属于 README 已承认的“背景自行加人”问题。
- 掌柜跨格一致性弱：第 1 格瘦削年轻、第 3 格圆脸中年、第 5 格胖脸大笑，像三个不同的人。

**气泡**：

- `/api/bubble/layout`、`/api/bubble/preview`、`/api/bubble/auto`、`/api/bubble/save` 均验证通过。
- 预览能把气泡移动到指定坐标并重绘；保存会重绘成品图。
- 第 1 格是“旁白条 + 画外音”，气泡编辑器提示“该分镜没有对话气泡”，无法编辑旁白文字；用户只能改分镜文本后重生成。画面里两条不同来源的文字还被合并进同一个旁白框，见 P2-12。
- 质量报告里所有格子的 `expected/detected` 都是 0，即使画面里实际有气泡；这是统计口径问题（程序画气泡不计入模型气泡检测），会让“气泡质量报告”看起来像没检查。

## 8. 发现的问题清单

### 8.1 P1（影响主流程/交付质量，建议先修）

**P1-1 演示模式无法完成“小说精修”**

- 现象：`/api/refine/start` + `demo=true` → `refine_status=失败`，`anchors=0`，`cells=0`，job 仍显示 done。
- 证据：`outputs/_e2e_refine_demo.json`；服务端消息“精修完成：0 锚点 / 0 格”。
- 根因：`DemoTextClient.chat_json()` 没有精修分支，落到通用 `_analyze()`。
- 影响：演示模式无法完整走 8 步流程；新用户会以为系统坏了。
- 建议：为 `DemoTextClient` 增加 `novel_refine` 分支（按段落切 8–12 锚点 + 25 格模板），或在演示模式隐藏/跳过精修并明确提示。

**P1-2 角色跨格一致性弱**

- 现象：掌柜在 3 个画面里像 3 个人；孔乙己人设“花白短发/40 岁”，主视图仍是黑发青年；“我”被画成成年男性。
- 证据：`outputs/孔乙己_最后的酒_交付版/05_分镜图/页面/页_001.png`、`页_002.png`；`data/characters/孔乙己/默认造型/主视图.png`。
- 影响：读者会认错人，长故事更明显。
- 说明：README 已承认“不能稳定保持同一张脸”，属于已知能力边界；但本次仍建议在默认提示词/参考通道上继续收敛。

**P1-3 敏感信息硬编码**

- `config.py` 顶部直接写有 DeepSeek API Key。
- 影响：一旦把目录打包/上传/发给别人，密钥即泄露。
- 建议：改为环境变量或 `.env`，至少在 README 和 `.gitignore` 中明确提醒；本次报告不复述密钥内容。

### 8.2 P2（功能缺陷/体验问题）

**P2-1 取消生成后任务状态仍是 done**

- 现象：9 格工程取消后，job `state=done`，消息“生成完成：2/14”。
- 影响：前端/外部调用无法区分“完成”和“用户取消”；统计和重试逻辑会误判。
- 建议：`ShotBatchGenerator.cancelled` 为真时，`finish_job` 写入 `state=cancelled` 或 `error="用户取消"`。

**P2-2 取消“标记跳过”会丢失原“已完成”状态**

- 现象：第 9 格原为“已完成”，标记跳过再取消跳过，状态变成“待生成”。
- 影响：已出图的格子被误判为未完成，导出/进度统计出错。
- 建议：`Shot` 增加 `status_before_skip`，取消跳过时恢复；或跳过只改 `skip` 标志，不改 `status`。

**P2-3 SB-009 版式留白严重，版式打分没有惩罚“视觉空区”**

- 现象：第 2 页 SB-009 合成后，下半页出现大面积空白；换 SB-001 后四格填满。
- 证据：`outputs/_e2e_page2_SB001.png` 与 `outputs/孔乙己_最后的酒_最终版/05_分镜图/页面/页_002.png` 对比。
- 影响：条漫节奏被打断，成品像“没拼完”。
- 建议：版式打分加入“面板覆盖率/空白率”指标；或在 `compose_page` 后检测空白率并提示换版式。

**P2-4 旁白条不可在气泡编辑器里编辑**

- 现象：第 1 格画面里有旁白框 + 画外音，但编辑器提示“该分镜没有对话气泡”，文本框为空。
- 影响：用户想改旁白只能回分镜表改文本再重生成，无法微调。
- 建议：把 `kind=narration/offscreen` 也纳入编辑器，允许改文字/位置/显隐。

**P2-5 群众角色没有身份卡，出图随机换脸**

- 现象：自检提示“我、酒客们没有可复用身份卡”；第 6 格质量分 92，原因 `no_reference`。
- 影响：配角/群像镜头脸和服装不可控。
- 建议：分析阶段强制为所有非纯路人角色生成 ≤90 字身份卡；或在出图前自动补一份简版身份卡。

**P2-6 空镜自动补主角与“空镜”语义冲突**

- 现象：全文分镜第 37 格描述“空荡荡的咸亨酒店柜台”，被自动追加“孔乙己是画面主体”。
- 影响：空镜/留白镜头被强行塞人，情绪落点被破坏。
- 建议：`AUTO_ASSIGN_PROTAGONIST_TO_EMPTY_SHOTS` 对“空荡/无人/只剩/粉板”等空镜关键词跳过，或只在 `characters` 为空且描述不含空镜词时补。

**P2-7 “画面外的方向”式描述污染分镜**

- 现象：全文分镜大量出现“指着画面外的方向”“对画面外的方向说话”，语义不通。
- 影响：提示词可读性差，模型容易画出奇怪构图。
- 建议：导演层把“画面外的方向”替换为具体对象（“画面左侧的柜台”“画面外的孔乙己”），或在 prompt 规范中禁止该占位词。

**P2-8 质量报告的气泡统计为 0**

- 现象：所有格子 `expected/detected=0`，但画面里实际有气泡。
- 影响：回溯报告无法用于气泡质量审计。
- 建议：程序画气泡也写入 `bubble_layout` 统计；区分 `model_drawn` / `program_drawn`。

**P2-9 姿态库全部回退到“正面兜底”**

- 现象：4 张骨架完全相同，原因字段均为“正面兜底”。
- 影响：姿态引导形同虚设，动作镜头仍靠提示词。
- 建议：检查 `data/pose_library` 的动作/视角文件命名与 `poseplan.choose_pose` 的匹配规则；补日志说明为什么没命中。

**P2-10 `analyze` 不传 title 会把工程名重置为“未命名作品”**

- 现象：新建工程标题“并发与控制测试”，调用 `/api/analyze` 只传 text/demo，工程名变成“未命名作品”。
- 影响：API 调用方/脚本会丢标题；UI 每次都传 title 所以不易发现。
- 建议：`title` 缺省时保留 `project.title`，只在显式传空串时重置。

**P2-11 `shots.py` 截图脚本与 8 步 UI 不同步**

- 现象：脚本 nav 到 `data-stage="5"` 后找 `.shot-card`，当前阶段 5 是 25 格，`.shot-card` 在阶段 7；点击超时 30 秒。
- 影响：README 里的截图工具直接失败。
- 建议：把脚本的阶段号改为 7，或改为按 `#shot-grid .shot-card` 定位。

**P2-12 旁白与画外音被合并进同一个旁白框**

- 现象：第 1 格画面顶部一个旁白框里同时出现“中秋过后，秋风是一天凉比一天……”和“（孔乙己）温一碗酒。”两条不同来源的文字。
- 影响：读者会误以为两句话同一来源；旁白/画外音的层次丢失。
- 建议：旁白与 `offscreen` 台词分框，或在同一个框内用换行 + 说话人前缀区分；必要时把画外音改为独立的小气泡/角标。

### 8.3 P3（小问题/文档一致性）

**P3-1 `config.py` 与运行态模型族不一致**

- 文件默认 `IMAGE_FAMILY="zimage"`，但 `data/settings.json` 保存了 `qwen`，UI/实际出图是 Qwen。
- 建议：README/配置注释说明“运行态可在设置里切换，文件默认值不一定等于当前值”。

**P3-2 启动日志出现“未读取到 API 密钥”误报**

- 13:03、13:33 启动时都有该 WARNING，但 `/api/service/status` 显示密钥正常、真实调用成功。
- 建议：检查启动顺序（密钥检查早于 config 读取/环境变量注入），避免误导用户。

**P3-3 自检导出时“有 1 页未合成”**

- `selftest.py` 第 8 项改了分镜后导出，提示“有 1 页未合成（第 1 页），本次条漫会跳过这些页”，但仍判定自检通过。
- 影响：自检通过但产物可能少一页；真实使用中用户可能忽略 WARNING。
- 建议：改分镜后自动 `compose_all_pages`，或在导出前强制校验页状态并失败退出。

**P3-4 `page/set-layout` 会更换 page id**

- 换版式后旧 `page_id` 立即 404，必须重新取 project 才能合成。
- 影响：脚本/第三方调用容易踩坑；UI 不受影响。
- 建议：换版式时保留原 page id，或在响应里明确返回新 id。

**P3-5 目录/标题含特殊字符时的可读性**

- 导出文件夹名直接使用作品名，含“·/（）”等字符；Windows 可用，但跨平台/压缩包解压时可能出现兼容问题。
- 建议：导出目录做文件名 sanitize（保留中文，替换 `<>:"/\|?*`）。

**P3-6 导出日志的文件数少于目录实际文件数**

- 现象：最终交付目录实际 177 个文件，导出日志仍写“共 57 个文件”；ZIP 实际 177 个条目。
- 影响：用户按日志判断产物是否完整时会被误导；自动化校验也可能误判。
- 建议：`exporter.export_project` 的计数改为递归统计实际写入的文件，或明确区分“交付文件 57 / 回溯文件 120”。
