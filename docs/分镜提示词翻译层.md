# 分镜提示词翻译层（Shot Prompt Compiler）

更新时间：2026-11-03

位置：`comicgen/prompts.py::shot_image_prompt()` → `comicgen/shot_prompt_compiler.py`

这一层只做 **分镜 JSON → Qwen-Image 能解析的观察式视觉 prompt** 的翻译，
不改小说原文、不改分镜结构字段、不碰 negative。

## 1. 三层语义不要混

| 语义层 | 载体 | 谁消费 | 翻译层是否改写 |
|---|---|---|---|
| 叙事语义 | 视觉锚点、25 格连续故事板、`refine_digest` | 分镜拆解、R1–R24 | 不碰 |
| 分镜语义 | `shot / camera / characters / char_sides / transition / panel_*` | 校验、页面合成 | 只读，不改 |
| 视觉语义 | 最终进入 Qwen 文本编码器的正向 prompt | T2I | **只在这一层工作** |

## 2. 三种模式

```python
PROMPT_REWRITER = "off"      # 旧版拼接，用于 A/B
PROMPT_REWRITER = "template" # 默认：零延迟规则翻译
PROMPT_REWRITER = "llm"      # 只让 LLM 重写首句框架，失败回退 template
```

`llm` 不会重写整个 prompt：它只生成一条 ≤120 字的观察式首句，其余身份锁、
风格块、气泡/参考图说明、negative 仍走原有逻辑，避免把结构字段改坏。

## 3. template 做了什么

### 3.1 首句定框架（≤120 字）

```text
一张{横向/竖向/方形}构图的漫画{主格/常规分格/嵌套小格}，{景别}，{机位}，
{场景}，{时间}，{主光方向}。
```

- `panel_orientation` / `panel_role` 在第一句；
- `inset` 额外写“画面边缘留出叠放空间，主体偏一侧”；
- 单人镜头在第一句插入“一名{年龄}{性别}，{发型轮廓}、{服装主色}”的观察式身份提示，
  不写角色名、不写小记忆点；双人写“两名人物，一左一右”，3 人以上写“排成错落横列”；
- 第一句永远第一、不参与 `drop_order`、不会被预算裁掉；
- 画风不塞进首句：它另有 `style_anchor` 区块，混在一起会让首句变成风格清单。

### 3.2 景别分级身份锁（5 级）

| 景别 | 保留 | 省略 |
|---|---|---|
| `wide`（远景/全景/建立） | 年龄、体型、发型轮廓、服装主色与轮廓 | 眼型、痣、缺指、单只耳饰等小记忆点 |
| `full`（全身） | 上述 + 服装层次 | 极小记忆点 |
| `medium`（中景） | 脸型、发型细节、服装层次 | 可保留 1 个小记忆点 |
| `close`（近景） | 眼型、表情、全部记忆点 | 全身服装轮廓可压缩 |
| `extreme`（大特写） | 脸型、眼型、发型、全部记忆点 | 体型/全身服装 |

实现分两层：

1. `castguard.compact_card(..., detail_level=...)` 先按景别生成单卡，
   远景直接不分配“小记忆点”预算，避免它占字数却画不出来；
2. `shot_prompt_compiler.trim_identity(..., n_cast=...)` 只做兜底裁剪：
   按“人物段”保留，反复压最长段，**绝不把第二个人整段切掉**。

### 3.3 抽象语义 → 可见元素

`rules/data/shot_prompt_rules.json` 的 `abstract_visuals` 可覆盖内置词表；
内置覆盖：悲凉、凄凉、萧瑟、冷清、压抑、颓唐、窘迫、看客的笑、哄笑、嘲弄、
冷漠、麻木、荒诞、疏离、孤独、孤寂、紧张、不安、绝望、希望、温情、蓄势、
命运转折、静默反应。

替换按“长词优先、单次替换”执行，避免“看客的笑”先被“笑”命中。

### 3.4 人群格轻量去克隆

3 人以上追加“从左到右依次是 A（特征）、B（特征）、C（特征）；
每个人的年龄、体型、发型、服装主色至少两项不同”。特征只从已有角色卡里取，
**不新增群众角色、不编造人设**。

### 3.5 预算保护

`config.PROMPT_BUDGET` 给每一类内容设上限：

```text
frame 120 / cast_wide 150 / cast_medium 280 / cast_close 420 / scene 140 /
action 80 / expression 60 / focus 40 / style 160 / composition 100
```

总上限仍由 `rules/data/shot_prompt_rules.json` 的 `max_chars`（当前 1000）
与 `config.PROMPT_MAX_CHARS` 决定；超预算按 `drop_order` 整段丢弃，
再缩画面内容，最后按句截断，绝不切在词中间。

### 3.6 出口清洗：不让描述和身份卡打架

`prompts._scrub_person_text()` 在正向出口统一做四件事：

1. `_scrub_ghost_names`：画面外角色名 → “画外”；
2. `_scrub_mismatched_glasses`：本格没人戴眼镜就删掉眼镜词；
3. `_scrub_outfit_conflict`：描述里“灰蓝长衫”和身份卡“赭石色旧长衫”冲突时，
   只替换“颜色 + 服装词”紧邻的短语，拉回身份卡的颜色；
4. `_scrub_eye_makeup`：去掉眼影/彩妆等会污染画风的词。

### 3.7 校验器

`shot_prompt_compiler.validate_prompt()` 会报：

- 正向里出现“不要/禁止/分镜/一格/漫画格/参考图”；
- 抽象词未翻译；
- 首句缺景别/机位；
- 身份锁里缺角色姓名。

它只报风险，不修改 prompt；提示词回溯（`data/projects/<id>/prompts/`）里可直接对照。

## 4. A/B 方法

```python
import config
config.PROMPT_REWRITER = "off"       # 旧版
config.PROMPT_REWRITER = "template"  # 新版
```

离线自检：

```powershell
.\env\Scripts\python.exe tools\prompt_pipeline_check.py
```

对比指标：

- 首句是否包含 `panel_orientation / panel_role / shot / camera / scene / time / light`；
- 身份锁是否被稀释（远景小痣/缺指等是否仍占大量字数）；
- 抽象词是否仍留在 prompt；
- 总长度是否仍在 `PROMPT_MAX_CHARS` 内；
- 同一工程 `off/template` 的 prompt 差异与出图差异。

## 5. 边界

- 不修改 `Shot` 的 `shot_type / camera / characters / char_sides / transition`；
- 不生成 negative，不把“不要……”混进正向；
- 身份锁字段是唯一事实源，模板只做裁剪/重述，不新增发型/服装/配饰；
- `llm` 首句失败、超时或无密钥时自动回退 `template`；
- 信息图/社媒图文的语义编译在 `comicgen/prompt_rewriter.py`，与本层互不替代。

## 6. 分镜参考图：文字身份锁 + 主视图/三视图/俯视图

只靠文字身份锁，Qwen 仍会在每一格重新猜脸。现在分镜/25 格出图会同时做两件事：

1. **文字身份锁**：首句身份提示 + `character_feature_lock` + 分级裁剪；
2. **参考图**：`Pipeline.character_reference_bundle()` 按镜头人数选参考图：
   - 单人/多人：每个可见角色只送 **一张主视图**；
   - **不送三视图**：三视图是一张三联图（三个小人），Qwen Edit 会把它
     当成“三个人”，分镜里出现 3~4 个克隆人；
   - **不送俯视图**：俯视图是头顶+双肩，也会被当成额外人物；
   - 三视图/俯视图只用于人工检查与后续编辑，分镜身份锁以主视图为准。

Qwen Image Edit 的多参考（`TextEncodeQwenImage21.images`）会把多张图一起编码；
提示词里同时写死“参考图只取脸型、发型、发色、服装、配色，不照搬站姿、构图、背景”。
实测姿势仍跟随本格文字（例如“竖起两根手指俯身”），但脸/发型/服装稳定得多。

开关：

```python
QWEN_STORYBOARD_USE_CHAR_REFS = True   # 分镜/25格送角色参考图
QWEN_STORYBOARD_REF_MAX = 3            # 单格最多几张参考
```

前置条件：阶段 3 必须先生成主视图/三视图；没有角色图时，25 格接口会拒绝生成
（`force=true` 可跳过），界面会在第 5 步顶部用黄字提示缺图角色。
