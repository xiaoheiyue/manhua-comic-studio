# 项目现状与默认策略

更新时间：2026-10-24

## 1. 当前主线

```text
小说输入
→ 第2步 精修：核心任务 / 视觉锚点 / 25 格连续故事板
→ 第3步 内容分析：角色 / 场景
→ 第4步 角色主视图 / 三视图 / 俯视图
→ 第5步 分镜拆解
→ 第6步 25 格场景分镜
→ 第7步 关键镜头姿态 / 道具图
→ 第8步 最终漫画页 / 条漫 / 导出
```

## 2. 已固化的默认策略

### 画风

- 不再硬编码 2D 韩漫；
- `comic_style_lock()` 读取 `project.style` 与 `style_detail`；
- 项目选什么风格，就输出什么风格。

### 角色

- `CHARACTER_SAME_SEED=True`：单角色镜头优先用角色固定 seed；
- 特写 / 近景不挂全身骨架，避免女性被骨架带成男性；
- 短款外套角色追加“衣摆到腰/髋，不要长风衣、过膝大衣”；
- 裤装角色禁止裙子、高跟鞋、换装。

### 双人

- `AUTO_SPLIT_MULTI_SHOT=True`；
- 分页前自动把双人镜头拆成单人格；
- 双人对话改为单人反应 / 过肩 / 插入物 / 正反打。

### 纯道具

- 无人物镜头不再走 Z-Image 文生图；
- 有 `prop_image` 就裁成该格直出；
- 没有就明确失败，要求上传道具图；
- 第 7 步有无人物卡的「上传道具图（无人格）」。

### 25 格

- 使用全部关键镜头，不再只选已有成图的镜头；
- 每格按镜头比例生成；
- 纯道具格如果有 `prop_image` 直接使用道具图；
- 联系表用满格裁切，不再留灰边。

### 俯视图

- 上传俯视参考后，系统先 `photo_to_skeleton` 提取骨架（`Character.top_skeleton`），
  再用骨架 + 身份锁生成 `俯视图.png`（`Character.top_view`）；
- 上传即自动生成（后台任务）；骨架提取失败时退回文本俯视，并在角色卡提示原因；
- 不再把通用默认图直接当角色俯视图（界面已移除「使用默认俯视」）。

## 3. 当前能力边界

Z-Image 8GB 下：

- 能完成 32 格 / 8 页的完整条漫；
- 能保持 2D 画风、页面版式、气泡、导出；
- 不能稳定保持同一张脸；
- 会在办公室/对话语境里自行补背景人物；
- 没有真正的角色参考通道。

已确认不可行/未安装：

- Nano Banana：只有 API 节点，没有本地权重，当前无 key；
- Qwen Image Edit：本地缺 `qwen3vl_8b`，8GB 跑不动；
- IP-Adapter：未安装 Z-Image 专用权重；
- 上一格 img2img：只能同场景小镜头连续，不能换镜头 + 锁角色。

## 5. 下一步建议

只建议两条：

1. 接受 Z-Image 的“背景可能多一个人”，先保证故事能读；
2. 需要严格同脸/严格人数时，接 Nano Banana / Qwen Edit 做最终格，不在 Z-Image 上继续调 prompt。


## 6. 创作工坊（非漫画）

独立菜单：`创作工坊 / 非漫画创作`。  
用 `handraw-style/` 的 365 风格、167 版式、36 主题色，生成：

- 海报；
- 社媒图文；
- 信息图 / 长图；
- 表情包（3×3 总表）；
- 插画 / 封面；
- IP / 头像；
- 电商图。

特点：

- 不读取小说工程；
- 不写“漫画”，避免模型画分镜格；
- 中文标题由程序叠加，避免错字/重复；
- 输出到 `outputs/创作工坊/<时间>/`，带 `meta.json` 与 `prompt.txt`。

文档：[创作工坊](创作工坊.md)

## 7. 结果可视化与工程恢复（2026-11-03）

第 2 步（精修/连续故事板）、第 5 步（25 格）、第 6 步（姿态图）现在有三层保障，
切换或载入工程后不会再出现“功能部分空白”：

1. **服务重启自动恢复上次工程**
   - `data/last_project.txt` 记录最后打开的工程；
   - 没有指针时回退“最近修改的合法工程文件”；
   - 不再一启动就返回空白 `Project`。
2. **每个步骤顶部有工程快照条**
   - 永远显示：工程标题 / ID / 更新时间 / 本步结果数量 / 步骤名；
   - 空状态会明确写“本项目尚未生成”，而不是留白。
3. **每个工程的结果墙**
   - `工程与产物 → 各工程的步骤结果`；
   - 每个工程一张卡：精修核心任务 + 锚点/故事板数量 + 25 格缩略图 + 姿态缩略图；
   - 可直接“看精修 / 看 25 格 / 看姿态 / 载入”。
4. **渲染不再互相拖垮**
   - `renderAll()` 对每一步单独 try/catch；某一步遇到旧工程脏数据时，只记录到
     `S.renderErrors`，不会让后面的 25 格/姿态图一起不渲染；
   - 第 5 步联系表文件缺失时，用分镜图重建 5×5 预览；
   - 第 6 步同时展示“关键镜头”和“所有已有姿态图的镜头”（旧工程格号不在
     `grid25_shots` 里时也不会漏）。
5. **刷新页面回到上次步骤**
   - 当前步骤写入 `sessionStorage`，刷新后自动回到该步骤。

## 8. 分镜/25 格的人物一致性（2026-11-03）

```text
主视图 / 三视图 / 俯视图
  → 分镜文字（25 格）
  → 逐格姿态骨架（用户上传优先）
  → 25 格 / 最终分镜
```

- **顺序**：25 格与最终分镜都走 Qwen T2I：角色主视图参考 + 本格提示词，
  **不挂自动姿态骨架**（2026-11-04 起，`AUTO_POSE_SHOTS=off`）。
  原因与证据见 [最终分镜人体结构修复](最终分镜人体结构修复.md)：
  内置骨架没有肩→髋躯干段，竖骨架又会被横格 center-crop 裁掉头脚，
  最终分镜因此出现“无头长衫 / 头在胸口 / 背后巨人”。
- 需要锁动作时，在第 7 步**上传自己的姿态图**；上传图会等比补边，不再裁切，
  且只对上传它的那一格生效。
- **参考图只送主视图**：三视图是三联图、俯视图是头顶+双肩，送进 Qwen Edit
  会被当成额外人物，出现克隆人；因此分镜只送一张主视图。
- **提示词配合**：首句写“一名老者/男子，发型轮廓、服装主色”，
  并写死“参考图只取脸/发型/服装，不照搬姿势、构图、背景”。
- 实测：单人近景/中景的脸、发型、服装明显稳定；全景因脸占比小，
  仍会有年龄感漂移，需要 LoRA / IP-Adapter 才能进一步锁死。
