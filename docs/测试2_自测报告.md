默认路径：

```text
E:\Comfy-Desktop\ComfyUI-Shared\input\俯视图.png
```

实际文件：

## 3. 优化方案

### 3.1 角色一致性

1. 先把**主视图 + 三视图**做稳定，再进入分镜；
2. 每个角色固定 seed；
3. 引入真正的参考图条件：

   - 或 Nano Banana / Qwen Image Edit 做“基础图 -> 分镜变体”；
4. 多人物格单独锁定人数，禁止第三人。

### 3.2 俯视图

1. 替换默认 `俯视图.png` 为真实顶视；
2. 校验真实图片格式（WebP 伪装 PNG）；
3. 生成侧用独立顶视工作流，不和 Pose ControlNet 硬拼；
4. 没有真实顶视时明确显示“未提供”，不拿别的角色图冒充。

### 3.3 25 格

1. 25 格只做联系表，不做最终页；
2. 每格按镜头比例生成（3:4、9:16 或 1:1），不要全部 512 方图；
3. 统一满版裁切；
4. 用第 2 步的 `continuous_cells` 直接驱动 25 格，而不是再从 27 格重选。

### 3.4 分镜描述

按参考资料：

- 每格只写：谁 + 一个动作瞬间 + 表情/视线 + 一个场景关键物 + 光源；
- 24–80 字；
- 不写心理、比喻、原文、整间屋子的装饰；
- 场景要具体，但只保留推动叙事的物件。

## 23. 双人镜头复测：不挂骨架后更糟

第 9 格（叶哥 + 陆鸣）去掉全身骨架后重跑：

- 没有变好；
- 直接画出 **3 个人**：两个坐在电脑前的女性 + 一个站着的女性；
- 叶哥/陆鸣的服装和脸仍然混。

原因：

- Z-Image 对“画面里恰好 2 个人”没有可靠计数控制；
- 负向“第三个人”压不住；
- 单人骨架无法表达两个人的站位；
- 没有双人参考/分区控制。

结论：

> 双人同格不是靠 prompt 或单骨架能解决的。  
> 在 Z-Image 8GB 下，应把双人对话拆成：
> 过肩镜头 / 单人反应 / 插入物 / 正反打，  
> 而不是让模型一次画两个完整人物。

证据：

- [双人去骨架结果](outputs/测试2_shot9_multinopose.png)

这条会写进分镜规则：**一格只放一个主要人物**。


## 24. 双人镜头拆分实验：端点可用，页面效果不合格

新增：

```text
POST /api/shot/split
```

把双人镜头拆成两个单人格，复制场景/机位，各自只保留一个角色。

测试第 9 格（叶哥 + 陆鸣）：

- 拆成第 9 格叶哥、第 10 格陆鸣；
- 两张单人格能生成，但：
  - 第 3 页出现两个坐着的陆鸣；
  - 原双人格（3 个人）仍留在页里；
  - 页面重排后格子比例/顺序变乱。

结论：

> 拆分必须在**分镜拆解/分页之前**做，不能等页面已经排好再拆。  
> 事后拆分会同时留下旧双人格和新单人格，页面必然乱。

证据：

- [双人拆分页](outputs/测试2_7页_双人拆分全身.png)

当前测试2 已被拆成 28 格，页面不是最终状态；下一轮应该从分镜阶段重新拆，而不是继续在旧页面上补。

这次没有事后拆旧页，而是在 `decompose_storyboard` 里、分页前自动拆：

但最终图仍然出现多人：

- 第 4 页：前景人物 + 背景人物；
- 第 7 页：两个人物。

原因：

- 数据层已经单角色，但 prompt 里仍有场景/姿态；
- Z-Image 在办公室/对话语境下会自行补第二个人；
- 负向“多余人物/第三个人”压不住；
- 没有角色参考/人数控制，单靠分镜结构不够。

结论：

> 自动拆双人解决了“数据层双人”，但没有解决“模型自己补人”。  
> 继续改分镜结构/版式已经到极限。

现在只剩两条现实路线：

1. 接受“背景可能多一个人”，只保证主叙事人物；
2. 换支持多参考/编辑的模型（Nano/Qwen）做最终格。
