# 最终分镜人体结构修复（2026-11-04）

## 1. 现象

同一工程里，25 格分镜（512 边长的小图）人物结构正常；进入最终分镜（按页面格子出大图）后出现：

- 长衫里没有头，只剩一截躯干；
- 头直接长在胸口，脖子和肩膀消失；
- 人物背后多出一个巨大的、无头的身体；
- 手臂过长、上身像被拉宽。

受影响的不止一格。以工程 `孔乙己·全文测试`（`caa29540ff`，32 格 / 8 页）为例，**9 格**带有自动姿态骨架：

```text
第 1、2、3、4、5、9、19、27、31 格
```

其中第 1、5、9、19、31 格最明显。

## 2. 根因：最终分镜挂了自动姿态骨架，25 格没挂

### 2.1 两条路径不一样

25 格（`05_grid25`）在 Qwen T2I 模式下明确跳过所有自动姿态：

```python
if not getattr(pipe, "storyboard_t2i", False) and s.index in pose_indexes:
    pose = ...
```

最终分镜（`06_image`）旧逻辑只跳过两种情况：

- 特写 / 近景；
- 没有开启角色参考图。

于是“全景 / 远景 + 有角色参考图”的格子仍然把 `pose_library` 的自动骨架送进
Qwen ControlNet。渲染走 `qwen_image_2.1_turbo_control`，ControlNet strength 0.8。

### 2.2 自动骨架本身没有躯干段

`data/pose_library/views/1全身正面.png` 等内置骨架是简化的 14 点棍状图：
**肩点和髋点落在同一条水平线上**，没有“颈 → 肩 → 髋”的躯干长度。
9 个受影响镜头复制的其实是同一个文件（SHA-256 完全相同，
`de4f7c78…`），并不是按动作区分的姿态。

把这种骨架交给 ControlNet，模型只能把长衫画成一整块，再把头贴在肩线/胸口；
手臂也因为没有肩关节支点而被拉长。复现图：

- `outputs/漫画_20261104_123359/05_分镜图/原图/分镜_001.png`（无头长衫）
- `.../分镜_005.png`（头被裁掉）
- `.../分镜_009.png`（头在胸口）
- `.../分镜_019.png`（背后多一个巨大身体）
- `.../分镜_031.png`（头陷进肩膀）

### 2.3 竖骨架被横格 center-crop，头脚被裁掉

`QwenEditClient.generate_control()` 旧代码：

```python
"10": {"class_type": "ImageScale", "inputs": {
    "width": 1280, "height": 1024, "crop": "center", ...}}
```

骨架库是 720×1024 竖图，页面格子可能是 1280×1024 横格。
`crop="center"` 先等比放大到覆盖画幅，再裁掉上下——**头、脚、髋经常被裁出画面**。
第 1、5 格的“无头长衫”就是这个裁切 + 坏骨架叠加的结果。

### 2.4 为什么负面提示词没拦住

Qwen 2.1 的分镜工作流用 `cfg: 1.0`。CFG=1 时负面分支不参与计算，
“多余人物 / 比例失调 / 两张脸”等负向词实际不起作用；能起作用的只有
正向构图与参考图条件。这和 [Qwen Image 2.1 UNION 节点说明](https://comfy.icu/node/QwenImage21UnionApply)
一致：guidance-distilled 模型建议把约束写成正向描述，而不是堆 negative。

## 4. 已落地修复

### 4.1 Qwen T2I 一律不挂自动骨架

`comicgen/pipeline.py::generate_one_shot()`：

```python
if self.storyboard_t2i and pose_path and not self.is_user_pose(pose_path):
    self.log(...)
    pose_path = ""
```

- 与 25 格保持同一条路径；
- 用户自己在第 7 步上传的姿态（`data/poses/`）仍然生效；
- 旧工程里已经写进 `shot.pose_skeleton` 的自动骨架也会被忽略。

### 4.2 姿态图改为等比补边，不再 center-crop

`comicgen/qwenedit.py`：

- 新增 `_pad_pose()`：按目标画幅等比缩放，黑底居中补边；
- `generate_control()` 的 `ImageScale` 改为 `crop="disabled"`。

这样即使用户上传竖版姿态，横格也不会裁掉头和脚。

### 4.3 自动姿态默认关闭

`config.AUTO_POSE_SHOTS` 由 `"key"` 改为 `"off"`；`_ensure_shot_poses()`
在 off 时直接返回 0。需要锁动作时，用第 7 步“上传姿态图”，不要依赖内置骨架。

### 4.4 回归测试

`tools/check_t2i_pose_policy.py`（不占 GPU，用假客户端）：

```powershell
.\env\Scripts\python.exe tools\check_t2i_pose_policy.py
# [+] Qwen T2I 姿态策略 OK：自动骨架忽略、用户姿态保留
```

## 6. 还建议做的两件事

1. **全景/远景加全身锚点**：正向写“全身完整入画，头顶到鞋底都在画面内，
   约 7 头身，肩宽约 2 个头宽，双臂自然下垂指尖到大腿中部，双脚踩在地面上”。
   这是 [FlowPix 全身比例方案](https://flowpixai.com/ai-art/ai-full-body-character-painting.html)
   里最有效的工程化约束，比“proportions correct”这种空话有效。
2. **横格不要画竖全身**：版面是 1280×1024 横格时，构图应写成“人物在环境中较小、
   左右留环境”，而不是“完整展现人物全身”；否则模型会为了塞下全身而压缩躯干。
   竖全身优先给竖格。
