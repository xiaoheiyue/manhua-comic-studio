# 25 宫格分镜结果 + 姿态先导方案

## 1. Nano Banana 的 25 宫格是什么

Nano Banana Pro 的 25 宫格不是“最终漫画页”，而是一张 **5×5 的分镜结果 contact sheet**：每一格是**一个场景/镜头**，不是人物姿态图。

- 一格里只放一个**场景镜头**：人物、动作、背景、机位、光线；
- 25 格共享同一角色、服装、场景和光线；
- 用来快速看剧情节奏、机位变化、角色站位；
- 每格尺寸很小，不能直接当最终漫画格，需要再逐格重绘；
- 它是“分镜结果”，不是“姿态总图”。

参考：

- [Nano Banana Pro comic storyboard workflow](https://nanobananao.com/blog/nano-banana-pro-comic-storyboard-panel-workflow)
- [Comic 25-Panel Storyboard skill](https://youmind.com/skills/comic-panel-breakdown-Lrxp4SCb5aPnOL)

## 2. 本项目采用的分层方式

我们的目标不是“一张 25 宫格直接出成品”，而是：

```text
文本分析
  → 25 个关键帧（不是把 46 格平均塞满）
  → 25 格分镜结果图（每格是场景镜头）
  → 逐格分析角色动作/机位
  → 每个关键帧的姿态骨架（Pose）
  → 角色白底姿态图（用于人工确认动作/服装）
  → 按关键帧选择进入漫画页的格子
  → 用骨架 + 身份锁 + 场景提示词逐格画漫画
  → 页内排版 / 气泡 / 自检
```

关键点：

- **25 宫格是分析工具，不是最终图**；
- 真正控制动作的是 **骨架**，不是“角色姿态图”本身；
- 角色姿态图用于**确认动作、服装、镜头**；漫画出图仍以 `skeleton + character_feature_lock` 为主；
- 这样不会出现“把姿态图当参考图，ControlNet 把衣服/背景一起抄进去”的问题。

## 4. 姿态分析规则

每个关键帧先写：

```json
{
  "shot": 15,
  "shot_type": "全景",
  "camera": "过肩",
  "characters": ["陆鸣", "叶哥"],
  "character_actions": {
    "陆鸣": "坐在桌前，右手放鼠标上，没有回头",
    "叶哥": "站在门口，右手提文件袋"
  },
  "pose": "views/12右过肩镜头.png",
  "pose_reason": "过肩"
}
```

`comicgen/poseplan.py` 规则：

- 跑/冲 → action_01
- 跳/踢 → action_02
- 坐/蹲 → action_03
- 挥手/推/伸/抓 → action_04
- 走/转身 → action_06
- 过肩 → 左/右过肩
- 特写/近景 → 特写/半身
- 俯视 → 不自动挂骨架（Z-Image 顶视不稳定，需真实俯视参考）

## 5. 出图顺序

1. **姿态图**：白底、只画角色、动作明确；用 512×768 或 768×1024，先确认动作和服装；
2. **漫画格**：骨架 + 角色身份锁 + 场景/光线/构图，尺寸按页面格子；
3. **不要**把白底姿态图当 ControlNet 输入，也不要把 25 宫格当角色参考图；
4. 25 格中只选 **真正承担叙事的格子** 进入页面，其他留在索引里。

## 8. 测试1 实测结果（2026-10-23）

- 工程：`测试1` / ID `76aa056fca`
- 文本：3053 字，分析出 5 个角色、3 个场景、46 格分镜
- 分镜结果：从 46 格中选 25 格，生成 `outputs/测试1_25宫格_分镜结果.png`（5×5 场景镜头）
- 姿态预演：`outputs/测试1_25帧_姿态预演.png`（白底人物，只是辅助）
- 姿态图：`data/projects/76aa056fca/pose25/`，每格 512×768 白底
- 漫画验证：选 5 格（1/15/30/41/46）用骨架 + 身份锁出图，见 `outputs/测试1_5格漫画_姿态先导.png`

### 实测发现

1. 分镜模型**没有主动填** `character_actions`；已在代码里用 `action` 回填到每个可见角色，否则姿态规划会把所有格子当站桩。
2. 姿态图提示词里如果没有写死“深灰长裤、短靴、纯白背景”，模型会画成白色裤子或把百叶窗/桌子带进来；已修正提示词，并用 MediaPipe 人像分割做白底清理。
3. 25 宫格是**分镜结果**，不是姿态图；它只能当镜头/节奏索引，最终漫画仍需逐格重绘。5 格漫画仍是电影分镜质感，漫画线条/网点需要单独的画风提示词和页面排版。

### 结论

这条“25 格分镜结果 → 动作分析 → 姿态 → 漫画”的路线可行，但必须：

- 25 宫格是**场景分镜结果**，只做镜头/节奏索引，不是姿态图；
- 姿态用**骨架**控制，不拿白底角色图当 ControlNet；
- 每格漫画单独写场景/光线/画风；
- 先跑 25 个关键帧，再按页面补格，不要一次跑 46 格。


## 9. 全片实跑与第一轮优化

测试1 最终跑完了 46 格 + 13 页，不是只看一格：

- 25 格分镜结果（从 46 格重组的 5×5 场景联系表）：`outputs/测试1_25宫格_分镜结果_优化后.png`
- 46 格全片联系表：`outputs/测试1_46格_全片联系表_优化后.png`
- 13 页完整页面：`data/pages/76aa056fca/页_001.png` … `页_013.png`
- 13 页联系表：`outputs/测试1_13页_全片联系表_优化后.png`
- 白底姿态预演（辅助，不是 25 宫格）：`outputs/测试1_25帧_姿态预演.png`

### 第一轮优化做了什么

1. **性别锁**：身份锁里补 `性别：女`，避免陆鸣被画成男性；
2. **女性负向**：当一格只有女性角色时，负向追加 `男性化/男相/喉结/胡须`；男女同框时不加；
3. **character_actions 回填**：模型漏填时用 `action` 回填每个可见角色；
4. **气泡**：46 格加气泡后重新拼 13 页。

### 仍然存在的问题

- 同一角色在不同格的**脸**仍有差异；身份只靠提示词，没有 LoRA/参考图条件（Pose ControlNet 与参考 latent 冲突）。
- 画面仍是**电影剧照质感**，不是漫画勾线/网点；需要单独的画风链。
- 少数格出现重复人物/多余人物（如第 17 格）。
- 25 宫格是“场景分镜结果”，不是最终页；最终页必须逐格重绘。

### 下一轮优化顺序

1. 固定角色脸：先改角色主视图，直到主视图本身稳定；再锁固定 seed；
2. 全片统一漫画线稿：用漫画线稿工作流重跑 46 格（不要照片质感）；
3. 清理重复人物：对多人物格单独用“人数锁定 + 负向”重画；
4. 气泡/页面排版微调。
