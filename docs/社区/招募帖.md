## 版本 A：小红书 / 即刻（口语、短）

**标题**：一个人写了个"小说转条漫"的本地工具，想找 30 个人来骂它

正文：

我不是画师，但我想把自己看的小说变成条漫。

所以花了几个月，写了个本地跑的流水线：丢一篇小说进去，它自己分析角色、拆分镜、选画风、出图、拼页、加气泡，最后导出长图和 PDF。

现在能跑通的：15 格 / 4 页的短篇，32 格 / 8 页的长篇也跑过。
跑不通的：同一张脸跨格保持得不好，全景会漂；办公室场景它老爱自己加人。

我没有开源过项目，现在想把它整理干净放出来，但不确定有没有人真的需要。

所以想拉个 30 人的内测群：
- 你带一篇自己的小说（或公版文本）来
- 我帮你看装环境、调参数
- 你告诉我哪里最该改

要求：Windows + 独显（8G 显存以上）+ 能接受折腾。
不太适合：想要"一键商用"的、完全没有折腾耐心的。

评论区扣 1，或者私信我。

## 版本 B：V2EX / 知乎（信息完整）

**标题**：做了个本地的「小说 → 条漫」流水线，想找内测

正文：

项目叫漫画生成器，跑在本地 ComfyUI 上（Z-Image-Turbo / Qwen-Image-2.1），不是套壳 API。

流程：小说 → 精修 → 角色/场景分析 → 人设三视图 → 分镜拆解 → 25 格 → 姿态/道具 → 拼页 → 气泡 → 条漫/PDF/ZIP。

几个自己觉得还算有用的点：
- 接入了 handraw-style 的 365 画风，按故事气质自动推荐；
- 74 种漫画分页版式，按内容自动编页，不是一页一格；
- 气泡按坐标定位填字，尽量不压脸；
- 每格出图后自检白边/文字溢出/多余气泡，低了自动重画；
- 离线自检脚本，不花 token 也能验证全链路。

清楚的短板：
- 角色同脸不稳定，8G 显存下这是硬限制；
- 只支持本地 ComfyUI，要装模型；
- 目前 Windows 优先，文档偏工程向。

打算 Apache-2.0 开源。开源前想找一批真实用户先踩坑，尤其是"装环境"这一段。
