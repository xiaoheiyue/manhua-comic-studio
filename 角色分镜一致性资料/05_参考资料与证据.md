# 05 参考资料与证据

> 本文是这套资料的“证据账本”：**哪些结论来自项目实测，哪些来自论文/官方文档，哪些只是社区经验。**
> 读法：先看证据等级，再看结论；不要把 C 级经验当 A 级事实。

### 3.1 Qwen-Image-Edit 官方与一手评测

**Qwen/Qwen-Image-Edit-2509 · Hugging Face**
<https://huggingface.co/Qwen/Qwen-Image-Edit-2509>
- 主要更新是多图输入：person+person、person+scene、person+object；
- 换姿势同时保持身份一致；原生支持 ControlNet keypoint；
- 三图输入示例。
- **证据等级：A**。用途：支持“多参考可行，但要按职责组合”；也是“身份一致 + 姿势可改”的官方依据。

<https://rits.shanghai.nyu.edu/ai/introducing-qwen-image-edit-2509-enhanced-image-editing-capabilities>
- “Optimal results with 1-3 input images”；

- **证据等级：A-/B**。用途：参考图数量的经验上限 1–3。

**Stable Diffusion Tutorials：Qwen Image Edit 2509 多图**
<https://www.stablediffusiontutorials.com/2025/09/qwen-image-edit-2509.html>

**Qwen-Image-Edit-2511 综述（博客园）**
<https://www.cnblogs.com/dsx2016/articles/19855963>
- 20B MMDiT；多角度/分镜；8GB 可运行（量化）；“AI 感较重，建议洗图”。
- **证据等级：C**。用途：Phase 2 的选型参考，不作为当前结论。

### 3.2 多主体/身份保持论文

**CogCanvas: A Benchmark for Evaluating Multi-Subject Reference-Based Image Generation**
<https://arxiv.org/html/2606.15867v2>
- 主体数 N=2→5 时，属性绑定（DINO-Sim）和属性问答（Attr-VQA）显著退化；
- N≥3 时服装/物件被丢弃、互换；N=5 时多数方法接近崩溃；
- 存在 **identity vs layout trade-off**：身份相似度高，往往提示词构图遵循度低。
- **证据等级：A**。用途：支持“一格多人 + 每人参考”很难；“参考图越强越不听话”；“多送图不是加法”。

**MultiBind: A Benchmark for Attribute Misbinding in Multi-Subject Generation**
<https://arxiv.org/html/2603.21937>
- 多主体生成中的属性错绑（把 A 的服装/特征绑到 B）是系统性问题，不是个别模型 bug。
- **证据等级：A**。用途：支持“双人同框必须做差异对照/分区，不能只写‘两人不同’”。

**Persistent Identity Preservation in Generative Image Models: A Benchmark and Evaluation System**
<https://arxiv.org/html/2609.04151v2>
- 用多张 enrollment 图的身份嵌入均值作为身份锚，降低姿态/表情/光照影响；
- 人类身份用 ArcFace 嵌入评估；
- 对比 in-context 条件与 LoRA 的差异。
- **证据等级：A**。用途：支持“同一角色多张干净参考做锚点”“用 ArcFace 做辅助验收”“in-context 模型仍需要参考图重建身份”。

**CharCom: Composable Identity Control for Multi-Character Story Illustration**
<https://dl.acm.org/doi/full/10.1145/3743093.3770985>
- 多角色故事插画的可组合身份控制；需要区域/身份组合，而非单张参考。
- **证据等级：A**。用途：说明“多人一致性”是独立研究问题；本项目 Phase 2 再考虑。

**UniCustom: Unified Visual Conditioning for Multi-Reference Generation**
<https://arxiv.org/html/2605.12088v2>
- 多参考场景下的 attribute leakage / cross-reference confusion。
- **证据等级：A**。用途：补充“多参考会互相混淆”的学术证据。

### 3.3 身份注入技术（IP-Adapter / FaceID）

**Tencent AI Lab · IP-Adapter Wiki**
<https://github.com/tencent-ailab/IP-Adapter/wiki/IP%E2%80%90Adapter%E2%80%90Face>
- IP-Adapter-FaceID 用 ArcFace 身份嵌入 + LoRA；
- Plus-Face 用裁切人脸作为条件；
- Full-Face 用 MLP 映射 CLIP 嵌入，比 Plus-Face 更好。
- **证据等级：A**。用途：证明“面部裁切参考”是有正式技术依据的；“身份嵌入”与“图像内容条件”是两条不同的路。

**Stable Diffusion Art · IP-Adapter 指南**
<https://stable-diffusion-art.com/ip-adapter>
- Plus-Face 用 cropped face；FaceID 用 InsightFace 身份嵌入；
- 不同变体对“像不像/听不听话”的取舍不同。
- **证据等级：B/C**。用途：解释为什么“面部特写参考”有效，以及为什么 LoRA/IP-Adapter 与 Qwen Edit 不能混为一谈。

## 4. 外部资料：工程实践

> C 级：单例/厂商经验，用于补充“怎么做”，不作为“一定有效”的证明。

### 4.1 角色参考表 / 分镜

**ScreenWeaver · AI Storyboard Character Consistency: The Reference Method**
<https://www.screenweaver.ai/blog/ai-storyboard-character-consistency>
- 每个角色一张固定参考表：4 个全身视角（front/3⁄4/side/back）+ 头部特写，同一比例/地平线、中性站姿、白底、plain previs；
- 参考表在每个出现该角色的分镜里都要在场；
- 参考表不能保证“像某个演员”，也不等于最终帧；分镜是 previs，不是成片；
- 重点：**参考表是“身份对象”，不是“一张好看的图”**。
- **证据等级：C**。用途：支撑 02 的资产规范（中性、白底、平光、多视角、头特写）；同时提醒“参考表不是万能的”。

**AI追光 · 角色三视图工坊**
<https://aizhuiguang.tech/tools/character-turnaround.html>
- 三视图的检查：三张互相吻合、平光、中性表情、无遮挡；
- 并排放大看头身比、数唯一性特征、看服装接缝、确认平光；
- “三视图负责锁得死，文字负责讲清楚”。
- **证据等级：C**。用途：02 的三视图验收清单；与本文“图+文字锚点”一致。

**腾讯云开发者社区 · AI短剧人物一致性实战：三视图锁定 + 双人同框防串脸**
<https://cloud.tencent.com/developer/article/2747984>
- 先做三视图，正面用于特写、侧/背用于转身/背影；
- 双人同框开 `input_fidelity=high`，不要同一镜头两个正面特写，必要时拆镜头；
- 每集结束对照三视图清一遍，崩了立刻重画，不要拖到装配。
- **证据等级：C**。用途：支持“侧/背单视图按需用”“双人拆格/降风险”“返修要趁早”。

**知乎 · 只需两步，三张图生成属于自己的 IP 电影**
<https://zhuanlan.zhihu.com/p/1933097405814931549>
- 三视图不只用于垫图，还用于多角度融合；少主体+特写/近景成功率高，多主体+远景仍需抽卡。
- **证据等级：C**。用途：支持“多人+远景最难，优先拆/降级”。

### 4.2 多参考的角色分工

**Atlas Cloud · Qwen Image 3.0 Pro Multiple Reference Images: Stop Letting 3 Inputs Fight**
<https://www.atlascloud.ai/blog/tips/qwen-image-3.0-pro-multiple-reference-images>
- 1–3 张参考；给每张图一个不重叠的职责；
- 身份放 Image 1；姿势参考要裁掉脸/头，避免身份泄漏；
- “为什么模型抄了姿势而不是角色”——因为姿势参考里的脸/服装/轮廓信号更强；裁到身体、写清“只控姿势”。
- **证据等级：C**（厂商博客，且是 3.0 Pro，不是本项目 2.1）。用途：支撑 03 的“一图一职/身份第一/姿势参考裁头”。

**Linocut · Best Multi-Reference AI Image Models**
<https://linocut.ai/blogs/multi-reference-ai-image-models>
- 五个规则：一个身份锚、每张参考一个职责、区分 must-keep/must-change、先结构后外观、不要只看脸；
- 给出“Image 1 保留身份，Image 2 只用外套，Image 3 只用姿势/机位”的提示词结构。
- **证据等级：C**。用途：支撑 03 的参考图职责句与顺序。

**MyAIForce · Pose Transfer in ComfyUI with Qwen Edit 2511**
<https://myaiforce.com/qwen-image-edit-pose-transfer>
- 用 Qwen Edit 做姿势迁移时，给姿势参考的头部打码/裁掉，避免参考的发型/脸泄漏；
- 关闭 Detect Face，避免参考脸形混入；
- 姿势骨架 + 像素参考一起用，比只给像素参考稳。
- **证据等级：C**。用途：支撑“姿势参考要提纯”“参考图会带脸/发型”。

### 4.3 文本/seed 纪律

**贝果科技 · AI角色一致性怎么做：角色设定表、参考图与各工具的官方方法**
<https://bigolab.com/guides/1634-ai-character-consistency>
- 固定描述 + 定妆参考图 + 逐张迭代；
- seed 不是角色锁（引用 Midjourney 官方说法）；
- 每次只改一处，跑偏就回到定妆照重开。
- **证据等级：B/C**（整理官方文档）。用途：支撑“seed 只复现随机性”“不要用一张漂移图回灌”。

**PixVerse · 如何用 AI 保持角色一致**
<https://pixverse.ai/zh/blog/how-to-create-consistent-characters-with-ai>
- 身份优先于动作；锁定用词；负向词；建立并复制模板；
- 参考静帧比堆形容词更有效。
- **证据等级：C**。用途：支撑 03 的提示词顺序与“身份卡逐字复用”。

**Sohu · AI漫剧里“角色三视图”怎么用？**
<https://www.sohu.com/a/1035895537_122618923>
- 三视图是“角色一致性”的起点而非终点；
- 固定角色描述段，逐字复用；用三视图校验脸型/发际线/服装/体型；
- 再生成表情卡/动作卡。
- **证据等级：C**。用途：支撑“三视图是资产，不是终点”“固定描述段”。

## 5. 外部结论 → 本项目采纳/不采纳

| 外部说法 | 来源 | 本项目结论 | 原因 |
|---|---|---|---|
| 多图输入 1–3 张最佳 | Qwen 官方/评测 | **采纳**：默认 1–2 张，最多 3 张 | 8GB 实测 3 张慢 2.26×，无可见收益 |
| 一张参考表覆盖多视角 | ScreenWeaver | **部分采纳**：资产层做多视角；分镜层只送单视图 | 编辑模型会把多身体当内容；成本高 |
| 三视图是起点不是终点 | Sohu/AI追光 | **采纳**：三视图只做视角字典，分镜靠路由 | 与项目“三联图不进分镜”一致 |
| 双人同框要 `input_fidelity=high` | 腾讯云 | **不直接采纳**：本项目 Qwen 路径无该参数 | 但采纳“双人拆格/分区/≤1 台词” |
| 身份放 Image 1，姿势参考裁头 | Atlas Cloud | **采纳**：身份参考第一张；姿势交给骨架 | 与 Qwen 节点“第一张定画幅/主身份”一致 |
| 姿势参考会泄漏身份 | MyAIForce | **采纳**：参考图只留身份，姿势用骨架 | 项目 img2img 实验同结论 |
| seed 不是角色锁 | 贝果/PixVerse | **采纳**：seed 只复现，不锁脸 | `rules/01` H9 已写 |
| 多主体 N≥3 属性错绑 | CogCanvas/MultiBind | **采纳**：3–4 人不送多参考；拆格/群像 | 项目双人/三人失败经验一致 |
| 多张 enrollment 图做身份锚 | Persistent Identity | **采纳**：主视图+面部特写+侧面图可作为角色锚点 | 但当前只用单张参考，Phase 1 再扩展 |
| LoRA 是最终解 | 社区 | **不采纳（当前）**：8GB 训练 OOM | 归档，等 12GB+ |
| 2511 多角度更强 | 博客园/B站 | **观望**：20B/8GB Q3 不划算 | Phase 2 再评估 |

## 6. 还没验证的问题（下一轮清单）

1. **Qwen 2.1 Turbo 的参考数量曲线**：1/2/3/4 张，固定提示词/种子，20 格 A/B，记录身份/服装/构图/耗时；当前只有 n=1。
2. **面部特写 vs 主视图**：用 ArcFace 相似度 + 人工，比较特写/近景的 ID 增益；当前只有视觉单例。
3. **侧/背单视图的增益**：主视图 vs 主视图+侧面/背面，侧身/背身镜头 A/B。
4. **俯视图是否值得送**：主视图 vs 主视图+top，在“真顶视”提示词下能否真的改变机位；如果不能，降级为“可选/不用”。
5. **参考图 pad 到分镜画幅**：能否消除输出比例不符/裁切；对比 pad vs 出图后 fit。
6. **双人 2 参考 + 左右分区**：可用率是否比纯提示词高；失败样本的共性是“服装相似”还是“站位重叠”。
7. **cfg=1.0 下负向词是否完全无效**：用强负向（例如“红色”）做对照；如果是，负向词只保留给 Z-Image。
8. **Qwen 2.1 vs 2511**：同一批 10 格，质量/速度/显存；2511 是否值得换。
9. **自动验收阈值**：ArcFace/人数/主色 ΔE 的项目内标定；不要套外部绝对值。
10. **文档-代码同步机制**：是否在 CI/selftest 里加“文档中的配置值/行号”检查（轻量）。
