## 1. 当前实现核查（2026-11-03）

### 1.1 角色资产生成链路

```text
人设文本
  → 姿态总图（Pose ControlNet，1536²）
  → 主视图（单独 Qwen T2I，1024×1536）
  → 三视图（正面=主视图；侧面/背面用主视图作参考生成，再拼 1536×768）
  → 俯视图（仅当用户上传 top_source；参考→骨架→ControlNet/Qwen 生成）
```

对应代码：

| 步骤 | 位置 | 说明 |
|---|---|---|
| 姿态总图 | `comicgen/pipeline.py:1461` | `generate_character_pose_sheet()` |
| 主视图 | `comicgen/pipeline.py:1554` | `generate_character_main_visual()`，单人正面直出 |
| 三视图 | `comicgen/pipeline.py:1605` | `generate_character_three_view()`，正面=主视图 |
| 俯视图 | `comicgen/pipeline.py:1675` | `generate_character_top_view()`，需 `top_source` |
| 总入口 | `comicgen/pipeline.py:1757` | `generate_character_images()` |

注意：

- `config.CHARACTER_TOP_AUTO=False`：没有上传俯视参考时，不自动生成俯视图；
- `config.CHARACTER_MAIN_FROM_TRIPLE=False`：主视图不再从三视图裁；
- 但 `rules/09_主视图与姿态图.md` 仍写“姿态总图→裁左上正面→主视图”，**已过时**；
- `config.CHARACTER_POSE_INSTRUCTION`（`config.py:1163`）仍硬编码“全部头发向后梳成低马尾”，会作用于姿态总图（不影响主视图/分镜，但会让人误判角色发型）；
- `generate_character_top_view` 在 `pipeline.py:1520` 和 `:1675` 有**两个同名定义**，后者覆盖前者；旧版是 45° 俯视，新版是“参考→骨架→顶视”。阅读时容易误判，建议删旧版。

### 1.2 分镜参考链路（P0 已修复，2026-11-03）

**修复前**：`comicgen/qwenedit.py` 把 `TextEncodeQwenImage21.images` 写成嵌套 `{"images": {"image_1": ...}}`，而 ComfyUI 的 `COMFY_AUTOGROW_V3` 要扁平键 `images.image_1`。参考图被静默丢弃：

- 同一提示词/种子，主视图 / +三视图 / +俯视图 / 三张全送，四张输出 SHA256 完全相同（`09F734…`）；
- 换成纯红方块参考，输出仍相同；
- 也就是说，过去“Qwen 参考图锁脸”的效果主要来自提示词和随机性。

**修复后**：

```python
enc = {"clip": ["2", 0], "prompt": prompt, "negative_prompt": negative,
       "resolution": resolution, "vae": ["3", 0]}
for i in range(len(names)):
    enc[f"images.image_{i+1}"] = [str(20 + i), 0]
```

同一提示词/种子、主视图参考，输出哈希变化（`3B51…`），画面明显贴近主视图（白发、瘦长脸、蓝衫+深褐夹克）。`generate_control()` 也同步改为扁平键。

**同时落地**：

- 参考图先 pad 到目标画幅（不放大、不裁人物），解码后再 `ImageOps.fit` 到分镜格；
- `plan_shot_refs()` 按景别/视角/人数路由（见 [`03`](03_分镜参考路由与提示词规范.md)）；
- 特写/近景不挂自动全身骨架；
- `Character.face_ref/views/view_quality` 与 `charrefs.py` 派生资产；
- 双人/多人“年龄/身高关系句”写入画面内容。

复现脚本：`tools/ref_probe.py`（旧路径，预期哈希相同）与 `tools/ref_probe_flat.py`（扁平键，预期哈希不同）；落地测试见 [`06_落地实现与测试记录.md`](06_落地实现与测试记录.md)。

### 1.3 输出画幅：已改为“参考图 pad + 输出 fit”

Qwen `TextEncodeQwenImage21` 的 latent 输出跟随**第 1 张参考图**的尺寸：

- 参考主视图 1024×1536（2:3），请求 1024×1024，会输出 832×1248；
- 参考面部特写 1024×1024，输出 1024×1024。

现在 `QwenEditClient._pad_ref()` 会先把参考图**等比缩到目标画幅内、白底居中**（不放大、不裁人物），解码后再 `ImageOps.fit` 到分镜格。实测 9 格输出全部为 1088×1280 / 1216 / 1152 等目标尺寸，没有再出现“参考图 2:3 把分镜格拉成 832×1248”。

> 仍是工程近似：pad 的白边可能被模型当背景，建议用 3–5 格做“pad vs 出图后 fit”的 A/B；当前实测没有出现白边污染，但样本只有 9 格。

## 2. 改造路线（按性价比排序）

### Phase 0：修通道 + 补资产（✅ 2026-11-03 已实施）

1. **修 P0**：`qwenedit.py` 的 `generate()` 与 `generate_control()` 改用 `images.image_N` 扁平键；
2. **补 `面部特写.png`**：从主视图裁头肩（`comicgen/charrefs.py` 的 `face_crop()`），先裁切、后考虑生成；
3. **切三视图**：`三视图.png` → `views/front|side|back.png`（有左右侧面时再分 `side_l/side_r`）；正面用主视图覆盖；
4. **验收俯视图**：人脸检测=0 才标 `top_down`，否则标 `high_angle`；
5. **修文档漂移**：至少改 `rules/08`、`rules/09`、`docs/角色主视图与姿态图.md` §10、`config.py` 注释；
6. **回归**：同一提示词/种子换参考图，输出哈希必须变化；三视图/俯视图生成不崩；页面合成无新裁切。

**验收标准：**

- 参考图变化 → 输出变化（哈希不同）；
- 抽 3 个角色，特写用 `face_ref`，肉眼比旧路径更像主视图；
- 单人近/中景没有新增“第二个人”；
- 输出画幅要么等于分镜格，要么有明确的 `fit/pad` 记录。

### Phase 1：路由矩阵（✅ 已落地；3 人 3 参考 A/B 已完成，不采纳）

1. 在 `Character` 增加 `face_ref` / `views` / `view_quality`；
2. 在 `Shot` 增加 `view_hint`（front/side/back/top）与 `ref_plan`（记录实际送的图、职责、顺序）；
3. 按 [`03_分镜参考路由与提示词规范.md`](03_分镜参考路由与提示词规范.md) 第 3 节实现 `plan_shot_refs()`；
4. 参考图统一 `pad` 到分镜格比例；
5. 提示词增加“图 N 是 X 的身份参考，只取…不取…”职责句；
6. 特写/近景不挂全身骨架；
7. 双人镜头每人 1 张 `face_ref`，左右分区；3 人 0 张多参考，4 人拆 3+1/2+2；
8. 日志/Prompt Trace 记录 `ref_plan`，出问题可回溯。

**特别注意：** 修 P0 后，“ControlNet + 多参考”会第一次真正同时生效。`generate_control()` 的 latent 来自 `TextEncodeQwenImage21`（跟随第 1 张参考图），ControlNet 的 `ImageScale` 用目标画幅，两者尺寸可能不一致；应用后必须单独回归“姿态格 + 参考图”组合，确认没有 batch/shape 报错或构图错位。

> 2026-11-03 已回归：中景 + 自动姿态 `pose_07` + 主视图，79.1s，无 shape/batch 报错，人物坐下/服装稳定。见 06 §3。

### Phase 1.5：第 5–7 步统一（✅ 2026-11-03 已落地）

- **第 4 步分镜拆解**：`rules/data/storyboard_rules.json` 的 `max_characters/split_above` 改为 3，`_split_multi_character_shots()` 不再保留 4 人；
- **第 5 步 25 格**：改用 `build_shot_references()`（与最终出图同一套路由），不再直接调 `character_reference_bundle()` 绕过 T2I 策略；Qwen T2I 跳过自动姿态补图，也不把自动骨架传给 25 格；
- **第 6 步姿态图**：Qwen T2I 下自动姿态停用，只保留用户上传的自定义姿态；Z-Image 仍可用自动骨架；
- **第 7 步最终出图**：继续用 `build_shot_prompt()` + `plan_shot_refs()` + 多脸兜底；页面合成只消费这些原图，不另起一套提示词；
- **4 人保护**：25 格入口检查关键镜头人数，>3 直接提示先拆；`force=true` 才允许硬出。

**验收标准：**

- 10 格抽检：人数正确率 100%，同角色身份人工通过 ≥80%，服装主色一致 ≥90%；
- 侧/背镜头能看到对应侧面/背面结构（不是正面硬猜）；
- 全景/远景没有新增克隆人；
- 双人镜头不再出现第三个人（失败即拆格）。

### Phase 2：身份注入（12GB+ 或云端）

- **LoRA**：每角色 20–60 张多角度图，触发词 + 权重 0.7–0.9；8GB 训练 OOM，暂不做；
- **IP-Adapter FaceID / PuLID**：换 SDXL/Flux 底模时可用；FaceID 用 ArcFace 身份向量，Plus-Face 用裁切人脸；
- **Qwen-Image-Edit-2511**：多图/多角度更强，但 20B 在 8GB 只能 Q3，画质/速度不划算；
- **区域控制**：Regional Prompting / Attention Couple，用于 2–3 人同框；当前 Z-Image 工作流不支持，不要未验证就接。

### Phase 3：后期与自动验收

- FaceDetailer / 局部重绘：只修脸，不动构图；修完重看表情；
- 自动质检：人脸检测/人数、ArcFace 相似度、主色 ΔE、OCR 文字溢出；
- 资产版本化：主视图变更 → 下游 `views/face_ref` 全部重建，旧分镜标记“需重跑”。

## 3. 数据结构建议

```python
@dataclass
class Character:
    ...
    face_ref: str = ""                 # 面部特写
    views: dict[str, str] = field(default_factory=dict)   # front/side/side_l/side_r/back/top
    view_quality: dict[str, str] = field(default_factory=dict)  # top: top_down/high_angle
    asset_version: str = "v1"

@dataclass
class Shot:
    ...
    view_hint: str = ""                # front/side/back/top
    ref_plan: list[dict] = field(default_factory=list)
    # [{"path": "...", "character": "孔乙己", "role": "identity|view|pose",
    #   "view": "front", "order": 1}]
```

`ref_plan` 必须写进 `prompt_trace`，这样返修时能回答：

- 这一格送了几张图？
- 每张图是谁、什么视角、什么职责？
- 顺序和提示词的“图 N”对得上吗？
- 出问题时是“没送”“送错”还是“送了但模型没用”？

## 4. 验收指标

### 4.1 指标定义

| 指标 | 定义 | 采集方式 | 建议目标 |
|---|---|---|---|
| **人数正确率** | 画面人数 = 分镜人数 | 人脸/人形检测 + 人工 | 100%（单人格） |
| **身份通过率** | 抽检格中“能认出是同一角色”的比例 | 人工三看 + ArcFace 辅助 | 主角 ≥90%，配角 ≥80% |
| **服装一致率** | 主色/款式/外层数量一致 | 人工 + 主色 ΔE | ≥90% |
| **记忆点保留率** | 指定配饰/疤/痣还在 | 人工 | ≥90% |
| **视角正确率** | 侧/背/顶视与分镜意图一致 | 人工 | ≥85% |
| **一次通过率** | 首轮生成即合格，无需返修 | 日志 | ≥70% |
| **返修率** | 因一致性问题重画的格数 / 总格数 | 日志 | ≤20% |

### 4.2 ArcFace 相似度怎么用

- 不要套外部绝对阈值；每个项目/画风/角色单独标定；
- 做法：取同一角色跨格正样本、不同角色负样本，计算余弦相似度分布，选使 EER 最小的阈值（或人工定一个保守阈值）；
- 只作为**辅助**：漫画风格、侧脸、遮挡、表情都会拉低相似度；最终以人工三看为准；
- 参考：Persistent Identity Preservation（arXiv 2609.04151）用多张 enrollment 图的身份嵌入均值做锚点，降低姿态/表情/光照影响；本项目可用主视图+面部特写+侧面图构建角色锚点。

## 5. 返修 SOP

### 5.1 先分类，再动手

| 失败类型 | 典型表现 | 先查 |
|---|---|---|
| 身份 | 脸不像、年龄/性别变 | 参考图送了吗？送的是脸还是全身？ |
| 造型 | 换装、外套变长、发型变 | 主视图在不在？服装锁写了吗？ |
| 人数 | 多一个人、克隆人 | 参考图里有几个身体？景别？提示词有没有人群词？ |
| 视角 | 侧脸像正脸、背面有脸、顶视不顶 | 有没有对应单视图？俯视图是不是真顶视？ |
| 画风 | 线条/上色变 | 风格块是否逐字复用？参考图是否把画风带进来？ |
| 连续 | 道具/伤口/时间不对 | 分镜表/场景状态，不是模型问题 |

### 5.2 返修顺序（从便宜到贵）

```text
1. 修提示词职责句（只取…不取…）        ← 最便宜
2. 换参考图（face_ref ↔ main ↔ side/back/top）
3. 调参考图预处理（pad 画幅、去背景、裁单人）
4. 换 seed / 重跑该格
5. 局部重绘（脸/服装/多余人物）
6. 重画该格（改构图/骨架）
7. 回炉资产（主视图/三视图本身错）      ← 最贵，但必须做
```

**不要做的事：**

- 不要把上一格/这张漂移图当参考图再喂回去（会把错误固化）；
- 不要在同一格上连续调 10 次 denoise/提示词（项目已经证明是无效循环）；
- 不要在“数据层单角色、模型仍补人”时继续改分镜结构（先查参考图/人数锁/骨架）。

### 5.3 返修记录

每格记录：

```json
{
  "shot": 8,
  "issue": "identity",
  "refs_before": ["主视图"],
  "refs_after": ["面部特写", "主视图"],
  "action": "swap_ref",
  "result": "pass",
  "note": "特写脸更稳；外套仍偏长，已加短款锁"
}
```

沉淀到 `outputs/一致性返修记录.jsonl`，下一轮直接查“同类问题上次怎么修”。

## 6. 8GB 现实约束

| 约束 | 影响 | 对策 |
|---|---|---|
| 8GB 显存 | Qwen 2.1 int8 + 8B 文本编码器；Z-Image 不能同时驻留 | 每次切换调 `/free`；不要并行跑两套 |
| LoRA 训练 OOM | 8GB/16GB 训不出角色 LoRA | 不把 LoRA 当主路径；用参考图路由 + 后期 |
| Qwen 每格 20–90s | 3 张参考比 1 张慢 2.26× | 默认 1–2 张；只在高收益镜头加图 |
| 俯视图生成不稳定 | 45° 高角度冒充顶视 | 人脸检测=0 才入库；否则标 high_angle |
| 姿态库骨架缺头 | 自动挂骨架会失败/画错 | `validate_pose()` 拦截；选不到就不挂 |
| 负向词弱 | cfg=1.0/1.4 | 不靠负向词；靠正面锁 + 路由 + 后期 |

## 8. 一句话总结

> **当前最大的问题不是“参考图不够多”，而是“参考图根本没进去”。**
> 先修 P0，再补面部特写/单视图，再按景别路由；每一步都用“换参考图 → 输出变化”和“10 格抽检”验收。
