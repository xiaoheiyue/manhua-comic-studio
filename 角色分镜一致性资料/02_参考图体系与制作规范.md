# 02 参考图体系与制作规范

> 本文定义角色设定资产的**种类、用途、制作方法、验收标准、入库结构**。
> 核心原则：**一张参考图只承担一个职责；进分镜前必须“单体重建”。**

---

## 1. 角色设定包：建议的目录与命名

```text
data/characters/<角色名>/<造型名>/
  主视图.png                 # 全身正面，身份主参考
  面部特写.png               # 头肩，特写/近景主参考（建议新增）
  半身.png                   # 可选：腰以上，近景备用
  三视图.png                 # 人工查看用，不进分镜
  views/
    front.png                # 正面单视图（通常 = 主视图）
    side.png                 # 侧面 90°（本项目三视图只有一张侧面）
    side_l.png               # 可选：左侧 90°
    side_r.png               # 可选：右侧 90°
    back.png                 # 背面
    top.png                  # 真顶视（可选）
  姿态图.png                 # 多姿态总图，人工查看/姿态库，不进分镜
  资产.json                  # seed、提示词、生成日期、质检结果
```

命名约定：

- 角色名/造型名用中文可以，但**不要带空格、斜杠、版本号之外的符号**；
- 同一角色多套造型必须分目录（`默认造型/`、`雨夜造型/`），不要在同一目录里覆盖；
- `views/` 下的单视图必须**一张图一个人**；文件名即视角，不允许 `side.png` 里并排两个人。

> 当前项目已有 `主视图.png / 三视图.png / 俯视图.png / 姿态图.png`，但没有 `面部特写.png` 和 `views/` 单视图。建议按本文补齐，不改现有文件名，避免破坏旧工程。

## 2. 主视图：身份主参考

### 2.1 用途

- 分镜的**默认身份参考**（单人近/中景）；
- 角色造型的**唯一权威定义**；
- 三视图的正面来源、面部特写的来源。

### 2.2 制作规范

| 项 | 要求 | 原因 |
|---|---|---|
| 人数 | 1 人，一个头、一个身体 | 多身体会被复制 |
| 视角 | 正面，平视，站姿自然（A-Pose/双臂自然下垂） | 正面信息最全；姿势不抢戏 |
| 取景 | 全身，头顶到脚底完整，脚不裁切 | 身高比例、鞋/下装要能对 |
| 背景 | 纯白或极浅中性灰，无场景、无文字 | 背景/文字会被当内容复制 |
| 光线 | 平光、中性、无强侧光/色偏 | 强光影会被当人物特征 |
| 表情 | 中性偏冷静，不笑、不皱眉 | 表情会被当“固有属性” |
| 服装 | 只保留一件外层；领口、袖口、下摆、腰带结构清楚 | 两件外套会被各画一次 |
| 分辨率 | 1024×1536（当前）；长边 ≥1024 | 脸像素有限，见下 |
| 命名 | `主视图.png` | 兼容现有代码 |

### 2.3 当前实测：脸只占 10.4%

本次对项目内 20 个角色主视图的测量：

- 17/20 能检出人脸；
- 人脸高度中位数 **160 px**，占画面高度 **10.4%**；
- 最小 100 px（6.5%），最大 305 px（19.9%）。

这不是“主视图不合格”，而是**全身构图的必然结果**：全身像要装下 7 个头身，脸就只能是 1/7 左右。问题在于：**分镜特写需要 700–900px 的脸**，主视图给不了。

> 所以主视图负责“全身比例 + 服装 + 发型轮廓 + 大致的脸”，**特写细节交给面部特写**。

### 2.4 主视图验收（四问）

1. **人数**：是不是只有一个头、一个身体？（用检测器 + 人工各看一遍；Haar 会误检，不能只信它）
2. **服装**：是不是只有一件外层？领口/袖口/下摆是否清楚？
3. **脸**：正脸、平视、无遮挡、无夸张表情？脸高是否 ≥120px？
4. **背景**：是否纯白/浅灰、无文字、无道具遮挡？

任一项失败 → 重生成，不要“先用着”。主视图是地基，地基歪了后面全歪。

## 3. 面部特写：特写/近景的身份参考（建议新增）

### 3.1 为什么需要

- 主视图的脸只有约 160px；特写成图的脸约 700–900px，放大 4–6 倍；
- 参考图送进编码器时还会被统一缩放，全身图里的脸占的 token 更少；
- 头肩特写让脸占参考图的 35%–50%，编码器可以把更多有效信息放在脸上。

> 这不是“多送一张图”的玄学，而是**有效像素/注意力分配**的问题。

### 3.2 两种做法，优先“裁”，必要时“生成”

| 做法 | 优点 | 缺点 | 适用 |
|---|---|---|---|
| **A. 从主视图裁头肩** | 100% 同一张脸；零漂移；可复现 | 分辨率低（脸仍 160px，放大后偏软）；可能带进衣领/背景 | 默认；一致性优先 |
| **B. 用主视图作参考，生成 1024 头肩特写** | 脸更清晰、细节更足 | 可能漂移；需要验收 | 特写是重点镜头、裁切太软时 |

**默认用 A**，因为一致性优先；B 只在“这张特写是封面/关键情绪格”时用，并且必须和主视图做人工比对。

裁切参数建议（与 `tools/ref_probe_flat.py` 的 `face_crop()` 一致）：

```python
side = max(face_w, face_h) * 2.4          # 头肩范围
cx   = face_x + face_w / 2
cy   = face_y + face_h / 2 + face_h * 0.15  # 略向下，带一点肩/领口
crop = image[cx-side/2 : cx+side/2, cy-side/2 : cy+side/2]
```

输出：`面部特写.png`，512×512 或 1024×1024，白底/透明底，脸居中，头顶留一点空间，不裁下巴。

### 3.3 面部特写验收

- 脸占画面高度 **35%–55%**；
- 正脸或轻微 3/4，不侧到看不到另一只眼；
- 平光、无遮挡（头发不盖眼、手不挡下巴）；
- 与主视图**同发型、同发色、同服装领口、同记忆点**；
- 若为生成版：与主视图的人脸相似度在项目内标定阈值以上（见 04）。

## 4. 三视图：视角字典，不是分镜参考

### 4.1 三视图到底提供什么

| 视图 | 提供的信息 | 主视图有没有 |
|---|---|---|
| 正面 | 脸、正面服装结构 | 有 |
| 侧面 90° | 鼻梁高度、下颌角、后脑形状、侧面服装厚度 | **没有** |
| 背面 180° | 后发、发旋/发缝、背部服装、腰带/下摆 | **没有** |

所以三视图的价值是**补充主视图看不到的角度**，不是“再来一张更全的身份证”。

### 4.2 制作规范

- **正面必须用主视图原图**（当前 `generate_character_three_view()` 已这样做）；
- 侧面/背面从主视图生成，一次只生成一个角度，提示词只写“侧面/背面 + 保持同一张脸/同一套服装”；
- 三个视图**同一身高、同一头身比、同一脚底线、同一平光**；
- 背景纯白，人物之间留白清楚，不重叠、不带文字标签；
- 生成后做一致性校验：头身比、服装接缝、记忆点位置、脸相似度；
- 不合格的视图**不要入库**，更不要“三张里凑合两张”。

### 4.3 落库时必须切分

一张 1536×768 的三联图，单个人物只有约 512×768，脸约 87px；整张送进分镜既降分辨率又增加版式风险。落库时切分：

```text
三视图.png
  → views/front.png   （直接用主视图覆盖，保证 100% 同脸）
  → views/side.png    （侧面 90°；有左右两张时可分 side_l/side_r）
  → views/back.png    （背面 180°）
```

切分可以用项目里的 `comicgen/pipeline.py` 的 `split_triple_view()`（按 `TRIPLE_VIEW_SPLIT_RATIOS` 均分并在附近搜索分割线）；切完必须人工看一眼：**有没有把相邻人物的手臂/衣角切进来**。

### 4.4 三视图验收（四看）

1. **并排放大到同一高度**：头身比是否一致？侧面明显矮一截 = 被画成另一个人；
2. **数记忆点**：痣/疤/耳饰/发际线，正面有的，侧面在对应位置也应该有；
3. **看服装接缝**：领口、袖口、腰线、下摆在三张里是否对得上；
4. **看光**：是否平光、无强侧光/色偏。

> 参考：[AI追光·角色三视图工坊](https://aizhuiguang.tech/tools/character-turnaround.html) 的检查清单与本文一致；差别是本文把“三张独立单视图”作为落库形态，把“三联图”只保留为人工查看。

## 5. 俯视图：几何参考，不是身份参考

### 5.1 它能看到什么

- 发旋位置、发缝方向、发量；
- 发髻/马尾在头顶的形状；
- 双肩宽度、衣领/外套领口的俯视结构；
- 身体向下的透视缩短。

**看不到脸。** 所以它不能锁身份，只能锁“顶视几何”。

### 5.2 制作规范

- **真正的正上方垂直向下**（90°），不是 45° 高角度；
- 画面里只有头顶、发旋、发缝、双肩、衣领；
- 不出现眼睛、鼻子、嘴、正脸；
- 白底、平光、同一发色/发量/发缝/衣领；
- 最好由真实俯拍照片或 3D 渲染提取骨架，再用 ControlNet + 身份锁生成；
- 没有合格参考时，**宁可不生成**，不要拿正面图伪装。

### 5.3 当前实测：10 张里 2 张不是真顶视

本次对项目内 10 张 `俯视图.png` 做人脸检测：

- 孔乙己、掌柜两张能检出人脸；
- 打开看，实际是“高角度俯视、仍能看到脸”，不是配置里写的“正上方垂直向下”。

这类图可以当“高角度参考”用，但不能当“顶视 POV”用。建议：

- 入库字段加 `view_type: top_down | high_angle`；
- 只有 `top_down` 且人脸检测为 0 的图，才允许挂到“正顶视”镜头；
- `high_angle` 只用于“俯拍人物”的普通镜头，且要与主视图配对。

### 5.4 俯视图验收

1. **人脸检测 = 0**（检测器 + 人工；有脸就不是真顶视）；
2. 能看到发旋/发缝，肩线左右大致对称；
3. 衣领/外套领口与主视图同款同色；
4. 没有第二个人、没有场景、没有文字；
5. 视角标注正确（`top_down` / `high_angle`）。

> 重要：**俯视图参考不保证模型把镜头变成顶视。** 本次探针 C（主视图+俯视图）里，画面仍是中景平视，只是视线更向下。镜头角度主要由提示词和构图控制，俯视图只是“头顶结构”的补充。所以俯视图是**低优先级、按需启用**，不要指望它“一送就变顶视”。

## 6. 姿态总图：人工查看，不进分镜

- 一张图里多个身体、多个动作、多个表情头像；
- 用途：人工确认动作/服装/多角度；姿态库参考；
- **不进分镜参考**：多身体会被复制，表情头像会被当成画面元素；
- 当前项目已经这样做（`models.reference_image()` 只返回主视图/旧兼容回退），保持。

> 如果未来要用“姿态总图”做 ControlNet 骨架，必须先从总图里提取单人骨架，并过 `poseplan.validate_pose()`；不要把总图直接送进图像条件。

---

## 7. 群像图：可选的“关系参考”

当一场戏必须 2–3 人同框（建立镜头、对峙、群像），可以制作一张**群像图**：

- 一张图里 2–3 人，按剧情站位（左/中/右），身高比例正确；
- 白底/简单背景，平光，不重叠；
- 每个人的脸、发型、服装与各自主视图一致；
- 只用于“群像建立镜头”，**不用于特写/近景**；
- 送进分镜时只送这一张（1 个参考槽），并在提示词里写清“左边是谁、中间是谁、右边是谁”。

代价：群像图本身可能漂移；制作成本高；只适合反复出现的固定组合。当前项目未支持，作为 Phase 2 的可选项。

## 8. 参考图预处理流水线

任何图进分镜前，按顺序过一遍：

```text
1. 选图        → 主视图 / 面部特写 / 侧面 / 背面 / 顶视 / 群像
2. 单体化      → 裁到一个人；三视图切单张；去掉第二个人
3. 去背景      → 白底或透明底；去场景、道具、文字、标签
4. 去姿势/光影 → 尽量中性站姿、平光；强姿势/强侧光只用于“结构参考”，不用于“身份参考”
5. 统一尺寸    → 长边 1024–1536；面部特写 512–1024；不拉伸
6. 校验        → 人脸数、分辨率、视角、服装/记忆点
7. 命名入库    → 角色/造型/视角/版本；写 `资产.json`
8. 禁止回灌    → 分镜图不得反推人设
```

### 8.1 去背景

项目已有 `BG_REMOVAL_ENABLED`（BiRefNet）。角色参考图建议去背景；**姿态骨架图不要去除背景**（会破坏骨架线）。

### 8.2 尺寸与格式

- 统一 PNG（无损）；不要用 WebP 伪装 `.png`（项目踩过 `500×926 WebP` 冒充 PNG 的坑，见 `docs/测试2_自测报告.md` BUG-01）；
- 长边不超过 1536，避免编码器过度缩放；
- 不要为了“更清楚”把 160px 的脸强行放大到 1024px——放大不增加信息，只会让模型看到模糊的边缘。

### 8.3 视角匹配

| 目标镜头 | 参考图视角 | 不要用 |
|---|---|---|
| 正面特写/近景 | 正面面部特写 | 侧面、背面、俯视 |
| 正面中景 | 正面主视图 | 三视图整张 |
| 侧身 45°/90° | 正面主视图 + 侧面单视图 | 正面图硬猜侧面 |
| 背身 | 正面主视图 + 背面单视图 | 正面图硬猜背面 |
| 正顶视 | 俯视图（top_down）+ 主视图 | 正面图、high_angle 图 |

## 9. 入库质检清单（复制到每个角色）

- [ ] `主视图.png`：单人、正面、全身、白底、平光、一件外层、脸高 ≥120px
- [ ] `面部特写.png`：脸占 35%–55%、正脸/轻 3/4、无遮挡、与主视图同发型/同领口
- [ ] `三视图.png`：三视图同一头身比、同一脚底线、平光；正面=主视图
- [ ] `views/front|side|back.png`：每张一个人、无相邻人物残肢、无文字（有左右侧面时再分 side_l/side_r）
- [ ] `views/top.png`：人脸检测=0、发旋/发缝可见、标注 `top_down`；否则标 `high_angle`
- [ ] `姿态图.png`：只做人工查看，未进分镜
- [ ] `资产.json`：seed、提示词、生成日期、质检结果、view_type
- [ ] 没有把分镜图/上一格图放进角色资产目录
- [ ] 没有用 WebP 改名冒充 PNG
- [ ] 没有“先用着”的明显漂移图

---

## 10. 一句话总结

> **主视图给“全身与服装”，面部特写给“脸”，单视图给“角度”，俯视图给“头顶结构”，姿态总图只给人看。**
>
> 每张图只回答一个问题；回答不了的问题，交给文本、骨架、构图和后期，不要逼一张图全答。
