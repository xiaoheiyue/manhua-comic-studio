# 03 分镜参考路由与提示词规范

> 本文定义：**每一格分镜送哪些参考图、按什么顺序送、提示词怎么写、什么时候必须拆格。**
> 目标不是“让模型看到更多”，而是“让模型只看到这一格需要的东西”。

---

## 1. 五条路由原则

### 原则 1：一图一职

每张参考图只承担一个职责：

| 职责 | 用哪张图 | 不要用它做 |
|---|---|---|
| 身份（脸/发型/服装） | 面部特写 / 主视图 | 锁动作、锁构图、锁背景 |
| 视角（侧/背/顶） | 对应的单视图 | 锁脸的特写细节 |
| 动作/构图 | 骨架/Depth/Lineart | 锁身份 |
| 画风 | 风格块/风格参考 | 锁角色长相 |

一张图同时干两件事，就会互相污染。**主视图已经同时携带“身份+服装+全身比例”，这已经是它的上限；不要再让它承担侧背/顶视/动作。**

### 原则 2：一镜一主参考

- 单人镜头：**1 张主参考**（面部特写或主视图），最多加 1 张辅助（另一视角/另一尺度）。
- 双人镜头：**每人 1 张**，共 2 张；不要给同一人送 2 张再给另一人送 2 张。
- 3 人：**0 张多参考**；4 人拆 3+1/2+2。
- 无人物：0 张。
- **例外**：全景/远景默认 0 张；如果这一格是明确的背影/侧面建立镜头，也建议只开 1 张 `main`，不要 `main+back`。2026-11-03 实测“远景+主视图+背面”会把背影复制成两个人，已改成默认 0 张。

Qwen-Image-Edit 系列（官方 2509/2511 与社区评测）的经验最佳输入是 1–3 张；本项目用的是 Qwen-Image-2.1 Turbo，走同一多图编码接口，但仍需本机标定。8GB 实测 3 张比 1 张慢 2.26 倍，且没有可见收益。**默认上限 2 张，只有“侧背+主视图”“顶视+主视图”这种明确互补才用 2 张。**

### 原则 3：顺序 = 职责 = 提示词编号

送图顺序必须与提示词里的“图 1/图 2”一一对应，否则模型会把 A 的脸套到 B 身上。

推荐顺序：

1. **身份参考**（面部特写/主视图）放第 1 张：它同时决定输出的画幅比例和主要身份；
2. **视角/结构参考**（侧面/背面/俯视）放第 2 张；
3. 双人镜头按**画面从左到右**排序，提示词也按左→右写。

### 原则 4：参考图只锁身份，姿势/构图/光影交给别的通道

提示词必须显式写“只取什么、不取什么”：

```text
图1是林晚的身份参考：只取脸型、五官、发型、发色、服装款式与主色；
不取参考图的站姿、构图、背景与光影。
```

不写这句，模型会把参考图的姿势、背景、光影一起复制。项目实验（`docs/测试2_自测报告.md` 第 10 节）已经证明：靠 denoise 调“换镜头 + 锁角色”是做不到的，必须把职责分开。

### 原则 5：能拆格就不要多人同框

| 人数 | 策略 | 参考图 |
|---|---|---|
| 1 人 | 默认 | 1–2 张 |
| 2 人 | 仅中近景/对峙/建立镜头；左右分区、中间留空、≤1 条台词 | 2 张（每人 1 张） |
| 3 人 / 4 人 | 3 人可用；4 人实测会多画一个，拆 3+1/2+2；逐人写位置/动作/视线；≤1 条台词 | 0 张（群像图可选） |
| ≥5 人 | 一律拆 | 0 |

> 纯提示词的双人可用率约 70–75%，3–4 人更低（`docs/分镜防撞脸防乱入_修复报告.md` 第 4 节）。把“多人同框”当成例外，而不是默认，是一致性最便宜的一步。
>
> 2026-11-03 实测补充：双人各送一张面部特写（2 张）可用，人物可区分、无第三人；三人不送参考（文本）结构可用，但背景会补模糊客人。多人同框里若有儿童/瘦小角色，还要把“年龄/身高关系”写进画面内容，否则少年会被画成成年人。

## 2. 路由矩阵（核心）

> `view` 指这一格实际需要的视角；没有显式字段时，从 `shot_type + camera + description` 推断。
> `face_ref` = 面部特写；`main` = 主视图；`side/back/top` = `views/` 下的单视图。

| # | 景别 | 人数 | 视角 | 参考图（按顺序） | 数量 | 理由 / 备注 |
|---|---|---|---|---|---|---|
| 1 | 特写 | 1 | 正面/3/4 | `face_ref` → `main`（可选） | 1–2 | 脸像素优先；主视图补领口/服装 |
| 2 | 近景 | 1 | 正面/3/4 | `face_ref` → `main` | 2 | 脸+服装都要；不要三视图 |
| 3 | 中景 | 1 | 正面/3/4 | `main` → `face_ref`（可选） | 1–2 | 当前代码的默认场景 |
| 4 | 全景 | 1 | 正面/3/4 | `main` | 1 | 脸小，参考收益低；防克隆可降为 0 |
| 5 | 远景 | 1 | 正面/3/4 | 0 | 0 | 剪影级；优先姿态+文本，避免克隆；实测 2 张会复制人物 |
| 6 | 特写/近景 | 1 | 侧面 45°/90° | `main` → `side`（有左右两张时用 `side_l/side_r`） | 2 | 侧脸结构必须由侧面图提供 |
| 7 | 中景/近景 | 1 | 侧面 45°/90° | `main` → `side` | 2 | 同上；侧面图只取轮廓/服装侧面；远景不送 |
| 8 | 中景/近景 | 1 | 背面 | `main` → `back` | 2 | 后发/背部服装结构；远景不送，实测会复制人物 |
| 9 | 任意 | 1 | 正顶视 | `main` → `top` | 2 | 身份在前，顶视几何在后；`top` 必须是 `top_down` |
| 10 | 中景/近景 | 2 | 正面/对峙 | 左角色 `face_ref/main` → 右角色 `face_ref/main` | 2 | 左→右；中间留空；只有说话人张嘴 |
| 11 | 全景/远景 | 2 | 任意 | 主角 `main` 或 0 | 0–1 | 优先拆成正反打；不送两张全身 |
| 12 | 任意 | 3–4 | 任意 | 0（或 1 张群像图） | 0–1 | >3 张参考会互相打架；**3 人 0 张可用；4 人实测会多画一个，拆 3+1/2+2** |
| 13 | 任意 | 0 | 任意 | 0 | 0 | 道具图/空镜；不要送角色图 |

### 2.1 为什么特写不送主视图（或只作辅助）

主视图的脸约 160px，特写成图的脸约 700–900px。把 160px 的脸放大 4–6 倍，模型只能“编”。面部特写把脸占参考图的比例从 10% 提到 35%–55%，让编码器把更多 token 分给脸——不是增加像素，而是提高脸的“有效占比”。

### 2.2 为什么侧/背镜头不能只用主视图

正面图没有侧面轮廓/后脑结构。只给正面，模型会按“一般人的侧面”猜；每个角色的鼻梁、下颌角、后脑形状不同，猜出来就不是同一个人。侧面/背面单视图就是为这个镜头准备的。

### 2.3 为什么顶视把主视图放第 1 张

- 第 1 张决定输出的画幅比例与主要身份；
- 顶视图看不到脸，不能承担身份；
- 顶视图只提供“发旋/发缝/肩线/衣领”的几何信息。

但如果顶视镜头需要方形/宽幅构图，先把两张参考图都 **pad 到目标画幅比例**（见 2.4），否则输出会跟着第 1 张的 2:3 走。

### 2.4 画幅：不要让参考图决定分镜格的比例

实测：Qwen-Image-Edit 的输出 latent 跟随**第 1 张参考图**的比例。送 2:3 的主视图，即使请求 1024×1024，输出仍是 832×1248。

分镜格有固定画幅（如 1088×1280、1088×960）。处理方式二选一：

1. **推荐：把参考图 pad 到目标画幅**（白底留边，不裁人物），再送。输出比例就跟分镜格一致，人物不被裁；
2. 或者：出图后 `ImageOps.fit` 到分镜格；但这是“先按参考图构图，再裁”，可能裁掉头/脚。

> 这是基于节点“latent 跟随第一张参考图”的工程推断，**需要 A/B 验证**：白边可能被模型当成背景，影响构图。先拿 3–5 格对比“pad vs 出图后 fit”，再决定全量用哪种。

不要用“把参考图裁成目标比例”来解决——那会把全身参考裁成半身，丢失比例信息。

## 3. 路由伪代码（给工程实现）

```python
def plan_shot_refs(project, shot, panel_size):
    names = [n for n in (shot.characters or []) if n]
    if not names:
        return []                                  # 无人物：不送

    if len(names) == 1:
        c = project.find_character(names[0])
        if not c:
            return []
        view = infer_view(shot)                    # front/side/back/top
        level = infer_level(shot.shot_type)        # close/medium/wide

        if view == "top":
            if c.top_quality == "top_down" and c.view("top"):
                return [pad(c.main, panel_size), pad(c.view("top"), panel_size)]
            return [pad(c.main, panel_size)]        # 没有合格顶视：退回主视图+文本
        if view in ("side", "back") and c.view(view):
            return [pad(c.main, panel_size), pad(c.view(view), panel_size)]
        if level == "close":
            ref = c.face_ref or c.main
            return [pad(ref, panel_size)]
        if level == "medium":
            refs = [pad(c.main, panel_size)]
            if c.face_ref:
                refs.append(pad(c.face_ref, panel_size))
            return refs[:2]
        # wide
        return [pad(c.main, panel_size)] if config.WIDE_SHOT_USE_REF else []

    if len(names) == 2 and infer_level(shot.shot_type) != "wide":
        refs = []
        for name in names:                          # 左→右
            c = project.find_character(name)
            if c:
                refs.append(pad(c.face_ref or c.main, panel_size))
        return refs[:2]                             # 最多 2 张

    # 3 人：0 张；4 人拆 3+1/2+2，不送多参考
    group = project.group_sheet_for(names)
    return [pad(group, panel_size)] if group else []
```

配套：

- `pad(img, panel_size)`：等比缩放到“能放进 panel”，白底填充到 panel 比例，**不裁人物**；
- `infer_view(shot)`：优先 `shot.view_hint`；否则从 `camera`/`description` 里的“侧/背/俯/过肩”推断；默认 `front`；
- `c.view(name)`：返回 `views/{name}.png`，不存在返回空；
- `c.face_ref`：返回 `面部特写.png`，不存在返回空；
- `c.top_quality`：`top_down` / `high_angle` / `""`，由 02 的验收流程写入。

> 当前代码只实现了“单人非远景/全景 → 1 张主视图”。上面的伪代码是目标形态，不是现状；改造顺序见 04。

## 4. 提示词结构

### 4.1 固定顺序

```text
画风锚 → 人数 → 参考图职责 → 身份卡（含左右/位置）→ 隔离声明
→ 镜头（景别/机位/角度/人物占比）→ 动作/表情/视线
→ 画面内容（这一格在演什么）→ 场景/时间/光线
→ 气泡/收尾
```

理由：文本编码器对靠前的实体绑定更强；把 700 字人设放在画面内容前面，等于用“角色百科”淹没“这一格在演什么”。

### 4.2 模板 A：单人 + 1 张身份参考

```text
【画风】{风格块，逐字复用}
【人数】画面里只有一位人物，就是{name}。
【参考图职责】图1是{name}的身份参考：只取脸型、五官、发型、发色、服装款式与主色；
不取参考图的站姿、构图、背景与光影。
【身份】{identity_card ≤90字}
【镜头】{景别}，{机位}，{角度}，人物占画面{比例}，{头顶/腰部}留白。
【动作/表情】{动作瞬间}；{表情}；视线{方向}。
【画面】{这一格在演什么，24–80字}。
【场景/光线】{一个关键场景物}；{光源/时间}。
【构图】单幅画面、一个镜头、一层景；不分格、不拼贴、不画中画。
```

### 4.3 模板 B：侧身 / 背身 + 2 张参考

```text
【人数】画面里只有一位人物，就是{name}，身体{朝左/朝右/背对}镜头。
【参考图职责】图1是{name}的身份参考：只取脸型、五官、发型、发色、服装款式与主色；
图2是同一角色的{左侧90°/背面}参考：只取{侧脸轮廓、鼻梁、下颌线/后脑、后发、背部服装结构}；
两张图都只取外观，不取站姿、构图、背景与光影。
【身份】{identity_card}
【镜头】{景别}，{侧机位/背机位}，{角度}，人物占画面{比例}。
【动作/表情】{动作}；{可见的一侧表情/看不见脸时写肩背姿态}。
【画面】{这一格在演什么}。
```

### 4.4 模板 C：正顶视 + 2 张参考

```text
【人数】画面里只有一位人物，就是{name}。
【参考图职责】图1是{name}的身份参考：只取发色、发量、服装款式与主色；
图2是同一角色的正上方俯视结构参考：只取发旋位置、发缝方向、肩宽、衣领形状；
不取图2的透视畸变、背景与光影。
【镜头】镜头在人物头顶正上方垂直向下（bird's-eye view, top-down），
只看到头顶、发旋、发缝、双肩与衣领；脸被头顶遮住，看不到眼睛鼻子嘴。
【画面】{顶视下的动作/环境}。
```

> 注意：顶视参考不保证模型把镜头变成顶视（见 02 第 5.4 节）。如果两轮都失败，**不要继续调提示词**；改用真实顶视构图、3D 参考，或放弃这个机位。

### 4.5 模板 D：双人 + 2 张参考

```text
【人数】画面里只有两位人物，就是{A}和{B}；画面里出现的其他东西都是环境与道具。
【参考图职责】图1是{A}的身份参考，图2是{B}的身份参考；
两张图都只取脸型、五官、发型、发色、服装款式与主色，不取姿势、构图、背景与光影。
【左】画面左侧三分之一是{A}：{身份卡}。{动作/表情}。
【右】画面右侧三分之一是{B}：{身份卡}。{动作/表情}。
【差异】{A}是{脸型/发型/外套轮廓}；{B}是{脸型/发型/外套轮廓}。两张脸各自独立。
【空间】{A}在左三分之一，{B}在右三分之一；两人之间留出一臂宽的空隙，背景从空隙里透出来。
【说话】这一格里说话的是{A}，只有{A}张嘴；{B}闭着嘴，看向{A}。
【构图】单幅画面；不分格、不拼贴、不画中画。
```

要点：

- 一人一段，先写完 A 再写 B，绝不交叉；
- 具体差异，不要写“两人明显不同”；
- 左右分区 + 中间留空，是纯提示词下最有效的“物理隔离”；
- 只有说话人张嘴；
- 双人格最多 1 条台词；超过 1 条就拆格；
- 身份卡超过 94 字时用 `castguard.compact_card(brief=True)` 重写，不要从中间切卡。

### 4.6 模板 E：无参考图（T2I / 远景）

```text
【人数】画面里只有一位人物，就是{name}。
【身份】{完整身份卡：性别/年龄/体型/脸型/发型/眼睛/服装/记忆点}
【镜头】{景别}，{机位}，人物占画面{比例}。
【动作/表情】...
【画面】...
【场景/光线】...
```

无参考图时，身份卡要写全；有参考图时，身份卡可以压缩到“发型轮廓 + 服装主色 + 记忆点 + 体型”，把五官细节交给参考图，避免文本与参考图互相冲突。

> 建议：有参考图时使用 `character_feature_lock(compact=True)`（若实现），保留剪影级/识别级锚点，删掉可被参考图覆盖的五官细节。当前代码还没有这个开关，作为 Phase 1 的改造项。

## 5. 负向词：保留，但不要当主防线

当前 Qwen 路径 `cfg=1.0`，负向条件基本不参与引导；Z-Image `cfg=1.4` 也只是弱引导。因此：

- 负向词可以有，用于 Z-Image 或未来换 cfg 的情况；
- **不要**把“防多人、防换装、防第二张脸”寄托在负向词上；
- 人数靠正面人数锁 + 拆格 + 参考图路由；
- 换装靠主视图 + 服装锁 + 下装锁；
- 多出来的第二个人靠“单视图参考 + 单人构图 + 后期裁切”；
- 负向词里不要写“不要参考图的姿势”——这等于把“参考图”喂给模型；用正面句“只取…不取…”写在参考图职责里。

## 6. 结构控制：骨架和参考图各管一段

| 镜头 | 骨架 | 参考图 | 说明 |
|---|---|---|---|
| 特写/近景 | **不挂全身骨架** | 面部特写/主视图 | 项目教训：特写挂全身骨架会把角色画成男性/体型漂移（`docs/测试2_自测报告.md` 第 19 节） |
| 中景 | 可选半身骨架 | 主视图（+面部特写） | 动作复杂时挂 |
| 全景/远景 | 单人骨架 | 主视图或 0 | 骨架锁动作/构图，参考图锁身份 |
| 侧身/背身 | 对应视角骨架 | 主视图 + 侧/背单视图 | 骨架和视角图都指向同一侧 |
| 正顶视 | **不自动挂骨架** | 主视图 + 俯视图 | 顶视骨架容易被解释成正面 |

原则：**参考图不负责姿势，骨架不负责身份。** 两者同时送时，提示词要写清“图只取外观，姿势按骨架/文字”。

## 7. seed、复现与 A/B

- **角色 seed**：主视图/姿态总图/三视图共用，用于降低资产生成时的脸型漂移；不指望它锁分镜的脸。
- **单角色分镜**：可用角色 seed 复现；换构图/角度仍会变（`rules/01` H9）。
- **多角色/无角色**：用本格 seed；不要用某一角色的 seed 去“同时锁两个人”。
- **A/B 对比**：固定 seed、固定提示词、只改一个变量（参考图/路由/骨架），否则结论不可信。
- **seed 不是一致性方案**：它只复现随机性；PixVerse/Midjourney 的官方说明都强调 seed 不保存角色（[PixVerse 指南](https://pixverse.ai/zh/blog/how-to-create-consistent-characters-with-ai)、[贝果整理](https://bigolab.com/guides/1634-ai-character-consistency)）。

## 8. 提示词长度与预算

| 段 | 预算 | 说明 |
|---|---|---|
| 画风块 | 100–200 字 | 逐字复用，不每格重写 |
| 人数/隔离 | 30–60 字 | 正面人数锁；不要写“不要第二个人” |
| 参考图职责 | 30–50 字/张 | 只取什么、不取什么 |
| 身份卡 | ≤90 字/人 | 双人 ≤94 字/人；超预算整段丢，不切字 |
| 镜头/动作/画面/场景 | 300–500 字 | 这一格的主体 |
| 收尾 | 30–50 字 | 单幅/不分格/风格统一 |
| **总计** | **≤1000 字**（`PROMPT_MAX_CHARS`） | 超预算按 `drop_order` 丢场景/构图，不切身份卡 |

有参考图时，身份卡可以更短；没有参考图时，身份卡要写全。**参考图越多，文本越要短**——两套身份描述会互相打架。

## 9. 常见故障 → 路由修正

| 现象 | 先查什么 | 路由修正 |
|---|---|---|
| 脸不像 | 参考图送了吗？送的是全身还是面部？ | 特写换 `face_ref`；近景 `face_ref + main` |
| 换装/外套变长 | 主视图在不在？服装锁写了吗？ | 送 `main`；加下装/外套长度锁；负向仅辅助 |
| 多出一个人 | 参考图里有几个身体？景别是不是全景？ | 切单视图；全景降为 0–1 张；拆格 |
| 侧脸像正脸 | 有没有侧面单视图？ | 送 `main + side`；加侧机位提示 |
| 背面出现正脸 | 有没有背面单视图？ | 送 `main + back`；提示“背对镜头、看不到脸” |
| 顶视不像顶视 | 俯视图是不是真顶视？ | 人脸检测=0 才用；否则退回文本/放弃机位 |
| 角色变男性/体型变 | 特写是不是挂了全身骨架？ | 特写/近景不挂骨架；加性别/体型锁 |
| 画面像参考图的姿势 | 参考图职责句写了吗？ | 加“只取外观，不取姿势/构图/背景”；换中性站姿资产 |
| 画风漂 | 风格块是否逐字复用？ | 风格块单独放，不塞进身份卡 |
| 双人串脸 | 是不是每人一张全身？ | 每人一张 `face_ref`；左右分区；失败即拆 |

## 10. 一句话总结

> **特写送脸，中景送身，侧背换视角，顶视换投影，双人每人一张脸，三人以上就拆格。**
>
> 参考图只回答“是谁/哪个角度”；“在演什么/怎么构图/什么光”由文本、骨架和后期回答。
