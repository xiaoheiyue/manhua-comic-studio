# 气泡定位与回填细则（出图后）

> 对应代码：`comicgen/bubble.py` · `_balloon_candidates()` / `detect_blank_bubbles()`
> / `layouts_from_plan()` / `_cover_balloon_items()`
> 对应规则：[../../rules/02_分镜与镜头规则.md](../../rules/02_分镜与镜头规则.md) §5.4

---

## 1. 输入

| 数据 | 来源 | 说明 |
| --- | --- | --- |
| `shot.bubble_plan` | `bubble.plan_layout()` | 每条台词的 `x/y/w/h/slot/speaker/tail`（归一化 0~1） |

| 台词 | `shot.dialogues` | 只处理非空、非 sfx 的条目 |

---

## 2. 候选检测（这一步决定"能不能找到"）

在不依赖计划框的前提下，先从画面里找"像气泡的白色区域"：

| 条件 | 阈值 | 原因 |
| --- | --- | --- |
| 近白 | R/G/B ≥ 226 | 气泡是纯白底 |
| 低饱和 | max-min ≤ 26 | 排除彩色高光 |
| 实心度 | area / bbox ≥ 0.55 | 膨胀后仍要接近实心 |
| 面积 | 画面 0.4% ~ 22% | 太小是噪点，太大是墙/天空 |
| 宽高比 | 0.28 ~ 6.5 | 兼容竖长/横长气泡 |
| 暗描边 | 每条边取 2px 窄带、20 分位 < 内部均值 - 25；**至少 3 条边**成立 | 白墙/窗户没有闭合黑边；均值会被背景稀释，所以用分位数 |
| 贴边 | 最多贴 1 条边（允许贴顶/贴左） | 分镜裁切经常切掉气泡的一边 |
| 白边清理 | 先削 10px 边、开运算 2 遍 | 去掉分镜的白色细边框 |
| 尾巴 | 膨胀 2 次后取连通域 | 细尾巴容易和主体断开 |
| 白色主体 | 面积 ≥ 画面 0.6% | 排除门把手、高光点这类小白块 |
| 检测分辨率 | **320px 宽**（不是 180） | 描边只有几像素，降采样太狠会让气泡内部和背景"漏"成一个连通域 |
| 描边封口 | 深色（lum<150）膨胀 2px 后从白色里挖掉 | 尾巴尖/抗锯齿有 1px 缺口，白底气泡会和浅色背景连成一片 |

输出：每个候选的 `(外接框, 白色主体框, 蒙版)`。

> 真机验证（2026-10-21，3 格）：第 1 格气泡贴左边缘、第 2 格气泡在白色背景上、
> 第 3 格普通气泡，全部 `定位 1/1`、`多画 0`、`兜底 0`。

---

## 3. 一对一匹配（这一步决定"填给谁"）

对每个计划气泡和每个候选算分：

```
score = 中心距离
      + 0.12 × |log(候选面积 / 计划面积)|
      + 0.8  × 侧别不符
      - 0.5  × IoU
```

- 中心距离 > `BUBBLE_MATCH_MAX_DIST`（默认 0.55）直接跳过；
- `BUBBLE_MATCH_REQUIRE_SIDE=True` 时，计划在左、候选在右 → 直接跳过；
- 所有配对按分数升序，**全局贪心、一对一**，避免两个计划框抢同一个气泡。

匹配结果写入 `shot.bubble_debug`：

```json
{"expected": 2, "detected": 2, "extra": 0, "fallback": 0}
```

---

## 4. 填字

- **匹配到**：只填字，`drawn_in_art=True`；使用候选的**白色主体内接框**，
  不按计划框硬填，因此字不会跑进尾巴、描边或背景；
- **没匹配到**：程序在"不与任何已检测气泡重叠"的位置补画，`drawn_in_art=False`，
  记 `bubble_fallback`；
- **一个都没匹配到**：整格程序兜底，记 `bubble_detect_fail`；
- **多出来的候选**：按气泡形状做调和填充补成背景，记 `bubble_count_mismatch`。

---

## 5. 自检与返修

| 代码 | 触发 | 处理 | 返修措辞 |
| --- | --- | --- | --- |
| `bubble_detect_fail` | 计划 N>0，检测 0 | 整格兜底，扣 14 | 按坐标画 N 个空白气泡 |
| `bubble_count_mismatch` | 候选多于台词 | 多画的补背景，扣 6 | 画面里只有 N 个空白气泡 |
| `bubble_fallback` | 有台词没匹配到 | 程序补画，扣 6/个 | 必须在指定位置画气泡 |
| `text_overflow` | 最小字号仍放不下 | 缩字号/换框 | 气泡画大一号 |
| `stray_balloon_covered` | 补掉了多画的气泡 | 扣 4 | 画面背景干净完整 |

`imggen` 会把 `bubble_detect_fail / bubble_count_mismatch / bubble_fallback`
视为**必须返修**，即使总分已经过线也会再画一次。

## 6. 回溯

每一格的 `plan / debug / layouts / quality_issues` 会写到：

```
data/projects/<工程id>/prompts/07_bubble/<序号>_shot_XXX.md
```

排查顺序：

1. 看 `plan` 里的坐标是否合理（是否压脸、是否贴边）；
2. 看 `debug.detected`：0 = 模型没画或画得不像气泡；>expected = 多画；
3. 看 `debug.fallback`：>0 = 有台词没找到对应气泡；
4. 看 `layouts[].drawn_in_art`：false = 程序补画的那几个；
5. 对照 `06_image` 里的提示词，确认坐标有没有写进提示词。
